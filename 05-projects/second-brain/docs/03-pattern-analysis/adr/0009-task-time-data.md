## Context and Problem Statement

일정 제안(F17)이 할 일마다 같은 시간(60분)을 썼다. 사용자는 할 일마다 시간이 다르다는 것을 확인했고(시험 준비 2시간),
사람이 자기 일의 시간을 짧게 잡는 경향(계획 오류, Buehler·Griffin·Ross 1994)에 대한 근거로 "실제로 걸린 시간을 모아 다음 질문에 쓴다"를 정했다.

## Considered Options

1. **이슈 제목 틀에 시간 칸을 더한다**(`목적 / 이름 / 내용 / 마감 / 시간`). 폰에서 한 번에 입력되지만 ADR-0005의 틀을 바꾸고, 사용자가 시간을 모를 때 틀이 깨진다.
2. **문서 칸 + 세션에서 묻기 (채택).** 문서 머리말에 `예상 시간`·`실제 시간`을 적고, 새 일을 넣을 때·완료할 때 세션이 선택지로 묻는다.
3. **별도 시간 기록 파일.** 한 곳에 모이지만 문서와 어긋날 수 있고 "상태는 원천 한 곳" 원칙에 어긋난다.

## Decision Outcome

| 칸 | 규칙 |
|---|---|
| 예상 시간 | 문서 머리말 `- 예상 시간: 90분`. **30분 단위**(30, 60, 90 …)만 받는다. 없으면 기본 60분 |
| 실제 시간 | 완료한 뒤 `- 실제 시간: 100분 (2026-10-14)`. 재는 값이라 30분으로 올리지 않는다. 완료 전에는 기록하지 않는다 |
| 새 일을 넣을 때 | 같은 목적의 기록이 있으면 "같은 목적의 일 N건이 보통 M분 걸렸어요(예상보다 보통 K배)"를 근거로 묻고 선택지는 30·60·90·120·180분과 추천값 |
| 완료할 때 | "실제로 얼마나 걸렸어요? (예상 N분)"을 선택지와 함께 묻는다 |
| 일정 제안 | `plan_week`가 할 일마다 문서의 예상 시간을 쓴다. 하루 상한(Q11)보다 길면 놓지 못했다고 알린다 |
| 통계 | 문서에서 다시 만든다(`duration_history`). 질문 문장에는 개수와 분만 있고 할 일 이름은 없다 |

## Consequences

- 이슈 제목 틀(ADR-0005)은 그대로다. 시간은 세션에서 묻는다.
- 기록이 쌓일 때까지(처음 며칠)는 "기록이 아직 없어요"와 기본 60분이다. 3건 미만이면 "참고만"이라고 말한다.
- 같은 목적 안의 일이 모두 한 덩어리로 보인다(중앙값). 이름의 비슷함으로 더 가깝게 고르는 것은 하지 않았다 — 기록이 충분히 쌓이면 다시 본다.
- 선택지의 값(30·60·90·120·180)은 사용자 확인 대기이고, 3시간은 하루 상한을 전부 쓰므로 표시가 필요하다.
