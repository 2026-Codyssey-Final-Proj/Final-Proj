## Context and Problem Statement

5→6 게이트의 보완 (바): 팀 저장소에는 개인 데이터를 두지 않기로 했지만, 데이터를 어디에 두고 코드가 어떻게 찾는지가 정해지지 않았다(V1은 `data` 고아 브랜치의 작업 폴더였다).
"현재 구조는 사용자가 자기 데이터로 써 보며 문제를 찾는 것이고, 팀 프로젝트로서는 개인이 가져가서 자기 것으로 쓴다"는 읽기(2026-10-13)를 만족해야 한다.

## Considered Options

1. **각자 로컬 폴더 + 설정 한 곳 (채택)** — 코드가 이미 폴더 경로를 인자로 받는다. 팀 저장소에 개인 글이 없다.
2. 각자 개인 비공개 저장소 — 백업·이력이 생기지만 사람마다 저장소를 만들어야 한다.
3. 팀 저장소의 개인 브랜치 — 협업자 전원이 읽으므로 팀 공유 조건 1번(저장은 사람마다 따로)에 어긋난다. 추천하지 않음.

## Decision Outcome

| 칸 | 규칙 |
|---|---|
| 자리 | 사용자가 정한 로컬 폴더. 안은 지금과 같다(`vault/`, `run-log.md`, `목록.md` …) |
| 설정 한 곳 | 환경변수 **`SECOND_BRAIN_DATA`**. `config.data_dir(기본 자리)`가 읽는다 |
| 우선순위 | 명령줄에서 준 폴더 > 환경변수 > 기본 자리(저장소의 `projects/second-brain/data`) |
| 없을 때 | "데이터 폴더를 찾지 못했습니다"라고 말하고 건너뛴다. "일이 없다"고 말하지 않는다 |
| 세션 시작 훅 | 같은 환경변수를 읽는다. 없으면 이전처럼 작업 폴더·본 작업 폴더의 `data`를 찾는다 |
| 백업 | 각자 책임이다(ADR의 대안 2 — 개인 비공개 저장소 — 로 나중에 옮길 수 있다) |

## Consequences

- V1의 `data` 브랜치 방식은 기본 자리로 그대로 동작한다. 환경변수를 설정하지 않으면 바뀌는 것이 없다.
- 팀원이 이 프로젝트를 가져가 쓰려면 빈 폴더를 만들고 환경변수 하나를 설정하면 된다(시험으로 확인: 새 빈 폴더에서 브리핑 동작, 폴더가 없을 때 알림).
- 폴더를 만들어 주지는 않는다. 첫 새 일을 넣을 때 `vault/`가 만들어진다(`intake.process_issue`).
- 환경변수 이름은 코드·훅·문서가 모두 같아야 한다 — 바꾸면 `config.py`·`session-briefing.sh`·이 문서·시험을 함께 고친다.
