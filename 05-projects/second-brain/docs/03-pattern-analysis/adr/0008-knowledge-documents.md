# ADR-0008: 지식 문서는 `vault/지식/` 따로 두고, 인용 횟수는 문서 머리말에 적는다

- Status: **Accepted**
- Deciders: 사용자 (2026-10-13, "가 / 가")
- Date: 2026-10-13
- 관련: [ADR-0006](0006-serial-numbers.md)(할 일 번호 범위), [ADR-0007](0007-data-branch.md)(데이터는 `data` 브랜치)

## Context and Problem Statement

지금까지 end-to-end로 돌아간 것은 P2(놓친 일 알람)뿐이고, 핵심 목적 P1(넣기 → 요약 → 저장 → 찾기 →
배운 것 남기기)은 아직이다(4→5 게이트 보완 2). 지식(관찰 → 해석 → 행동, F10a)을 담을 문서의 자리와,
다시 꺼내 쓴 횟수(Q4 나)를 어디에 남길지 정해야 했다.

## Considered Options

1. **지식 문서의 자리:** (가) `vault/지식/<목적>/<이름>.md`로 따로 둔다 · (나) 할 일과 같은 목적 폴더에 둔다.
2. **인용 횟수의 자리:** (가) 지식 문서 머리말 · (나) 실행 기록에 `cite` 한 줄씩.

## Decision Outcome

| 칸 | 규칙 |
|---|---|
| 자리 | `vault/지식/<목적>/<이름>.md` — 번호도 마감도 없다. 목적은 할 일과 같은 다섯 가지 |
| 칸 | 관찰 / 해석 / 행동 / 출처(어느 일에서) / 인용(`인용: N (마지막 YYYY-MM-DD)`) |
| 할 일과의 관계 | 행동에 날짜가 생기면 기존 이슈 틀로 할 일 문서를 만든다(F10b). 지식 문서는 목록(`목록.md`)에 세지 않는다 |
| 인용 횟수의 원천 | 지식 문서 머리말 한 곳. 실행 기록에는 쓰지 않는다 |
| 주간 점검 | 이번 주 새로 남은 지식 개수를 세어 한 줄로 적는다: "이번 주 지식 N개가 `vault/지식/`에 저장됨" — 이름·본문은 쓰지 않는다 |

## Consequences

- 목록 만들기와 번호 부여는 `vault/<목적>/`만 보므로 바뀌지 않는다. `지식` 폴더는 목적 이름이 아니라서 번호 로직과 섞이지 않는다.
- 인용 횟수는 문서를 읽기만 하면 센다(일요일 점검). 로그를 합산할 필요가 없다.
- 지식 문서도 `data` 브랜치에 있으므로 병합 없이 커밋·푸시하고 커밋 전 비밀값 검사를 거친다(ADR-0007).
- 잃는 것: 한 문서를 여러 번 인용한 날짜별 기록(머리말에는 횟수와 마지막 날짜만 남는다). 필요해지면 새 ADR로 실행 기록 `cite`를 더한다.
