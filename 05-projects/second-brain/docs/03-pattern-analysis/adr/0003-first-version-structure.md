# ADR-0003: 세컨드 브레인 첫 버전의 구조 — 서버 없이 파일 + Claude 세션, 폰 알람의 빈틈을 어떻게 막나

- Status: **Accepted** (2026-10-08, 사용자 확인 — 아래 Decision)
- Deciders: 사용자 (Claude는 후보와 비교표를 쓰고, 고르는 것은 사용자)
- Date: 2026-10-08 (초안)
- 근거 파일: [세션 파일](../../../PROGRESS.md) 3단계 표 D1~D4, 설정값 표, 요청 판정 순서

## Context

2→3 게이트는 Go다(2026-10-07). 요구 39개, 숫자 Q1~Q10, 추적표가 확정됐고, 3단계에서 D1~D4가 정해졌다.

| 이미 정해진 것 | 값 |
|---|---|
| 서버 | 지금은 로컬·외부 경로, **서버는 나중**(사용자 2026-10-06, 기록·보안 기준 5절) |
| 폰 입력 (F11, D3) | GitHub 비공개 저장소의 **이슈**, 제목 한 줄 `프로젝트 / 할 일 / 기한`. 세션을 열 때마다 Claude가 읽고 문서로 옮긴 뒤 닫는다 |
| 폰 알람 (F8b, D1·D2) | 구글 캘린더(주로 쓰는 계정), 한 줄 `프로젝트 이름 / 파일 경로 / D-3 (10/12)`, 시간은 마감일에서 자동, 알림 3일 전·1일 전·당일 모두 오전 8시 |
| 백업 (D4) | GitHub + 내 컴퓨터, 사본 둘 |

**풀어야 할 문제:** 알람은 Claude가 이슈를 문서로 옮길 때 캘린더 일정으로 만들어진다. 그래서 폰으로 이슈를 넣고 **세션을 열기 전까지는 그 마감에 알람이 없다**. F8b("Mac이 꺼져도 폰 알람", Must)와 Q1(놓친 일 주 1개 이하)에 닿는 빈틈이다. 마감이 3일보다 먼 일은 영향이 작고, **마감이 3일 이내인 일을 폰으로 넣었을 때** 문제가 된다.

## 후보 도출 (표준 카탈로그 먼저)

[5대 아키텍처 스타일](../../../../../01-docs/03-pattern-analysis/02-architecture-styles.md) 중 개인 프로젝트의 기본은 Layered이고, 근거 없이 Event-Driven 이상으로 가지 않는다. 이 시스템은 ADR-0001처럼 "정적 파일 + 외부 도구(Claude 세션)"라서 5대 스타일 어디에도 깔끔히 맞지 않는다. 아래 후보는 구조(파일 중심, 서버 없음)는 같고 **빈틈을 막는 방법**만 다르다.

## Considered Options

1. **세션 중심 그대로.** 알람은 세션에서 이슈를 옮길 때 만든다. 빈틈은 받아들이고 Q1로 잰다.
2. **세션 중심 + 임박 마감은 폰에서 직접.** 마감이 3일 이내인 일은 폰에서 캘린더에 직접 넣고(알림은 사용자가 설정), 이슈에도 적는다. 세션이 옮길 때 같은 일정이 이미 있으면 새로 만들지 않는다 [동작은 5단계에서].
3. **GitHub Actions가 이슈를 만들 때 일정을 자동 생성.** 이슈 제목이 고정된 틀이라 AI 없이 해석할 수 있다. 문서로 옮기는 일은 계속 세션이 한다(이벤트 기반 부분은 알람 생성 하나뿐).
4. **항상 켜진 서버.** 이슈·웹훅을 받아 일정과 문서를 만든다. 사용자가 "서버는 나중"으로 이미 정했으므로 비교용으로만 둔다.

[해석] **Claude의 권장: 2.** 첫 버전(Walking Skeleton)에 새 비밀값과 항상 열린 쓰기 권한을 만들지 않으면서, 빈틈은 "마감이 3일 이내인 일만 폰에서 직접"이라는 규칙 하나로 줄인다. 그래도 새면 3으로 넘어간다 — 그 기준은 일요일 점검(Q1)에서 놓친 일의 원인이 알람 지연으로 나온 경우다. 3은 가장 완전하지만 사용자의 가장 큰 걱정(계정 탈취)에 닿는 새 비밀값을 만들어서, 필요가 **측정으로** 드러난 뒤에 도입하는 쪽이 안전하다.

## Decision — 사용자가 정한다

**결정할 것 (하나):** 폰 알람의 빈틈을 어떻게 막을까?

- (가) 1 세션 그대로, 빈틈은 받아들이고 Q1로 잰다
- (나) **2 임박 마감은 폰에서 직접** (Claude 권장)
- (다) 3 GitHub Actions로 자동 생성
- (라) 다른 안

선택: **(나) 임박 마감은 폰에서 직접** — 사용자 2026-10-08 ("나로 진행 먼저 F8b 빈틈만 따로 풀고 ADR은 그다음"). 같은 날 비교표 "1: 예", 원칙표 "2: 예"로 확인해 Accepted. 세션 파일 3단계 D5에 기록됨.

Accepted 뒤에는 본문을 고치지 않고, 바뀌면 새 ADR로 대체한다.

## Consequences

- 마감이 3일보다 먼 일은 문제가 없다. 3일 이내 일을 폰으로 넣을 때만 "캘린더에도 직접"이 필요하다.
- 같은 일이 캘린더에 두 번 생기지 않게, 세션이 옮길 때 같은 제목의 일정이 이미 있는지 확인한다(요구로 추가할지는 4단계에서 정한다).
- Q1 점검(일요일) 때 "알람이 늦어서 놓친 일"을 따로 센다. 한 달에 1번 이상 나오면 ADR-0004로 3을 검토한다.
- 3을 쓰게 되면 구글 쓰기 권한이 저장소 비밀값에 생기므로, [기록·보안 기준](../../../../../.claude/rules/security-records.md) 3절에 행을 추가하고 최소 권한을 쓸 때 원문으로 확인한다.
