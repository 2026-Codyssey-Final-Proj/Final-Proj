## 무엇

- [gamercross/No-Code-Workflow-Automation-Project](https://github.com/gamercross/No-Code-Workflow-Automation-Project) —
  Make와 Zapier로 같은 자동화를 만들어 비교하고(프로젝트 1), Make로 **회의록 자동 요약 → 필터 → Slack 공유 →
  Google Sheets 저장**을 만든 과제(프로젝트 2). 보너스로 AI 연동, 오류 처리(재시도·대체 경로·실패 알림), 보안.
- 2026-07-06~07-08, 작성자 사용자 한 명. README + `comparison-report.md`.

## 목적 연결

- **P2 프로젝트 진행 자동화** — "넣으면 → 요약 → 걸러서 → 알리고 → 기록"이라는 자동화의 뼈대(Trigger · Action ·
  Filter · Router)를 이미 설계했다. 세컨드 브레인의 "넣으면 Claude가 요약해 정리"와 "남은 날 알림"이 같은 구조다.
- **P4 보안** — 비밀값 관리 원칙을 스스로 세웠다.

## 가져올 것 (후보)

| 단계 | 재료 | 쓰는 곳 |
|---|---|---|
| 2단계 요구사항 | Trigger · Filter · Router · Action 개념, 회의록 요약 워크플로우 6단계 | "남은 날 알림"·"요약해 정리"를 이벤트-조건-동작으로 쓰기 (EARS Event-driven 문장과 같은 꼴) |
| 2단계 보안 요구 | 보안 원칙: API 키는 환경변수, Webhook URL·이메일 마스킹, 스크린샷에서 키·토큰 제거 확인 | 기록·보안 기준 2절과 대조, 2단계 보안 요구 문장 |
| 3·5단계 | 오류 처리: 실패 알림, 재시도, 대체 경로(Fallback), 워크플로우 모듈화 | 자동화가 실패했을 때 "놓친 일"이 생기지 않게 하는 설계 |
| 3단계 대안 비교 | 노코드의 한계(대량 처리·복잡한 계산은 코드가 맞다), 무료 플랜 비교 | "노코드 도구 vs Claude Code 스크립트" 비교 줄 |

## 교훈

- 노코드는 빠르지만 규모·복잡도가 커지면 코드가 맞다고 스스로 결론 냈다(README "노코드 자동화의 한계").
- 도구를 고를 때 **무료 플랜에서 되는가**를 기준에 넣었다 — 지금의 "유료면 안 쓴다"와 같은 기준.

## 보안 메모

- 공개 저장소. 키·Webhook·이메일은 마스킹돼 있다고 README에 적혀 있다(이번 확인에서 실제 키 패턴은 보이지 않음).
- 이 자동화는 회의록을 외부 서비스(Make, AI API, Slack, Google Sheets)로 보낸다 — 세컨드 브레인에서 같은 구조를
  쓰면 기록·보안 기준 3절(밖으로 나가는 것)에 경로가 늘어난다.
