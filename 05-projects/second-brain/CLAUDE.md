# second-brain — 프로젝트 안내

학교생활 동안 사용자와 Claude가 함께 쓰는 **지식 창고(세컨드 브레인)**를 이 워크스페이스의
기능으로 만드는 프로젝트다. 개인 사용, 반영구 사용. 개발은 루트의 7단계 워크플로우(Full
등급)를 따르고, **작업물은 사용자가 쓰고 Claude는 리뷰한다**
([review-mode.md](../../.claude/rules/review-mode.md)). **단, 이 프로젝트의 코드는 Claude가 짠다** — 아래 "역할".

> **팀 레포(V2)에서의 주의.** 이 프로젝트는 이재엽의 개인 프로젝트(V1)에서 옮겨 왔다. 이 레포는 협업자 전원이 읽으므로 아래를 바꿨다.
> 1. **`data` 브랜치와 할 일 문서는 이 레포에 두지 않는다.** 아래 "데이터는 `data` 브랜치" 절과 ADR-0007은 *V1의 기록*이다. 개인 데이터의 저장 구조는 [PROGRESS.md](PROGRESS.md) "남은 일 1".
> 2. **진행 상태의 원천은 [PROGRESS.md](PROGRESS.md)다.** V1의 세션 파일은 옮기지 않았다.
> 3. 구글 캘린더 연결·GitHub 이슈 입력은 개인 환경이다 — 팀 레포의 이슈를 개인 입력 창구로 쓰지 않는다.

이 파일은 **프로젝트 라우터**다 — 이 프로젝트 고유의 것만 담는다. 공통 규칙은
[루트 CLAUDE.md](../../CLAUDE.md)를 따른다.

## 아무 작업이든 시작하기 전에

- **진행 상태의 원천은 [PROGRESS.md](PROGRESS.md)의 게이트 로그뿐이다**(V1에서는 세션 파일이었다). README나 다른 문서에 상태 문장을 다시 적지 않는다
  (qa-prep-system에서 여러 곳에 적었다가 어긋난 전례).
- 단계를 넘어갈 때마다 → [`gates.md`](../../01-docs/00-overview/gates.md)의 DoR/DoD와
  게이트 리뷰(`dev-workflow` 명령 5).

## 역할 — 이 프로젝트에서 루트 리뷰 모드와 다른 점

사용자 결정 2026-10-01 "(다)": PRD의 "개발과 진행사항을 자동화한다"는 **진행 관리와 코드 작성 둘 다**다.
"코드를 너가 짜고 검수는 저기 있는 내용을 바탕으로 검수해도 좋을거 같아."

| 진행 관리 (Claude가 한 일, PR, 남은 일) | Claude | [방향 점검 페이지](https://claude.ai/artifact/NvVmaGaWVwgcH77mS35JVt)(claude.ai 비공개 스냅숏, 기록·보안 기준 3절)의 "진행 관리" 절에 보인다. 원천은 세션 파일 게이트 로그와 PR이다 |

## 데이터는 `data` 브랜치 — 병합 없이 바로 커밋 (ADR-0007, 사용자 결정 2026-10-08)

할 일 문서(`vault/`)·실행 기록(`run-log.md`)·목록(`목록.md`)은 **main에 없다.** 이력이 이어지지 않는 `data` 브랜치에 있고, 작업 폴더는 `05-projects/second-brain/data/`(main에서 무시)이다. 코드·규칙·문서는 지금처럼 PR이다.

- **처음 한 번 (또는 새로 클론했을 때):** `git worktree add 05-projects/second-brain/data data` — 그리고 `.claude/hooks/pre-commit.sample`을 `.git/hooks/pre-commit`으로 복사([기록·보안 기준](../../.claude/rules/security-records.md) 6-3).
- **입력:** 세션이 열려 있으면 사용자가 말로 한다(이슈 없이). 폰에서는 이슈를 올리고 다음 세션에서 같은 처리를 한다.
- **처리:** 사용자에게 "이렇게 정리할게요" 한 장(문서, 캘린더 일정 제목·시각·알림, 커밋될 파일)을 보여 주고 **"예" 한 번**을 받는다. 그 뒤 문서 쓰기 → 캘린더 일정 만들기·확인 → 일정 번호를 문서에 적기(`save_event_id`) → 실행 기록 → 커밋·푸시.
- **커밋:** `cd 05-projects/second-brain/data && git add -A && bash ../../../.claude/hooks/check-secrets.sh --staged && git commit … && git push origin data`. 비밀값 검사를 통과해야 커밋한다.
- **한 폴더, 한 번에 한 세션:** `data` 브랜치는 한 작업 폴더에만 펼칠 수 있다. 다른 세션이 쓰는 중이면(`git status`가 더럽다) 기다린다.

## 참고 자료 넣기 — 사용자가 주는 GitHub 링크·파일 묶음

사용자 결정 2026-10-01 "(가)": 사용자가 GitHub 링크를 주면 Claude가 파일을 읽고 분석해 참고 자료로 넣는다.
세컨드 브레인의 핵심 기능(넣기 → 요약 → 창고에 쌓기)을 사람 손으로 먼저 해 보는 것이고, 쌓인 자료는 2단계
(놓친 일 정량화)와 3단계(창고 구조 ADR)의 재료가 된다. 첫 사례: [my-setup-proj](docs/references/my-setup-proj.md).

- **저장 위치:** `docs/references/<저장소>.md` 한 파일씩. 폴더·분류를 새로 만들지 않는다 — 구조는 3단계 ADR에서 정한다.
- **형식:**
  ```
  무엇: 저장소 한 줄 요약, 기준 커밋
  목적 연결: P1 지식 사이클 / P2 프로젝트 진행 / P3 MCP·스킬 / P4 보안 중 어디
  가져올 것: 단계별로 재사용할 노하우 (사용자가 골라 확정)
  교훈: 그 작업에서 배운 것, 멈춘 이유가 있다면
  보안 메모: 공개 여부, 팀원 정보 여부
  ```
- **목적에 답하지 않으면 넣지 않는다** — my-setup-proj의 교훈("목적성을 잃어서 그만둔 케이스")에서.
- **팀 저장소는 내 몫이 중심:** 팀원은 이름·직책·하는 일 한 줄만 적는다. 팀원의 커밋 내용·피드백 원문은 옮기지 않는다(S3, 사용자 결정 2026-10-01).
- 비공개 저장소도 내용이 Claude(AI 서비스)로 전송된다 — [기록·보안 기준](../../.claude/rules/security-records.md) 1절.
- 분석 문서는 사용자 요청으로 Claude가 쓰고 `claude-drafted` 표시를 남긴다. "가져올 것"의 확정은 사용자가 한다.

### 자료가 많을 때 — 묶음으로 받는다

사용자 결정 2026-10-04: "레프런스들이 많을때 한번에 넣기 어려우니 우리만의 레프런스들을 어떻게 받을지". 위의 GitHub
링크 말고 **파일·스크린샷을 한꺼번에** 받을 때의 방법이다. 첫 사례: 코딩마라톤 가이드(스크린샷 115장) — 처음엔 루트 `레프런스/`에 뒀다가 2026-10-06 `~/proj/coding_marathon_result/코딩마라톤 가이드/`로 옮겼다.

**절차는 루트 [참고 자료 받기](../../.claude/rules/reference-intake.md)로 옮겼다**(2026-10-04 — 목적이 워크스페이스 전체라서).
① 받기 → ② 문서화 → ③ 비교 → ④ 반영 → ⑤ 꺼내 쓰기. 이 프로젝트에 남는 것:

- ③ 비교에서 **세컨드 브레인 전용** 재료는 `docs/references/<묶음>.md`에 둔다. 워크스페이스로 갈 것은 루트
  [후보 장부](../../01-docs/catalog/reference-candidates.md)에 둔다.
- **비교 전에 문서화를 먼저 한다** — 사용자 결정 2026-10-04("비교할거야 그전에 문서화를 먼저 하고 싶은거야").
- **원문 우선:** 텍스트(md·JSON·링크) > PDF > 스크린샷. 스크린샷은 패널이 잘려서 같은 날 반쯤 가려진 줄 14개를 추정해 읽었다.
  추정한 곳은 문서에 그렇다고 표시한다.
- **원본과 git (사용자 결정 2026-10-04 "(다)"):** 원본은 받은 기록표가 있는 폴더의 `<묶음>/`에 둔다(지금은 이 워크스페이스 밖 코딩마라톤 가이드 폴더). 2026-10-06부터는 정리한 `README.md`도 원본과 함께 그 폴더에 둔다(사용자 결정 — 워크스페이스 git에는 그 전 이력만 남음). 2026-10-08에 그 폴더의 `.md` 문서만 `gamercross/coding_marathon_result` 저장소에 커밋했고 원본은 제외했다. 공개 템플릿으로 보내지 않는다(인스턴스 데이터,
  [git-workflow.md](../../.claude/rules/git-workflow.md)).
- **받기 진행 상태는 받은 기록표에만 적는다**(받음 → 문서화 → 비교 → 반영). 프로젝트 진행 상태(세션 파일)와는 따로다.
- **보안 확인은 묶음마다, 커밋 전에** — 키, 도메인·IP, 다른 사람의 정보([기록·보안 기준](../../.claude/rules/security-records.md) 6-2).
  결과는 받은 기록표의 "보안 확인" 칸에 적는다.

## 시작 전에 알려진 위험 (착수 점검, 2026-09-30)

- **자기 참조:** 이 저장소의 파일·링크를 읽어 그래프를 만들면, 생성된 결과물이 다시 입력이
  될 수 있다 — [체크리스트](../../01-docs/catalog/checklist.md)의 "자기 참조 도구 체크리스트".
- **학교 내용을 둘 자리:** 지금 구조에는 과목(영역)·자료·보관함 자리가 없다. 기능(메커니즘)과
  학교 노트(인스턴스 데이터)를 어디에 둘지 정해야 한다 — 공개 템플릿으로 보낼 때 섞이지 않게
  ([git-workflow.md](../../.claude/rules/git-workflow.md)).
- **데이터 범위:** 팀원 이름, 강의 자료 등 남의 데이터가 들어가면 AI 서비스로 전송된다.
