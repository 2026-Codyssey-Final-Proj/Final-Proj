## 1. 이 인터뷰로 확인할 것

기획안의 문제 문장은 아직 **가설**이다([final-project-plan.md](../00-overview/final-project-plan.md) "검증 계획", [canvas.md](../00-overview/canvas.md) "핵심 장벽"). 인터뷰는 아래 다섯 가지를 확인하고, 결과는 맞음 / 아님 / 일부 / 공백 중 하나로 적는다.

| ID | 가설 | 어디서 나왔나 | 질문 |
|---|---|---|---|
| H1 | AI로 프로그램을 만들다가 **지금 어디까지 왔고 다음에 무엇을 할지** 몰라 진행이 멈춘다 | 기획안 "문제" 1 | Q1~Q5, Q7 |
| H2 | AI가 만든 결과가 맞는지 판단하지 못한다 | 기획안 "문제" 1 | Q6 |
| H3 | 끝까지 만들어도 **내 코드를 설명하지 못한다** | 기획안 "문제" 2 | Q8 |
| H4 | 배운 것이 **다음 프로젝트로 이어지지 않는다** | 기획안 "문제" 2 | Q9, Q10 |
| H5 | 위 문제가 코딩 학습자 밖의 유형(기획자·디자이너·직장인·창작자)에게도 같은 모양이다 | 기획안 "검증 계획" [제안] | 유형(S2)별로 H1~H4를 비교 |

인터뷰 뒤에 정하기로 한 **미정 값**도 여기서 재료를 모은다([requirements.md](../00-overview/requirements.md) 9·11절).

| 미정 값 | 인터뷰에서 모으는 재료 | 질문 |
|---|---|---|
| FR-1 "다음 할 일" 표시 개수 | 한 번에 몇 개쯤 보면서 일했는지 (본인 말) | Q7 |
| FR-2 완료 기준 | 응답자가 "끝났다"고 보는 상태를 본인 말로 | Q5 |
| FR-8 역량·노력의 항목과 단위 | 실력이 늘었다는 것을 무엇으로 아는지 | Q9, Q10 |
| FR-13 "비전공자"의 기준, 용어 풀이 수준 | 프로그래밍 교육 경험, 멈췄던 단어 | S1, Q11 |
| 성공 수치(완주율·설명 성공률)의 기준선 | 시작한 수 대비 끝낸 수, 설명이 이어졌는지 | Q5, Q8 |
| 등급을 묻는 질문 문구 | 20분으로 줄이며 뺐다 — 7절 | **공백** |

## 2. 대상 유형

모두 **AI로 프로그램을 만들어 본 사람**이다(requirements.md 0절 — 보고서·과제 같은 비개발 작업만 한 사람은 대상이 아니다).

| 유형 | 누구 | 기획안에서의 위치 | 인원 [제안] |
|---|---|---|---|
| ① 코딩 학습자 | AI로 코딩을 배우는 학생·교육생 | 첫 검증 대상 (원안) | 1~2 |
| ② 코딩을 모르는 기획자·디자이너 | 코딩은 모르지만 AI로 서비스를 만들어 본 사람 | 원안 | 1 |
| ③ 직장인 | 업무용 프로그램을 AI로 만들어 본 사람 | 가설 | 1 |
| ④ 창작자 | 개인 프로젝트로 AI로 만들어 본 사람 | 가설 | 0~1 |

- **필수:** 프로그래밍을 배우지 않은 사람 **최소 1명**(requirements.md 2-1 ①). 보통 ②가 해당하고, ③·④도 S1 답이 "배운 적 없음"이면 센다.
- **첫 검증 순서 [제안]:** ① → ② → ③ → ④. ①은 원안의 첫 대상이고, ②는 FR-13 필수 조건을 채우며, ③·④는 대상 확장(H5) 가설이다. 3명만 구하면 ①·②·③(또는 ④)으로 한다.
- **제외:** 팀원, 그리고 Project Navigator 기획을 미리 들은 사람 — 답이 기획 쪽으로 끌려간다. 같은 코디세이 과정 동료는 ①로 가능하되 이 기획을 모르는 사람만.
- **공통 조건 [제안]:** 최근 3개월 안에 AI(ChatGPT·Claude·Cursor 등)로 프로그램을 하나 이상 만들어 보기 시작했다. 기억이 생생한 실제 경험을 듣기 위해서다.

## 3. 진행 방식

| 항목 | 내용 |
|---|---|
| 형식 | 1:1, 대면 또는 화상 |
| 시간 | 20분. 6절의 분 단위는 목표이고, 응답자가 길게 말하면 꼬리 질문을 줄인다 |
| 진행 | 고한결. 기록자가 따로 있으면 진행자는 질문에만 집중한다 |
| 녹음 | 응답자가 동의할 때만. 원본은 레포에 올리지 않는다 — [README.md](README.md) |
| 제품 설명 | **하지 않는다.** 마무리에서 사용 테스트 참여만 묻는다. 먼저 설명하면 답이 그쪽으로 끌려간다 |

## 4. 진행자가 지킬 것

[review-mode.md](../../.claude/rules/review-mode.md) "질문하는 법"의 규칙 중 인터뷰에 그대로 쓰는 것이다.

1. **실제로 있었던 일을 묻는다.** "최근에 ○○했던 때"를 떠올리게 한다. "○○가 있으면 쓰시겠어요?" 같은 미래 가정은 묻지 않는다 — 실제 행동을 알려 주지 않는다.
2. **기대하는 답을 암시하지 않는다.** 판정을 묻는 질문은 양쪽을 다 열어 둔다(아래 5절의 나쁜 예 → 바꾼 예).
3. **얕은 답에는 꼬리 질문을 한다.** 이유 · 다른 방법 · 실제 사례 중 빠진 것을 묻는다 — "그때 다른 방법도 있었나요?", "실제로 그랬던 때를 하나 말해 주세요".
4. **"자주", "오래" 같은 말은 숫자로 한 번만 되묻는다.** 답을 못 주면 "모름"으로 적고 넘어간다.
5. **우리 용어를 쓰지 않는다.** 단계·게이트·EARS·완료 기준 같은 말 대신 응답자의 말을 쓰고, **응답자가 쓴 표현을 그대로 적는다**(FR-13 용어 수준의 재료).
6. **보기를 주지 않는다.** "누구에게 물으셨나요, 검색하셨나요?"처럼 묻지 않고 "그때 무엇을 하셨나요?"로 묻는다. 아래 질문의 `메모용` 보기는 진행자만 본다.

## 5. 하지 않는 질문 — 나쁜 예와 바꾼 예

| 나쁜 예 | 왜 안 되나 | 바꾼 예 |
|---|---|---|
| "AI로 만들다 막혀서 힘드셨죠?" | 막혔다는 답을 암시한다 | "진행이 순조로웠던 때와 그렇지 않았던 때를 하나씩 말해 주세요" (Q2) |
| "단계를 알려 주는 도구가 있으면 쓰시겠어요?" | 미래 가정 — 대부분 "네"라고 답한다 | "다음에 할 일은 어떻게 정하셨나요?" (Q7) |
| "자기 코드를 설명 못 하시죠?" | 답을 정해 두고 묻는다 | "한 부분을 골라, 처음 보는 친구에게 설명하듯 말해 주세요" (Q8) |
| "역량 지도가 있으면 좋겠어요?" | 우리 기능을 설명하며 묻는다 | "실력이 늘었다는 걸 무엇으로 아시나요?" (Q10) |

## 6. 질문지 (20분)

### 시작 (1분)
[README.md](README.md)의 **동의 안내**를 읽고, 녹음 여부를 묻는다.

### 배경 (2분)
- **S1.** 프로그래밍을 배운 적이 있나요? 있다면 어디서, 얼마 동안이었나요? → FR-13 "비전공자" 기준 재료. 답을 그대로 적는다
- **S2.** 지금 하시는 일이나 공부는 어떤 쪽인가요? (유형 ①~④를 진행자가 표시. 학교·회사 이름은 적지 않는다)

### 가장 최근에 만든 것 (6분) — H1
- **Q1.** 가장 최근에 AI로 만들어 본 프로그램 하나를 골라 주세요. 무엇을, 왜 만들었나요?
- **Q2.** 진행이 순조로웠던 때와 그렇지 않았던 때를 하나씩 말해 주세요.
- **Q3.** 순조롭지 않았던 그때 무엇을 하셨나요? (`메모용`: AI에게 다시 물음 / 검색 / 사람에게 물음 / 잠시 손을 놓음 / 그만둠)
- **Q4.** 그 프로그램은 지금 어떤 상태인가요? (`메모용`: 끝남 / 진행 중 / 멈춤 / 기타)
- **Q5.** 최근 3개월 동안 AI로 시작한 프로그램은 몇 개이고, 그중 스스로 "끝났다"고 보는 건 몇 개인가요? "끝났다"는 어떤 상태를 말하나요? → 완주율 기준선, FR-2

### AI의 결과를 판단할 때 (3분) — H1·H2
- **Q6.** AI가 만들어 준 결과가 맞는지 어떻게 확인하셨나요? 마지막으로 확인한 때를 예로 들어 주세요.
- **Q7.** 다음에 할 일은 어떻게 정하셨나요? 할 일을 어딘가에 적어 두었다면, 한 번에 몇 개쯤 보면서 일하셨나요? → FR-1

### 설명하기 (4분) — H3
- **Q8.** 그 프로그램에서 한 부분을 골라, 처음 보는 친구에게 설명하듯 어떻게 동작하는지 말해 주세요.
  - 시작 전에 "시험이 아니에요. 맞고 틀림을 보지 않아요"라고 말한다.
  - 진행자는 **맞고 틀림을 판단하지 않는다.** 설명이 끝까지 이어졌는지, 멈췄다면 어디서 멈췄는지만 적는다 → 설명 성공률 기준선

### 배움이 이어지는가 (3분) — H4, FR-8
- **Q9.** 그 프로그램을 만들며 새로 알게 된 게 있다면 무엇인가요? 그걸 어딘가에 남기셨나요? (남기지 않았다면 그것도 답이다)
- **Q10.** 본인 실력이 늘었는지 그대로인지 무엇으로 아시나요? 다른 사람에게 보여 준다면 무엇을 보여 주시겠어요? → FR-8 항목·단위

### 모르는 말 (1분) — FR-13
- **Q11.** AI의 답이나 자료를 보다가 뜻을 몰라 멈췄던 단어가 있었다면 기억나는 대로 말해 주세요. 그때 어떻게 하셨나요? → FR-13 용어 풀이 수준

### 마무리 (1분)
- **Q12.** 제가 묻지 않았지만, AI로 프로그램을 만들며 겪은 일 중에 꼭 말하고 싶은 게 있나요?
- **Q13.** 11/2~11/5에 저희가 만든 시연 화면을 써 보는 사용 테스트(#13)를 하는데, 참여해 주실 수 있나요? (연락처는 진행자만 따로 보관하고 레포에 적지 않는다)

## 7. 20분으로 줄이며 뺀 것

고한결이 40분 초안을 20분으로 줄이기로 했다(2026-10-15). 뺀 질문과 그 때문에 비는 곳이다 — 빈 곳은 지어내지 않고 **공백**으로 둔다.

| 뺀 것 | 확인하려던 것 | 영향 |
|---|---|---|
| 쓰는 AI 도구 | 배경 | 없음 — Q1 답에서 자주 나온다 |
| 처음부터의 진행 순서 | H1 | Q2·Q3으로 멈춘 지점만 본다 |
| AI가 낸 방법 중 고른 경험 | H2, FR-3 | H2는 Q6만으로 본다 |
| "왜 이렇게 만들었어요?"에 답한 경험 | H3 | H3는 Q8만으로 본다 |
| 전에 배운 걸 다시 쓴 경험 | H4 | H4는 Q9·Q10만으로 본다 |
| 다른 일과 겹침, 사용량 한도 | FR-6 | FR-6 재료 없음 — FR-6은 시연이 가상 숫자라 인터뷰가 필수가 아니다 |
| 프로젝트 규모를 표현하는 말 | 등급을 묻는 질문 문구(requirements.md 9절) | **공백** — 다른 방법이 필요하다(예: #13 사용 테스트) |
| 할 일 카드 관찰 | FR-1 표시 개수 | Q7의 본인 말로만 본다 — 관찰보다 약한 근거다 |
