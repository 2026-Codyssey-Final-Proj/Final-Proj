# 인터뷰 (#10 · #11)

개발 전에 예비 사용자 3~5명을 인터뷰해, 기획안의 문제가 실제로 있는지 확인한다([final-project-plan.md](../00-overview/final-project-plan.md) "검증 계획"). 담당은 고한결.

| 파일 | 무엇 | 이슈 |
|---|---|---|
| [questionnaire.md](questionnaire.md) | 확인할 가설, 대상 유형, 질문지 | #10 |
| `respondent-A.md`, `respondent-B.md` … | 응답자별 요약 (아래 틀) | #11 |
| `summary.md` | 가설별 종합 판정과 미정 값 후보 | #11 |

## 레포에 올리지 않는 것

이 레포는 비공개지만 협업자 전원이 읽는다([security-records.md](../../.claude/rules/security-records.md) 2절, [team-sharing-security.md](../00-overview/team-sharing-security.md)).

- 응답자의 **이름·연락처**, 학교·회사 이름, 한 사람을 알아볼 수 있는 사연 → `응답자 A`로 가리고 요약만 둔다
- **녹음 파일과 받아 적은 원본 메모** → 진행자의 컴퓨터에만 둔다
- 사용 테스트(#13) 참여 의사를 밝힌 응답자의 연락처 → 진행자가 따로 보관한다

개인정보 관련 법적 요구가 적용되는지는 Claude가 판단하지 않는다 — **확인이 필요하다**(security-records.md 4절).

## 보관과 삭제 [제안]

security-records.md 5절이 "인터뷰 설계 때" 정하기로 한 칸이다. 고한결이 확정한다.

| 무엇 | 어디 | 언제 지우나 |
|---|---|---|
| 녹음·원본 메모 | 진행자의 컴퓨터 | 그 응답자의 요약(`respondent-X.md`)을 커밋한 날 |
| 사용 테스트용 연락처 | 진행자의 컴퓨터 | 평가가 끝난 날(11/13) |
| 요약 (`respondent-X.md`) | 이 폴더 | 지우지 않는다 — 식별 정보가 없는 제출 근거다 |

## 동의 안내 (인터뷰 시작 때 읽는다)

> 오늘 이야기는 AI로 프로그램을 만드는 사람들이 어떤 일을 겪는지 알아보는 팀 과제(코디세이 Final-Project)에 씁니다.
> 이름·연락처·학교나 회사 이름은 적지 않고, "응답자 A"처럼 가려서 요약만 팀 저장소에 남깁니다.
> 녹음은 동의하실 때만 하고, 요약을 만든 뒤 지웁니다.
> 답하기 싫은 질문은 넘기셔도 되고, 언제든 그만두셔도 됩니다.
> 정답이 있는 질문은 없습니다 — 평가가 아니라 경험을 듣는 자리입니다.
> 녹음해도 될까요? 시작해도 될까요?

"요약을 만든 뒤 지웁니다"는 위 [제안]을 따른 문장이다. 보관 기간을 바꾸면 이 문장도 함께 고친다.

## 요약 틀 (`respondent-X.md`)

```markdown
# 응답자 A

| | |
|---|---|
| 유형 | ① 코딩 학습자 / ② 기획자·디자이너 / ③ 직장인 / ④ 창작자 |
| 프로그래밍 교육 (S1) | 응답 그대로 |
| 인터뷰 | YYYY-MM-DD, N분, 대면/화상 |

## 가설별로 들은 것

| 가설 | 들은 것 (응답자의 말 그대로) | [해석] | 판정 |
|---|---|---|---|
| H1 | | | 맞음 / 아님 / 일부 / 공백 |
| H2 | | | |
| H3 | | | |
| H4 | | | |
| H5 | | | |

## 미정 값의 재료

| 값 | 응답 |
|---|---|
| Q5 시작한 수 / 끝낸 수, "끝났다"의 뜻 | |
| Q7 한 번에 보면서 일한 할 일 개수 | |
| Q8 설명이 이어졌나 / 멈춘 곳 | |
| Q10 실력이 늘었다는 근거 | |
| Q11 멈췄던 단어 | |

## 그 밖에 나온 것
```

- 응답자의 말은 **그대로** 옮기고, 진행자의 해석은 `[해석]`을 붙여 따로 적는다.
- 답이 없으면 지어내지 않고 **공백**으로 둔다.
