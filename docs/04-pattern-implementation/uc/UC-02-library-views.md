## 0. 유스케이스를 이렇게 나눈다 (작성 기준)

**한 유스케이스 = 한 가지 목표.** 같은 목표를 이루는 **다른 길**은 한 유스케이스 안의 "대안"으로 쓰고, **목표가 다르면** 따로 쓴다.

| 질문 | 답 | 이 문서의 선택 |
|---|---|---|
| 짧게 보기·전체 화면·세션별·책별은 같은 목표인가? | 목표는 모두 "쌓인 것을 본다"이고 **보는 방식만 다르다** | **UC-02 하나**에 "보기 선택"으로 쓴다 |
| 가져오기는? | 목표가 다르다 — "다른 곳의 것을 책장에 들인다" | 따로 쓴다(후보 UC-03) |
| 파일을 올려 묻기는? | 목표가 다르다 — "내 파일로 답을 얻는다" | 따로 쓴다(후보 UC-04, 후보 C-2) |
| API 키로 시작하기는? | 목표가 다르다 — "구독 없이 쓰기 시작한다" | 따로 쓴다(후보 UC-05, 후보 C-1) |

이 지도는 [제안]이다. UC-01은 시연 시나리오 전체를 하나로 쓴 것(2026-10-16 결정)이고, 막히는 곳이 보이면 나눈다.

## 1. 한눈에

| 항목 | 내용 |
|---|---|
| 이름 | 서재를 본다 |
| 목적 | 사용자가 **쌓인 것(결정·요구·배운 것)** 을 지금 하는 일에 맞는 방식으로 보고, 필요하면 이 단계에 쓴다 |
| 주 행위자 | 사용자 |
| 보조 행위자 | 안내 패널(마스코트), 저장된 책(표지) |
| 요구 | FR-8(지식 창고), FR-13(쉬운 말), 후보 C-3(보기 방식) |
| 범위 | 화면 안의 보기. 가져오기·본문 열기는 별도(설계 4절) |

## 2. 보기 네 가지 — 언제 무엇을 쓰나

| 보기 | 모양 | 언제 | 시연(11/1) | 제안 |
|---|---|---|---|---|
| **짧게 보기** | 패널 안의 한 줄 요약과 책 몇 권 | 작업하면서 곁눈으로 확인("지금 3단계와 이어지는 책이 있나") | ✅ | **기본** — 패널이 작게 떠 있다가 정할 게 생길 때 묻는 구조와 맞다 |
| **전체 화면** | 넓은 화면의 책장·표지·목차 | 찾아서 읽고 정리할 때 | ✅ | 펼침 |
| **세션별** | 작업 한 번(코딩 도구에서 연 세션)마다 그때 쌓인 것 | "이건 어느 작업에서 나왔나"를 돌아볼 때 | Could | "세션" 정의를 이재엽이 확인(아래 9절) |
| **책별** | 종류(요구·결정·지식·점검…)마다 한 권 | 종류로 찾을 때 | 전체 화면 안에서 | 책장의 기본 모양 |

## 3. 사전 조건

| # | 조건 |
|---|---|
| P1 | 서재에 책이 하나 이상 있거나, 비어 있어도 "아직 쌓인 것이 없어요"를 보인다 |
| P2 | 쌓인 것은 **나만 보기**가 기본이다(FR-9) |

## 4. 기본 흐름 — 짧게 보기에서 시작

| # | 사용자 | 시스템 |
|---|---|---|
| 1 | 안내 패널에서 서재를 연다(또는 패널이 "이 단계와 이어지는 책이 있어요"라고 **제안**하고 사용자가 누른다) | 패널 안에 **지금 단계와 이어지는 책 몇 권**과 한 줄 요약을 보인다 |
| 2 | 책 한 권을 누른다 | 그 책의 표지와 목차(이름·만든 날·출처·인용)를 보인다. **본문은 보이지 않는다** |
| 3 | "이 단계에 쓰기"를 누른다 | 인용이 +1로 기록되고 패널에 "인용으로 표시했어요"를 보인다 |
| 4 | "전체 화면으로 보기"를 누른다 | **같은 내용**을 넓은 화면에서 보이고, 사용자의 위치(어느 책·어느 줄)는 그대로다 |

## 5. 대안 흐름 — 보기 선택

| 번호 | 갈래 | 흐름 |
|---|---|---|
| A1 | 전체 화면에서 시작 | 책장 → 책 표지·목차 → 쓰기. 4단계의 반대 방향이다 |
| A2 | **세션별 보기**로 바꾼다 | 책이 아니라 **작업 한 번**마다 묶어 그때 쌓인 항목을 보인다. 세션이 알려지지 않은 항목은 "세션 미상"에 모은다 |
| A3 | **책별 보기**로 바꾼다 | 종류마다 한 권으로 묶는다(기본 책장) |
| A4 | 보기를 바꾼다 | **같은 항목이 같은 값**으로 보인다(보기만 다르다). 마지막에 쓴 보기를 다음에도 쓴다(브라우저에 기억) |
| A5 | 패널이 서재를 제안했지만 사용자가 무시한다 | 아무것도 바뀌지 않는다. 같은 제안을 반복하지 않는다 |

## 6. 예외 흐름

| 번호 | 상황 | 시스템 |
|---|---|---|
| E1 | 서재가 비어 있다 | "아직 쌓인 것이 없어요(인터뷰 뒤에 채워져요)"를 보인다. 빈 화면이 아니다 |
| E2 | 책 표지를 읽지 못한다(형식이 다름) | 그 책만 "읽지 못함"으로 표시하고 나머지는 보인다. 지어내지 않는다 |
| E3 | 항목이 많다 | 한 화면에 보이는 개수에 상한을 두고 "더 보기"로 펼친다(개수는 고한결이 정한다) |
| E4 | 세션별 보기인데 세션 정보가 하나도 없다 | "작업 세션 기록이 아직 없어요"를 보이고 책별 보기로 돌아가는 길을 준다 |
| E5 | 좁은 화면(휴대폰 폭) | 전체 화면 보기는 한 열로 쌓이고 가로 스크롤이 없다 |

## 7. 사후 조건

| 조건 | 내용 |
|---|---|
| 성공 | 사용자가 원하는 책·항목을 찾아 보았고, 필요하면 인용이 기록됐다. 보기를 바꿔도 값이 같다 |
| 기록 | 인용 횟수와 마지막 보기만 남는다(본문·개인 정보는 남기지 않는다) |

## 8. 시험 문장 (수용 시나리오 #17 입력)

| 대상 | Given | When | Then |
|---|---|---|---|
| 짧게 보기 | 책 3권이 있고 3단계 진행 중이다 | 패널에서 서재를 연다 | 3단계와 이어지는 책이 **먼저** 보이고 본문은 안 보인다 |
| 전체 화면 | 책을 하나 열어 둔 상태다 | 전체 화면으로 바꾼다 | **같은 책·같은 줄**이 열려 있다 |
| 세션별 | 항목 일부에 세션 정보가 있다 | 세션별로 바꾼다 | 세션 정보가 없는 항목은 "세션 미상"에 모인다 |
| 보기 일치 | 항목 N개가 있다 | 네 가지 보기를 모두 연다 | **항목 수와 각 항목의 값이 모두 같다** |
| 인용 | 책 항목을 열었다 | 열어 보기만 한다 | 인용이 **올라가지 않는다**("쓰기"를 눌렀을 때만) |
| 빈 서재 | 책이 없다 | 서재를 연다 | "아직 쌓인 것이 없어요"가 보인다 |
| 좁은 화면 | 폭 390px | 전체 화면 | 가로 스크롤이 없다 |

## 9. 이 초안이 읽어 넣은 것 (확인해 주세요)

| # | 내용 | 이유 |
|---|---|---|
| 1 | **"세션"을 코딩 도구에서 연 작업 한 번**(FR-7이 알리는 단위)으로 읽었다 | 요구에 세션의 정의가 없다. 개인 환경의 "워크플로우 세션 파일"과는 다른 말이다 |
| 2 | 기본 보기를 **짧게 보기**로 두었다 | 패널이 작게 떠 있다가 정할 게 생기면 묻는 구조와 맞다 |
| 3 | 세션별 보기는 **Could**로 두었다 | 세션 정보가 데이터에 실제로 들어 있는지 확인되지 않았다(API·훅 정보를 받은 뒤 판단) |
| 4 | 보기 선택을 브라우저에 기억하는 것으로 읽었다 | 시연은 서버가 없다 |
