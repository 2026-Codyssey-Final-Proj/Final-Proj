## Context and Problem Statement

세컨드 브레인은 V1에서 5단계까지 만든 지식 창고·마감 알림이고, 팀 레포의 `projects/second-brain/`에서 이어 진행한다(현재 6단계). Navigator의 성장 기록(FR-8)과 같은 문제를 푼다. **코드를 합칠지, 두고 연결만 할지**를 정해야 한다.

## Considered Options

1. **별도 모듈로 두고 인터페이스로만 연결** — 세컨드 브레인은 `projects/second-brain/`에 그대로, Navigator는 기록을 쓰고 읽는 얇은 경계만 둔다.
2. **Navigator 안으로 합침** — 코드를 옮겨 한 구조로 만든다.
3. **대회 뒤에 합침** — 시연 동안은 연결 없이 가상 데이터만 쓴다.

## Decision Outcome (제안)

**Claude 제안: 1.**

| 이유 | 근거 |
|---|---|
| V1 코드·시험이 이미 도는 상태를 건드리지 않는다 | 6단계 진행 중, 5→6 게이트 Go(2026-10-14) |
| 합치는 일은 11/1 동결 전에 비용이 크다 | schedule.md |
| 연결표에 이미 요구별 대응이 있다 | migration.md 6절 |

## Consequences

- 두 구조 사이의 약속(기록 형식)이 생긴다. 이 약속이 3단계 API·데이터 계약(#7)에 들어간다.
- 합치는 결정은 대회 후로 미룬다. 대회 후 개인 작업 이전(소유 미정)과 같이 다룬다.
