## Context and Problem Statement

Navigator는 사용자의 작업 글을 Claude로 판정·초안·리뷰한다. 쓰는 사람은 **깃허브 계정이 있고 Claude를 구독한 AI 입문자**다. API 키를 따로 만들게 하면 입문자에게 진입 장벽이 되고, 서버를 두고 우리가 대신 호출하면 인증·비용·약관을 우리가 져야 한다. 어떤 방식으로 Claude를 부를지 정해야 한다.

## Considered Options

1. **구독만** — 사용자 컴퓨터에 로그인된 Claude Code(`claude -p`)로만 호출한다.
2. **구독이 기본, API 키는 선택 (채택)** — 키가 없으면 구독으로, 키가 있으면 그 사람 키로, 둘 다 없으면 연습용 예시로 동작한다.
3. **API 키만** — 모든 사용자가 자기 키를 만든다.
4. **우리 서버가 대신 호출** — 호스팅 웹, 로그인·서버가 필요하다.

## Decision Outcome

**2를 채택한다. 기본은 사용자 본인의 Claude 구독이다 — Claude만 구매한 사람도 키 없이 쓸 수 있다.**

| 순서 | 조건 | 동작 |
|---|---|---|
| 1 | `ANTHROPIC_API_KEY`가 있음 | 그 사람의 키로 호출(한도·사용량도 그 사람 것). 코디세이 같은 중계 서버의 가상 키도 이 경로 |
| 2 | 키가 없고 이 컴퓨터의 Claude Code에 로그인되어 있음 | **구독으로 호출** — 기본 경로 |
| 3 | 둘 다 없음 | 연습용 예시(fixture)로 동작 |

이미 `provider.js` 한 곳에 구현되어 있고(ADR-0003의 "호출은 한 모듈"), 이 ADR은 **그 구조를 유지하겠다는 결정**이다.

### 지켜야 할 것

| 규칙 | 이유 |
|---|---|
| 우리는 **구독 로그인 정보·토큰을 저장·전송·중계하지 않는다** | 각자 컴퓨터의 로그인에만 의존한다 |
| 서버는 이 컴퓨터(127.0.0.1)에서만 받는다 | 다른 웹페이지가 내 구독으로 Claude를 부르지 못하게 |
| 키·로그인 값은 로그·오류·화면에 싣지 않는다 | 기존 `provider.js` 규칙 |
| 사용량 한도를 화면에 알린다 | 구독 한도에 걸리면 입문자가 이유를 모르게 막힘 |
| **남의 컴퓨터를 대신해 우리 구독·키로 호출해 주지 않는다** | 아래 4번과 다른 선택이다 |

## Consequences

- **Claude 구독자는 키 없이 바로 쓸 수 있다.** Claude를 구독하지 않은 사람은 키를 쓰거나 연습용 예시로만 쓸 수 있다.
- 비용과 한도는 **사용자 몫**이다(구독 한도 또는 본인 키).
- 이 선택은 **설치형**(이 컴퓨터에서 실행, 서버 없음)에 맞는다. 호스팅 웹(4번)은 이 결정 밖이며, 하려면 새 ADR과 약관 확인이 먼저다.
- 구독 한도가 낮으면 한 번에 쓰는 토큰을 줄여야 한다(현재 `NAV_TOKEN_BUDGET`로 상한을 둘 수 있다).

## 확인 필요 (법적 해석을 하지 않았다)

| 항목 | 내용 |
|---|---|
| Anthropic 약관 | Agent SDK 문서는 제3자 제품이 Claude.ai 로그인·구독 한도를 제공하는 것에 사전 승인이 필요하다고 안내하고, 법적 고지는 구독 인증이 Claude Code·Claude.ai 전용이라는 취지로 알려져 있다. 반면 지원 문서는 2026-06-15부터 구독에 월 Agent SDK 크레딧이 있다고 한다. **두 안내가 서로 맞지 않아 공식 페이지에서 직접 확인한다.** 이 ADR은 "사용자가 자기 컴퓨터의 자기 Claude Code를 쓰고, 우리는 인증 정보를 다루지 않는다"는 구조라는 점을 근거로 삼는다 |
| 시점 | **팀 밖에 배포(베타)하기 전**에 확인한다. 확인 결과가 다르면 이 ADR을 새 ADR로 대체한다 |
| 미성년·개인정보 | 사용자의 작업 글이 Claude(해외 서비스)로 전송된다는 점의 고지와 보관 기준은 보안 기준에서 따로 다룬다 |
