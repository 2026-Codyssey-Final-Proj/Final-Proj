# 패턴 카탈로그

7단계(유지보수)에서 새로 배운 패턴이 쌓이는 곳. 3단계(패턴 분석)에서 검색/참조합니다.
항목은 Volere 카드 형식으로 통일합니다.

## 항목 형식

```
## <패턴 이름>

- 트랙: 알고리즘 / 프로젝트
- 계층: 설계 패러다임 / 구현 기법 패턴 (알고리즘) — 또는 아키텍처 스타일 (프로젝트)
  ([03-pattern-analysis](../03-pattern-analysis/01-algorithm-paradigms.md) 분류 참고)
- 태그:
- 언제 쓰는가:
- 트레이드오프:
- 예시 문제/사례:
- 처음 배운 날짜/출처:
```

> `트랙`/`계층` 필드는 항목이 쌓이면 알고리즘 기법과 아키텍처 패턴이 검색에서
> 뒤섞이는 걸 막기 위해 있습니다.

위 형식으로 7단계 회고에서 하나씩 쌓입니다. 아래 UI 패턴 5개는 회고가 아니라 **끝난 팀 과제에서 가져온 것**이고,
화면을 만들 때 꺼내 쓰려고 등록했습니다(사용자 결정 2026-10-04 "(다)"). 코드는 `source/` *(V1에만 있음)*에 있습니다.

## 사유 붙은 비활성 버튼 + 게이트 블록

- 트랙: 프로젝트
- 계층: UI 패턴 (화면 구성 — 03-pattern-analysis의 아키텍처 스타일 분류 밖)
- 태그: ui, 접근성, 게이트, 차단, vue
- 언제 쓰는가: 조건이 안 맞아 행동을 막아야 할 때. 회색 버튼만 남기지 않고 **이유("G4 - 프리미엄 전용")와 푸는 법**을 버튼 옆과
  화면 위 고정 블록에 함께 보인다. `disabled` 대신 `aria-disabled` + `aria-describedby`로 이유를 읽어 준다(포커스도 유지)
- 트레이드오프: 문구가 늘어 화면이 길어진다. 토스트·팝업은 쓰지 않는다 — 사라지는 알림은 벽이 아니다
- 예시 문제/사례: Intent-Specify C2·C3 — C3ReasonedButton.vue *(V1에만 있음)*,
  C2GateBlock.vue *(V1에만 있음)*, 원칙 U1(SD_02 §1 *(V1에만 있음)*)
- 부분 사례(푸는 법이 빠진 쪽): 서비스 포털(코딩마라톤 가이드 묶음 8, 스크린샷) — 서비스 카드 24개 중 16개가 `권한 부족`이고 카드마다 필요한 역할 배지(USER·ADMIN·EDITOR)가 보여 **이유는 있다.** 그러나 누구에게 요청하는지, 요청 버튼은 **화면에서 보이지 않는다**(화면 밖에 있을 수 있다). 강의 자료 5의 "해제 주체가 내가 아니면 버튼은 '요청 보내기'"가 메우는 자리다
- 처음 배운 날짜/출처: 2026-10-04 / Intent-Specify(코딩마라톤 팀 과제). 부분 사례는 2026-10-08 / 서비스 포털 스크린샷

## 근거 칩과 근거 드로어

- 트랙: 프로젝트
- 계층: UI 패턴
- 태그: ui, 추적성, 근거, 요약, ai-출력
- 언제 쓰는가: AI가 만든 결과(요구사항, 요약)가 **어디서 나왔는지** 보여야 할 때. 항목마다 근거 번호 칩을 달고, 누르면 원문 대화가
  옆에서 열린다. 근거가 없으면 "근거 없음" 태그로 사람 확인을 받는다
- 트레이드오프: 생성 단계에서 근거 번호를 함께 받아야 하고, 그 번호가 실제로 있는지 검증해야 한다(모델이 엉뚱한 번호를 댈 수 있다)
- 예시 문제/사례: C4EvidenceChip.vue *(V1에만 있음)*·C4EvidenceDrawer.vue,
  [RTM](../02-problem-analysis/05-traceability.md)을 화면으로 옮긴 것. 세컨드 브레인 요약의 "근거" 칸 후보
- 처음 배운 날짜/출처: 2026-10-04 / Intent-Specify

## 진행 레일

- 트랙: 프로젝트
- 계층: UI 패턴
- 태그: ui, 진행, 단계, 상태
- 언제 쓰는가: 여러 단계를 거치는 흐름에서 **지금 어디이고 어디가 막혔는지**를 모든 화면 위에 항상 보일 때
- 트레이드오프: 화면 위 공간을 차지한다. 단계 상태의 원천이 하나여야 한다(화면이 따로 계산하면 어긋난다)
- 예시 문제/사례: C1ProgressRail.vue *(V1에만 있음)*, 원칙 U4. 우리 방향 점검 페이지의 "지금 사용자 차례"와 같은 역할
- 처음 배운 날짜/출처: 2026-10-04 / Intent-Specify

## 생성 상태 표시 + 폴링

- 트랙: 프로젝트
- 계층: UI 패턴
- 태그: ui, llm, 비동기, 대기, 재시도
- 언제 쓰는가: LLM 생성처럼 수 초~수십 초 걸리는 작업. 시작하면 상태(생성 중 / 재생성 중 / 실패, 다시 시도)를 보이고 서버 상태를
  주기적으로 확인한다. 일정 시간이 지나면 안내 문구를 바꾼다(설정값 `ui.retry_notice_seconds`)
- 트레이드오프: 폴링 간격만큼 요청이 늘고 반응이 늦다. 스트리밍보다 단순하지만 덜 즉각적이다
- 예시 문제/사례: useGenerationPoll.ts *(V1에만 있음)*, C6GenerationStatus.vue
  (원본의 `api/sessions` 모듈은 복사하지 않았다 — 구조만 본다). 기록·보안 기준 6-1(실패를 숨기지 않는다)과 같은 생각
- 처음 배운 날짜/출처: 2026-10-04 / Intent-Specify

## 디자인 토큰 단일 원천 + 라이트/다크

- 트랙: 프로젝트
- 계층: UI 패턴
- 태그: ui, css, 디자인-토큰, 다크-모드, 접근성
- 언제 쓰는가: 색·글꼴을 화면마다 쓰지 않고 토큰 한 파일에서 정의하고, 다크 모드는 **값만 바꾼다**. 상태 표시(차단·추가·수정·삭제)는
  전용 확장 토큰으로
- 트레이드오프: 토큰 이름을 먼저 정해야 한다. 원값을 바꿀 때 근거를 주석으로 남기는데, **주석과 값이 따로 놀 수 있다** — 원본에서 대비 조정
  주석은 `#6e6e73`, 실제 값은 `#5c5c62`였다(반대 사례)
- 예시 문제/사례: tokens.css *(V1에만 있음)*, useTheme.ts *(V1에만 있음)*.
  **색값은 다른 회사 디자인 분석에서 왔다 — 구조만 쓰고 색은 새로 정한다**(`theme-factory` 스킬로 고르기)
- 처음 배운 날짜/출처: 2026-10-04 / Intent-Specify
