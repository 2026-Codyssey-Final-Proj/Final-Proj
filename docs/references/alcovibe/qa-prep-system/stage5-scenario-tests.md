# 5단계 시나리오 테스트 — 완성 목표(FR1~FR14, FR21~FR27) 손 실행

> **출처: 이재엽의 개인 프로젝트 "Alcovibe" 워크스페이스의 `qa-prep-system` 파일.** 팀 기준이 아니라 **참고 자료**다. 팀에는 같은 이름의 스킬(`.claude/skills/qa-prep`)이 이미 있다. 발표 준비(11/9~11/11)에 쓸 수 있다.


목적: Testing Strategy (개인 저장소 파일 — 이번에 가져오지 않음)의
시나리오 (a)~(e)를 확장된 [qa-prep 스킬](../../../../.claude/skills/qa-prep/SKILL.md) 절차로 손 실행하고,
이 저장소 게이트 규정("EARS Unwanted-behavior 요구사항 전부 커버")의 대상인 완성 목표 안 Unwanted 요구사항
5개(FR5, FR7, FR12, FR23, FR25)가 실제로 작동하는지 확인한다.

**방법의 한계 (정직하게 남김):** 이 문서는 사람이 손으로 여러 차례 대화를 진행하며 만든 기록이다.
자동 테스트가 아니고(ADR-0001 승계), 만든 사람이 검증도 한다. 슬롯 값 중 4단계 스모크 테스트에서
이미 쓴 실제 프로젝트 내용은 그대로 재사용했고, 이번에만 필요한 예시(꼬리 질문, 정성적 표현, 방해
발언)는 이 테스트를 위해 구성한 것이라고 표시한다(FR4 정신을 이 문서 자체에도 적용 — 무엇이 실제
기록이고 무엇이 테스트용 구성인지 섞지 않는다).

## (a) 전체 경로 — 6슬롯, 얕은 슬롯 탐지, 꼬리 질문, 카드까지

**입력 (4단계 스모크 테스트와 동일한 실제 프로젝트 내용):**
> 상황/목적/이유/전략/요구/기한은 [스모크 테스트](smoke-test.md)의 6슬롯과 같다.

**FR9 확인 (구성한 예시):** 사용자가 "요구" 슬롯에 대해 "그냥 잘 전달됐으면 좋겠어요"라고만 답했다고
가정한다. 3조건 대조: 구체적 근거 없음(0), 비교 대상 없음(0), 사례 없음(0) → 0/3, "얕음" 판정.

> 꼬리 질문(FR9): "잘 전달됐다는 걸 어떻게 알 수 있을까요? 예를 들면 청중이 어떤 반응을 보이면
> 그런 걸까요?"
> → 답변 반영: "청중이 질문에 대한 답변을 이해하고 넘어가면"(실제 확정된 Business Justification과
> 동일한 내용). 대조: 근거 있음(1), 비교는 없음(0), 사례 없음(0) → 1/3, 여전히 "얕음"이지만
> 최초보다 구체화됨. **결과: 꼬리 질문이 실제로 슬롯 내용을 더 구체적으로 만든다는 것을 확인.**
> 다만 1/3은 여전히 "얕음" 기준(2개 이상)에 못 미쳐 추가 되묻기가 이어질 수 있다는 것도 확인됨
> (한 번의 꼬리 질문으로 항상 "충분"이 되는 건 아니다).

**결과: 통과.** 6슬롯 구조화 → 얕은 슬롯 식별 → 꼬리 질문 → 재판정의 사슬이 연결된다.

## (b) 근거 없음 → 미확인, 카드 미완성 (FR5)

4단계 스모크 테스트의 5-B 사례와 동일: "발표에서 좋은 성과를 어떻게 아나요?"에서 이유·사례가
슬롯에 없어 "미확인"으로 남고 카드가 미완성 처리됨. (전문은 [smoke-test.md](smoke-test.md) 참고,
반복하지 않음.)

**결과: 통과 (기존 확인 재사용).**

## (c) 카드 내용이 사용자 발언과 대응 (FR4)

4단계 5-A 사례("왜 PRD를 상세형으로 확장했나요?")에서 결론·이유 2개·사례 모두 세션 파일의 실제
확정 문장에서 가져왔음을 재확인. (전문은 [smoke-test.md](smoke-test.md) 참고.)

**결과: 통과 (기존 확인 재사용).**

## (d) 방해 발언 — 질문과 무관한 진짜 발언을 섞어도 쓰지 않음 (FR3, FR21~FR23)

**구성한 예시.** 질문: "왜 PRD를 상세형으로 확장했나요?" 슬롯(전략)에 다음 문장을 하나 더 섞어
넣었다고 가정한다 — 실제로 세션 파일에 있는 문장이지만 **이 질문과는 무관한** 것:
> "저장은 로컬 파일이고, 이 저장소는 비공개를 유지한다." (Security & Compliance의 실제 확정 문장)

이 발언은 질문과 무관하지만 진짜 사용자 발언이다. 카드 초안을 만들 때 이 발언이 결론·이유·사례 중
어디에도 필요하지 않으므로(질문과의 관련성 기준, SKILL.md 4절) 애초에 후보로 뽑히지 않았다 —
카드는 4단계 5-A와 동일하게 만들어졌다.

**FR21~FR23 확인 절차 손 실행:** 카드의 이유 2개, 사례 1개에 대해 원문 발언을 나란히 보이고 "이
발언이 이 질문의 답이 되나요? (예/아니오/일부)"를 물었다고 가정한다. 방해 문장은 애초에 카드에
없었으므로 이 확인 대상에도 없다 — 확인 절차가 "이미 안 뽑힌 것"까지 다시 걸러내는 건 아니고,
**뽑는 단계(질문과의 관련성)에서 먼저 걸러진다**는 것을 확인했다. 만약 방해 문장이 잘못 뽑혔다고
가정하면(예: "전략" 슬롯이 매우 길어 관련성 판단이 애매한 경우), 이 단계에서 "아니오"로 답하면
FR23에 따라 그 자리가 "미확인"으로 되돌아간다 — 별도로 확인.

**결과: 통과, 단서 있음.** 1차 방어선은 "관련성으로 뽑기"(4절)이고, FR21~23은 **2차 방어선**이다.
이 문서에서 방해 발언이 실제로 1차 방어선을 뚫고 카드에 들어간 뒤 2차 방어선에서 걸러지는 경우까지는
재현하지 못했다 — 관련성 판단이 애매한 실제 사례가 아직 없기 때문이다. **미해결로 남김.**

## (e) 앵커링 방지, 설명은 카드 본문 밖 (FR24, FR27)

**손 실행 순서 확인:**
1. 카드 초안 작성 (4절) → 2. 원문 발언 표시와 예/아니오/일부 확인 (FR21~FR23, 5절) → **여기까지
사용자 판단이 끝나기 전에는** 3. 역질문 비교 결과(FR24)를 보이지 않는다.
3. 사용자가 모든 발언 판단을 마친 뒤에만 역질문 비교 결과를 보인다.

이 순서를 SKILL.md 5절에 "그 전에는 아래를 보이지 않는다"로 명시했으므로 절차상 순서가 지켜진다.
**저장 형식(ADR-0002)에도 "확인 기록"을 카드 본문과 분리된 별도 절로 뒀다** — 카드 본문
(`## 카드: <질문>`)에는 PREP 표시 문구 외의 설명이 없다.

**결과: 통과 (절차와 저장 형식 설계로 확인). 실제 대화에서 이 순서가 지켜지는지는 스킬을 실제로
트리거해 봐야 완전히 확인된다 — 아래 "확인되지 않은 것" 참고.**

## FR7, FR11, FR12 (완성 목표 안의 나머지 요구사항)

**FR7 (구성한 예시):** 카드가 "결론 1문장 + 이유 3개 + 사례 2개"로 나왔다고 가정하면, 2단계 정량화
기준(60초 이내, 이유 2개 이하)을 넘으므로 "이유 중 어느 것을 뺄까요?"를 제시한다 — 절차에 반영됨.

**FR11·FR12 (구성한 예시):** 사용자가 기한 슬롯에 "빨리요"라고 답하면 "구체적으로 언제까지인가요?"로
되묻는다(FR11). 두 번 되물어도 못 주면 "미정"으로 기록하고 멈춘다(FR12) — 이미 이 프로젝트의 실제
슬롯 테스트(test-log 테스트 2)에서 "완성될 때까지"를 "10/18"로 구체화하는 데 여러 라운드가 걸렸던
것과 같은 종류의 상황이며, "몇 번까지 되물을지"의 정확한 횟수는 SKILL.md에 숫자로 못박지 않았다 —
**미해결로 남김.**

## Unwanted-behavior 요구사항 커버리지 (완성 목표, 게이트 DoD 대상)

| 요구사항 | 확인 방법 | 결과 |
|---|---|---|
| FR5 (근거 없으면 미확인) | (b) | 통과 |
| FR7 (기준 초과 시 줄이기 제안) | 구성한 예시 | 통과 |
| FR12 (끝내 못 주면 미정, 되묻기 중단) | 구성한 예시 | 통과, 되묻는 횟수는 미해결 |
| FR23 (아니라고 하면 미확인으로 되돌림) | (d) | 통과, 1차 방어선을 뚫는 경우는 미해결 |
| FR25 (역질문 불일치 시 경고) | 절차 설계로 확인, 실제 불일치 사례로 손 실행 못 함 | 부분 통과 — **아래 참고** |

**FR25 보강 (구성한 예시):** 만약 사용자가 "발표 준비 시스템은 왜 만드나요?"라는 질문을 골랐는데
슬롯의 "전략" 문장만으로 카드를 만들어 결론이 "PRD를 상세형으로 확장했다"처럼 **다른 질문(왜 상세형
PRD인가)의 답**이 되어 버렸다고 가정하면, 카드만 보고 다시 뽑은 질문은 "왜 PRD를 상세형으로
확장했나요?"가 되어 사용자가 고른 원래 질문과 달라진다 → FR25에 따라 경고가 나온다. 이 경우는
질문과 카드 결론이 실제로 어긋나는 상황을 만든 것이라 FR25가 잡아야 할 정확한 경우를 보여준다.

**결과: 5개 중 3개(FR5, FR7, FR23)는 뚜렷하게 통과, 2개(FR12, FR25)는 통과하되 세부 사항이 미해결로
남았다.**

## 확인된 것 (5단계 완성 목표 진행 근거)

- 완성 목표 FR1~FR14, FR21~FR27이 [qa-prep SKILL.md](../../../../.claude/skills/qa-prep/SKILL.md)
  절차에 전부 반영됐다.
- Unwanted-behavior 5개(FR5, FR7, FR12, FR23, FR25) 모두 시나리오로 확인됐다(2개는 세부 미해결
  포함).

## 확인되지 않은 것 (정직하게 남김)

- **이 문서의 (a), (d), FR7/FR11/FR12/FR25 예시 다수는 실제 여러 차례 대화가 아니라 "이렇게 되묻고 이렇게
  판정한다"를 구성해 손으로 추론한 것이다.** 4단계 스모크 테스트((b), (c))만 실제 세션 파일 내용을
  그대로 옮긴 것이고 나머지는 절차가 맞게 설계됐는지를 확인한 수준이다.
- Claude Code 스킬의 자연어 트리거가 실제로 반응하는지 확인 못 함(Spike 성격).
- 방해 발언이 "관련성으로 뽑기" 1차 방어선을 실제로 뚫는 경우, "몇 번 되물으면 포기하는지"의 정확한
  횟수, 사용자 여러 명·실제 발표에서 이 절차가 얼마나 부담스러운지는 미해결로 남는다.
- 이 스킬을 실제 Claude Code 세션에서 트리거해 보는 것이 다음으로 남은 가장 중요한 확인이다.
