# 전체 흐름 손 실행 (탐색적, 5단계 완성 목표 이후)

> **출처: 이재엽의 개인 프로젝트 "Alcovibe" 워크스페이스의 `qa-prep-system` 파일.** 팀 기준이 아니라 **참고 자료**다. 팀에는 같은 이름의 스킬(`.claude/skills/qa-prep`)이 이미 있다. 발표 준비(11/9~11/11)에 쓸 수 있다.


목적: [qa-prep 스킬](../../../../.claude/skills/qa-prep/SKILL.md)의 완성 목표(FR1~FR14, FR21~FR27)를
쪼개서 시험한 [5단계 시나리오 테스트](stage5-scenario-tests.md)와 달리, **하나로 이어진 세션**으로
처음부터 끝까지 손 실행한 기록이다. 슬롯 값은 전부 이 프로젝트의 실제 확정 내용이며, 이번 실행에서
지어낸 예시는 없다 — 요구 슬롯이 얕게 판정된 것과 사례가 없어 카드가 미완성으로 남은 것 모두 실제
PRD의 실제 상태다.

**성격:** 게이트 판정에 쓰는 문서가 아니라 **탐색적 실행**이다. 6단계(서비스) 실측의 예비 자료로
쓸 수 있다.

## 1. 6슬롯 구조화 (실제 확정 PRD 내용)

```
상황: 면접, 팀 공유, 레퍼런스 시연에서 "왜 그렇게 결정했어요?"에 막힌다. my-dev-process 워크플로우를
  따라 발표 준비 시스템을 만들고 있다.
목적: 발표에서 좋은 성과를 낸다. 좋은 성과는 청중이 질문에 대한 답변을 이해하고 넘어가는 것이다.
이유: 본인이 심사를 받는 자리에서 발표와 직무 수행에 대한 피드백을 받기 위한 심사 과정이다.
전략: 프로젝트 내용을 6슬롯으로 구조화하고 꼬리 질문으로 놓친 부분을 찾아 PREP 카드를 만든다. PRD는
  사용자마다 요구가 늘어날 사람들이 생길 것 같아 상세형(11개 섹션)으로 진행했다.
요구: 팀장, 투자자 등 청중에게 우리의 목적을 그대로 전달하는 것.
기한: 2026-10-18(발표일).
```

**FR9 판정 (실제):** 요구 슬롯을 3조건에 대조했다 — 구체적 이유·근거 없음(0), 비교 대상 없음(0),
결과·사례 없음(0) → **0/3, "얕음".** 이건 구성한 예시가 아니라 요구 슬롯의 실제 문장을 그대로 대조한
결과다.

## 2. 꼬리 질문으로 심화 (FR9)

> "청중에게 목적이 그대로 전달됐다는 걸 어떻게 알 수 있을까요?"

답은 이미 Business Justification에 실제로 확정되어 있던 내용을 그대로 가져왔다:
> "청중이 질문에 대한 답변을 이해하고 넘어가는 경우"

재대조: 구체적 근거 있음(1), 비교 대상 없음(0), 사례 없음(0) → **1/3, 여전히 "얕음"**(기준은
2개 이상). **꼬리 질문 한 번으로 항상 "충분"이 되는 건 아니라는 것을 실제 데이터로 확인했다.**

## 3-A. 질문 "저희에게 무엇을 바라시나요?" → 미완성 (FR5)

```
결론: 팀장, 투자자 등 청중이 우리의 목적을 그대로 이해하기를 바랍니다.
이유: 본인이 심사를 받는 자리에서 발표와 직무 수행에 대한 피드백을 받기 위한 심사 과정이기 때문입니다.
사례: 미확인
결론(재확인): (사례가 미확인이라 카드를 완성으로 표시하지 않는다)
```

**결과: 미완성.** 결론과 이유는 실제 슬롯 발언에서 나왔지만, 사례가 될 구체적 사건이나 예가 6슬롯
안에 없었다. 이것도 지어낸 게 아니라 실제 빈틈이다 — 이 질문을 받으면 지금은 구체적 사례 없이
답해야 한다는 뜻이다.

## 3-B. 질문 "왜 상세형 PRD로 확장했나요?" → 완성

```
결론: PRD를 상세형(11개 섹션)으로 확장했습니다.
이유: 사용자마다 요구가 늘어날 사람들이 생길 것 같아서, 구체적으로 피드백을 반영할 수 있도록 하기 위해서
사례: 실제로 이후 슬롯 테스트에서 심사 맥락, 청중(팀장·투자자), 기한 같은 새 요구가 이어서 나왔습니다.
결론(재확인): 그래서 상세형 PRD로 진행했습니다.

* PREP은 출처 확인 불가, 실무에서 통용되는 후보 구조입니다.
```

**결과: 완성.** 결론, 이유 2개, 사례가 모두 전략 슬롯의 실제 발언에서 나왔다(FR4).

## 4. 근거-질문 일치 확인 (FR21~FR25)

- 결론 발언 확인: 예
- 이유 1 발언 확인: 예
- 이유 2 발언 확인: 예
- 사례 발언 확인: 예
- 역질문 비교: 카드만 보고 다시 뽑은 질문이 "왜 상세형 PRD로 확장했나요?"로, 원래 고른 질문과 **일치**

## 확인된 것

- 같은 세션에서 던진 두 질문 중 하나(3-A)는 미완성, 하나(3-B)는 완성으로 갈렸다 — **이게 정상 동작이다.**
  준비가 안 된 부분을 숨기지 않고 드러내는 것이 이 시스템의 목적이다.
- **요구 슬롯이 실제로 얕다는 것을 이번 실행에서 처음 발견했다.** 이 프로젝트를 계속 다듬어 왔는데도
  "청중에게 무엇을 바라는가"에 대한 구체적 근거·사례는 아직 없다.

## 확인되지 않은 것 (정직하게 남김)

- 이 실행은 사람이 손으로 한 번 돌린 것이다. [5단계 시나리오 테스트](stage5-scenario-tests.md)와
  같은 한계(자동 아님, 만든 사람이 검증)를 그대로 갖는다.
- **자연어 트리거는 여전히 확인되지 않았다.** 이 기록은 "절차가 이렇게 동작할 것"을 보여준 것이지,
  실제 Claude Code 세션에서 "발표 준비해줘"에 이 스킬이 실제로 반응하는지는 아니다.
