# 세션 운영 — 여러 Claude 세션을 나눠 쓰는 법

이 워크스페이스는 Claude 세션 여러 개를 **같은 작업 폴더**에서 동시에 쓴다(2026-10-06 기준 8개). 세션끼리는 기억이
이어지지 않고, 작업 폴더·브랜치·PR은 공유된다. 이 문서는 그 상태에서 서로 덮어쓰지 않고 이어 가는 방법이다.

## 왜 필요한가 — 2026-10-06 하루에 실제로 일어난 일

| 일어난 일 | 결과 |
|---|---|
| 다른 세션이 공유 작업 폴더의 브랜치를 바꿨다 | 이 세션이 보던 파일이 다른 브랜치의 것으로 바뀜 |
| 다른 세션이 규칙·장부 초안을 커밋하지 않은 채 남겼다 | 같은 파일(`CLAUDE.md`, `consistency.md`)을 고치려면 남의 변경을 골라내야 했음 |
| 두 세션이 같은 PR 브랜치에 커밋했다 | 푸시 거절, 겹친 줄을 손으로 합침 |
| Claude가 푸시한 몇 분 뒤 PR이 병합됐다(4번) | 그 브랜치에 다음 커밋을 올렸으면 `main`에 빠질 뻔함 — 병합 확인 훅이 막음 |
| 두 세션이 겹치는 일을 했다 | 추적표(RTM) 초안이 요구 32개 기준으로 열렸고, 다른 세션이 그사이 확정한 7개가 빠짐 |
| 로컬 `main`에 푸시하지 않은 커밋이 생겼다 | 어느 세션이 만들었는지 작업 폴더만 봐서는 알 수 없음 |

공통 원인: **세션이 공유 상태(작업 폴더, 브랜치)를 "내 것"으로 가정**했다.

## 원칙

1. **세션 하나 = 주제 하나 = 브랜치 하나 = PR 하나.** 주제가 끝나면 PR을 열고 세션을 닫는다. 다른 주제가 떠오르면 새 세션에서 한다.
2. **세션마다 따로 작업 폴더(git worktree)를 쓴다.** 공유 작업 폴더에서 브랜치를 바꾸지 않는다.
3. **상태는 원천 파일에만 적는다** — 프로젝트는 세션 파일 게이트 로그, 워크스페이스 후보는
   [후보 장부](../catalog/reference-candidates.md), 묶음 받기는 `~/proj/coding_marathon_result/코딩마라톤 가이드/README.md` 받은 기록표(다른 저장소·로컬 폴더).
   다음 세션은 대화가 아니라 이 파일에서 이어 간다.
4. **커밋할 때마다 그 브랜치의 PR이 병합됐는지 다시 본다** — 세션 시작 때 한 번이 아니다. 병합됐으면 최신 `main`에서 새 브랜치를
   딴다([git-workflow.md](../../.claude/rules/git-workflow.md), `block-merged-branch-push.sh`).
5. **다른 세션이 남긴 커밋 전 파일은 건드리지 않는다.** 같은 파일을 고쳐야 하면 내 변경만 골라 커밋하고, 그 사실을 사용자에게 말한다.
   꼭 커밋해야 하면(예: 내 문서가 그 파일을 링크) **수정 없이 따로 한 커밋**으로 올리고 메시지에 출처를 적는다.

## 주제 종류

| 종류 | 예 | 원천 | 같이 돌려도 되나 |
|---|---|---|---|
| 프로젝트 단계 진행 | 세컨드 브레인 2단계 RTM, 3단계 ADR | 그 프로젝트의 세션 파일 | 같은 프로젝트의 다른 단계와는 **안 됨**(같은 세션 파일) |
| 참고 자료 묶음 | 코딩마라톤 가이드 묶음 문서화 → 비교 | 받은 기록표 + 후보 장부 | 됨 — 단 장부를 고치는 다른 세션과는 안 됨 |
| 워크스페이스 메커니즘 | 규칙·훅·체크리스트·장부 판정 | 후보 장부, 각 규칙 파일 | 같은 규칙 파일을 고치는 세션과는 안 됨 |
| 리뷰 | 게이트 리뷰, 커밋·PR 리뷰 | 성장 로그 | 됨 |

같은 원천 파일을 고치는 두 세션은 **동시에 열지 않는다** — 이게 오늘 겹침의 대부분이었다.

## 세션 하나의 흐름

**시작 — 첫 메시지에 한 줄**

```
주제: <무엇> / 원천: <어느 파일> / 이어서: <지난번 남은 일, 원천 파일의 어디>
예) 주제: 세컨드 브레인 RTM / 원천: 세션 파일 2단계 6절 / 이어서: PR #36에 F15·F16·S9 7줄 추가
```

**작업 폴더 만들기** (Claude가 한다)

```bash
git fetch origin
git worktree add -b <브랜치> <scratchpad>/<이름> origin/main
```

**진행** — 확인은 한 번에 5개까지([review-mode.md](../../.claude/rules/review-mode.md) 질문하는 법 2). 확정은 원천 파일에만 쓴다.
커밋 전마다 `gh pr list --head <브랜치> --state all`.

**끝**

1. PR을 연다(병합은 사용자).
2. 남은 일을 원천 파일에 적는다 — 대화에만 남기지 않는다.
3. 작업 폴더를 지운다: `git worktree remove <scratchpad>/<이름>`. 병합된 브랜치는 사용자가 원하면 원격·로컬 모두 지운다
   (지우기 전 `git log origin/main..<브랜치>`가 비었는지 확인).
