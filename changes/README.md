# 버전 기록 조각 — PR마다 파일 하나

PR은 [CHANGELOG.md](../CHANGELOG.md)를 고치지 않는다. 대신 여기에 **`<브랜치 끝 이름>.md`** 한 장을 둔다.
`main`에 올라오면 Action([jira-release.yml](../.github/workflows/jira-release.yml) → [changelog-fold.js](../.github/scripts/changelog-fold.js))이
CHANGELOG 맨 위 버전의 **다음 번호**를 붙여 표에 넣고, 이 파일을 지우고, PR 번호 `(#n)`을 "무엇" 끝에 붙인다.
그래서 동시에 열린 PR이 CHANGELOG 한 줄에서 부딪치지 않는다(2026-10-19 하루에 PR 넷이 v4.0을 골랐던 일).

## 파일 내용 — 네 줄, `키: 값`

```
종류: 작은 고침
누가: 이재엽
무엇: 게이트 문구를 쉬운 말로 (F-12)
건드린 곳: `02-frontend/navigator/`(담당 임유정 — 이 줄이 알림)
```

| 줄 | 값 |
|---|---|
| `종류` | **큰 묶음**(기능을 더하거나 바꿈 → N+1.0) 또는 **작은 고침**(버그 · 문서 · 시험 → M+1). 번호는 병합될 때 정해진다 — 사람은 종류만 고른다 |
| `누가` | 올린 사람 이름([TEAM.md](../TEAM.md)) |
| `무엇` | 한 줄. 고칠 목록 번호(F-n) · Jira 키가 있으면 같이 |
| `건드린 곳` | 폴더. 남의 담당 폴더를 고쳤으면 그 폴더 — 이 칸이 담당에게 가는 알림 |

- 값에 `|`를 쓰지 않는다(표 칸이 깨진다). `python3 04-tests/run_all_tests.py`가 네 줄과 `|`를 먼저 잡는다.
- 파일 이름은 브랜치의 마지막 조각(`v2/gate-copy` → `gate-copy.md`)으로 — Action이 병합 커밋의 브랜치 이름과 맞춰 PR 번호를 붙인다(이번 push와 지난 병합 커밋 200개까지 — 앞 실행이 실패해 남은 조각도 제 번호를 받는다). 이름이 달라도 합쳐지며, 조각이 하나뿐이면 그 push의 PR 번호를 붙인다.
- `main`에 직접 올릴 때는 조각 대신 CHANGELOG 맨 위에 한 줄을 직접 써도 된다(그 다음 조각은 그 줄 다음 번호를 받는다).
- 한 push에 조각이 여럿이면 이름순으로 차례 번호를 받는다.
