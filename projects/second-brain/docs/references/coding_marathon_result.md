- **무엇:** 코딩마라톤 팀 과제의 결과물. **Intent-Specify** — 막연한 아이디어를 4범주 질문(동기·범위·성공기준·메타)으로
  되물어 모호한 표현은 숫자로 확정하고, 근거(대화 번호)가 붙은 EARS 요구사항 명세로 바꿔 주는 웹 서비스. 두 번째 기능으로
  확정 명세의 요구사항마다 Given-When-Then 수용 테스트를 만든다. Vue 3 + Express(TypeScript) + 지정 MariaDB + Claude API.
  기준 커밋 `cd3e899`(2026-10-06 비밀번호 제거로 이력을 다시 쓰기 전 `b0456e8`)(2026-10-03). 명세 → 계획 → 작업 → 구현 순서(spec-kit 방식, `.specify/`)로 진행했다.
- **같은 마라톤의 강의 자료와의 관계:** [coding-marathon.md](coding-marathon.md)는 **받은 자료**에서 배울 것, 이 문서는 그 자료로
  **직접 만든 것**에서 배울 것이다. 강의 자료의 분석설계 프롬프트(유스케이스·프로세스·UI/UX·아키텍처)와 DDBM 캔버스를 실제로 썼다
  (`design/UC_*`, `SD_01·02·04`, `Intent-Specify.md`).
- **목적 연결:** **P2 프로젝트 진행**(가장 강함 — 이 서비스가 하는 일이 우리 1·2단계와 거의 같다), **P4 보안**(비밀값·실행 기록·
  재시도 상한을 코드로 강제한 사례). P1·P3는 약함.
- **내 몫:** **공백** — 팀 3인 과제인데 저장소에서는 누가 무엇을 했는지 구분되지 않는다(구현 커밋 하나에 전부 들어 있음). 사용자가 채운다.

## 교훈

- **강의 자료를 이틀(10-02~10-03) 안에 실제로 썼다.** 유스케이스 7개(+개요)·프로세스·UI/UX·아키텍처 설계서가 명세·계획의 근거 칸에 번호로 이어진다
  — 우리 원문제("배운 게 재사용되지 않는다")의 반대 사례.
- **목표 수치를 재지 못한 채 끝났다.** "다음 질문 p90 10초", "명세 생성 90초"는 API 키가 없어 fixture로만 돌았다 — 측정 스크립트만 있다.
- **빈 단계 파일이 남았다.** `Intent-Clarify`·`Intent-Report`·`Intent-Implement`는 "기록이 없습니다"뿐이다. 회고(Report)가 없다.
- **확인 대기 4건이 열린 채다**(단체 라이선스 내보내기 기본값, API 경로의 근거 없음 처리, 체험 한도 3회, 운영 API 키·예산).
- 접근성 대비 미달(4.29:1)을 자동 검사(axe)로 찾아 고쳤다 — 자동 검사가 사람 눈보다 먼저 잡은 사례.

## 보안 메모

- 저장소는 **비공개**(GitHub, 2026-10-04 확인). 비밀번호·API 키는 커밋되지 않았다(`.env` 무시, 예시 파일은 자리표시자, 테스트 계정은 가짜 값).
- 다만 **실제 서비스 도메인, 내부 IP, DB 호스트·이름, 배포 계정·경로**가 여러 파일에 평문으로 있다(`CLAUDE.md`, `README.md`,
  `Intent-Plan.md`, 계획 문서, CI 설정). 비밀값은 아니지만 공개하면 공격 표면이 드러난다 — 이 문서에는 옮기지 않았다
  (Nginx/SSL 레프런스 README와 같은 처리).
- 팀원 정보: 저장소에 이름이 드러나는 팀원 정보는 없다(공용 계정 커밋). 이 문서에도 적지 않았다.
- 서비스 쪽 데이터 보호: 대화 원문을 앱에서 AES-256-GCM으로 암호화하고 화면의 이메일을 가린다 — 세컨드 브레인에 다른 사람 정보를
  둘 때 참고할 수 있는 재료.
