## 교훈

- 사용자 진술(README "배운 점"): "Prompt Engineering은 단순히 질문을 잘 작성하는 기술이 아니라, **AI가 안정적으로
  업무를 수행하도록 설계하는 과정**." 세컨드 브레인의 "개인 AI = Claude + 외부 기억" 관점과 이어진다 — 모델을
  학습시키지 않고 규칙과 형식으로 품질을 만든다.
- 사용자 진술: "프롬프트를 개선하면 **무료 모델에서도** 충분히 업무 자동화에 활용 가능한 수준" — 유료 도구를 쓰지
  않는다는 지금 결정과 같은 방향.
- 이 워크스페이스의 질문 규칙("추측하지 않는다", "근거가 없으면 공백")과 같은 원칙을 7월에 이미 스스로 세웠다.
- 관찰(Claude): 커밋 메시지가 "ㅇㅇ", "dd", "라스트"처럼 내용이 없어, 저장소 이력만으로는 무엇을 언제 왜 바꿨는지
  다시 볼 수 없다. 지식 사이클(P1)에서 "기록이 다음 판단의 재료가 되려면" 무엇이 필요한지 보여 주는 사례.
