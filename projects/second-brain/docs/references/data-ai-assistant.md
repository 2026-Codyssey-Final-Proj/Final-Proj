## 무엇

- [gamercross/data-ai-assistant](https://github.com/gamercross/data-ai-assistant) — **"내 데이터를 아는 AI 비서"**.
  사용자가 (날짜, 값, 메모) 데이터를 등록하면 백엔드가 기간·통계·추세 요약을 만들고, 채팅할 때 그 요약을 Gemini
  시스템 프롬프트에 넣어(context injection) 맞춤 답을 한다. 대화는 자동 저장되고 다시 불러온다.
- FastAPI + Firestore + Gemini, 프론트는 HTML/JS. 백엔드 Render, 프론트 Vercel에 배포. 2026-09-17~09-19,
  작성자 사용자 한 명.

## 목적 연결

- **P1 지식 사이클 / "개인 AI" 배경 — 가장 가까운 선행 작업.** 방금 PRD 배경에 넣은 "개인 AI = 훈련된 모델 + 나만의
  외부 기억"을 작은 규모로 이미 만들었다: 내 데이터 → 요약 → 모델에 주입 → 답, 대화 기록 저장.
- **P4 보안** — 아래 보안 메모가 "계정 탈취가 가장 큰 걱정", "로그인이 필요하지 않을까"라는 세컨드 브레인 논의의
  실제 사례다.

## 가져올 것 (후보)

| 단계 | 재료 | 쓰는 곳 |
|---|---|---|
| 3단계 설계 | 원본 데이터를 통째로 넣지 않고 **요약을 만들어 주입** | 지식 창고가 커졌을 때 Claude에게 무엇을 읽힐지(전부 / 요약 / 검색) 비교 |
| 3단계 설계 | 대화 저장·불러오기 | 대화에서 나온 결정을 재료 표처럼 남기는 방식과 비교 |
| 2단계 비용 | `CHAT_MAX_TOKENS`(기본 500)로 응답 길이·비용 제한 | 무료·저비용 운영 요구 |
| 4단계 | `seed_data.py --dry-run`(키 없이 샘플 확인) | 실제 데이터 없이 Walking Skeleton을 돌려 보는 방법 |

## 교훈

- 요약을 시스템 프롬프트에 넣는 방식은 작고 빠르지만, 데이터가 커지면 요약 품질이 곧 답의 품질이 된다 —
  LLM-Prompt-Engineering의 "원문 우선, 모르면 모른다" 규칙과 함께 봐야 한다.

## 보안 메모

- **배포된 백엔드 API에 인증이 보이지 않는다**(라우터에 로그인·토큰 확인 코드 없음). 공개 URL을 아는 사람은 누구나
  데이터를 등록·수정·삭제하고 대화 기록을 읽을 수 있고, Gemini 사용량도 쓸 수 있다. 지금 넣은 데이터가 샘플뿐인지,
  배포를 계속 둘지는 사용자가 확인할 일이다.
- 세컨드 브레인에 주는 교훈: 서버를 두는 순간 **인증이 먼저**다 — 3단계 "서버 필요 여부·인증" ADR의 실제 사례.
- 키는 환경변수(`.env.example`에는 이름만), 저장소에 실제 키 패턴은 보이지 않았다.
