**상태: 설계 확정(2026-10-14), 구현하지 않는다.** 사용자 결정 2026-10-14: 이 내용은 **AI 운영체제에서 확인**하도록 설계만 만들어 두고,
세컨드 브레인의 6단계 실측이 끝난 뒤 **7단계 유지보수·버전 업그레이드**에서 받아 연결한다. 6단계 측정 대상은 바뀌지 않는다.

## 0. 설계 기준 (사용자 결정 2026-10-14)

**자기가 만든 내용이 어떻게 기록되어 있는지, 사용자가 스스로 확인할 수 있어야 한다.** 이 문서의 모든 선택은 이 기준으로 가른다.

| 기준이 뜻하는 것 | 설계에 반영한 곳 |
|---|---|
| 내가 말한 것이 어디에 저장됐는지 찾을 수 있다 | 표지 목차의 `자리`·`문서` 열(5·4절) |
| 언제·어디서 온 것인지 보인다 | 목차의 `만든 날`·`출처` 열 |
| 지금 상태와 바뀐 것이 보인다 | 목차의 `상태`, 표지의 "이번 쇄에서 바뀐 것" |
| 확인했는지가 남는다 | 표지의 "확인" 칸(사용자가 훑은 날짜). 자동 생성과 사람이 확인한 것은 따로 적는다(기록·보안 기준 6-2) |

## 1. 풀려는 문제

작업물과 데이터가 하나씩 기록으로 쌓이는데, **무엇이 어디에 쌓이고 있는지**가 한눈에 보이지 않는다. 지금 `data` 브랜치의
`README.md`는 할 일 문서·실행 기록·목록만 설명하고, 이후 생긴 지식·점검·준비·관찰 자리는 적혀 있지 않다.

## 2. 비유 — 도서관

| 도서관 | 세컨드 브레인 |
|---|---|
| 도서관 | `data` 브랜치 |
| 서가 안내판 | 데이터 루트 `README.md` (책 목록 한 장) |
| 책 한 권 | 폴더 하나 — 아래 3절 |
| 책의 표지·목차 | 그 폴더의 대표 `README.md` |
| 판(edition)·쇄(printing) | 표지의 `n판 m쇄` |
| 책 내용 | 폴더 안 문서 하나하나 (원천) |

## 3. 책 목록 (폴더 하나 = 책 한 권)

| 책 | 자리 | 담는 것 | 쓰는 쪽 |
|---|---|---|---|
| 할 일(목적별 5권) | `vault/<생활·학교·작업·대회·기타>/` | 할 일 문서 | 사용자 말 → Claude |
| 지식(목적별) | `vault/지식/<목적>/` | 관찰·해석·행동 | 사용자 말 → Claude |
| 점검 | `점검/` | 주간 점검 보고 | 자동 생성 |
| 관찰 | `관찰/` | 6단계 사용 기록 | Claude, 사용자가 훑음 |
| 준비 | `준비/` | 다른 곳에서 이어서 할 메모 | Claude |
| (부록) 실행 기록 | `run-log.md` | 자동화 성공·실패 한 줄씩 | 자동 |

원천은 폴더 안 문서 하나하나이고 **README는 거기서 다시 만드는 파생물**이다 — 지금 `목록.md`·`지식목록.md`와 같은 방식이다
(상태를 따로 두지 않는다).

## 4. 책 표지(README) 모양

```markdown
---
책: 작업            # 폴더 이름
자리: vault/작업/
판: 1
쇄: 1
갱신: 2026-10-14
권수: 3             # 문서 개수
---
# 작업 — 1판 1쇄

무엇을 담나: 목적이 "작업"인 할 일 문서.
어디에 쌓이나: `vault/작업/` (완료하면 `보관/`로 옮김). 번호는 2000~2999.
누가 쓰나: 사용자가 말하면 Claude가 문서와 캘린더 일정을 만든다.

## 목차
| 번호 | 이름 | 상태 | 마감 | 만든 날 | 출처 | 한 줄 | 문서 |
|---|---|---|---|---|---|---|---|

## 이번 쇄에서 바뀐 것
- 2002 추가, 2001 완료

## 확인
- 자동 생성: 2026-10-14 (1.2쇄)
- 사용자가 훑어 확인한 날: —
```

- **본문을 싣지 않는다.** 이름·번호·상태·날짜·출처·행동 한 줄까지만(기존 목록 규칙과 같다, S4).
- **`확인` 칸이 0절 기준의 자리다.** 자동으로 만든 날짜와 사용자가 훑은 날짜를 따로 적어, "확인함"을 자동 시험 통과와 섞지 않는다.
- 표지 위 `---` 머리말이 **AI OS가 읽는 부분**이다(6절).

## 5. 판·쇄 규칙 — `n판 m쇄`, 처음은 1.1

| 올리는 때 | 판 | 쇄 |
|---|---|---|
| 책의 **구조**가 바뀐다(표지 칸, 목차 열, 묶는 기준, 폴더 범위) | +1, **쇄는 1로 되돌림** (1.3 → 2.1) | — |
| 목차 **내용**이 바뀌어 다시 만든다(문서 추가·완료·수정) | 그대로 | +1 (1.1 → 1.2) |
| 다시 만들었지만 결과가 같다 | 그대로 | **그대로** (같은 입력 같은 결과) |

- 이력은 git이 담는다. README에는 현재 판·쇄와 이번 쇄에서 바뀐 것만 둔다.
- 판을 올리는 결정은 **사용자**가 한다(구조 변경이므로). 쇄는 생성기가 올린다.
- "버전 n.1"의 `.1`을 이렇게 읽었다 — 사용자가 "n판 m쇄"로 확인(2026-10-14). 날짜 기반·단순 횟수 방식은 쓰지 않는다.

## 6. AI 운영체제와의 연결 계약

| 항목 | 값 |
|---|---|
| 방향 | AI OS → 세컨드 브레인 데이터, **읽기 전용** |
| 읽는 것 | 책 표지의 머리말 필드(`책`·`자리`·`판`·`쇄`·`갱신`·`권수`)와 루트 책 목록 |
| 읽지 않는 것 | 문서 본문, 지식 본문, 점검 보고 내용 |
| 판이 바뀌면 | AI OS가 `판` 값 비교로 알아채고 연결을 다시 확인한다. 쇄만 바뀌면 그대로 읽는다 |
| 쓰는가 | 아니오. 쓰기는 세컨드 브레인 생성기만 한다 |
| 밖으로 나가는가 | 이름·개수만이다. 남의 정보·비밀값은 기존 마스킹(`mask_sensitive`)과 비밀값 검사를 거친다 |

AI OS 쪽 설계는 [AI 운영체제 재료](../../../ai-os/README.md)에서 이어서 한다. 이 문서는 **연결 지점만** 정한다.

## 7. 요구 후보 (아직 요구가 아님 — 7단계에서 EARS로 확정)

| # | 문장 후보 | 시험 후보 |
|---|---|---|
| L1 | 데이터 폴더마다 대표 README가 있고, 무엇을·어디에 쌓는지 적는다 | 폴더 5종에서 README가 생성된다 |
| L2 | README의 목차는 폴더 안 문서에서만 다시 만들고, 본문은 싣지 않는다 | 본문 문자열이 README에 없다 |
| L3 | 내용이 바뀌면 쇄가 1 오르고, 같으면 그대로다 | 두 번 돌려 같은 결과 |
| L4 | 구조가 바뀌면 판이 오르고 쇄는 1이 된다 | 열을 바꾼 뒤 1.3 → 2.1 |
| L5 | 루트 README가 모든 책의 판·쇄를 한 장으로 보인다 | 책 수와 표의 행 수가 같다 |
| L6 | 사용자가 만든 문서는 표지 목차에서 만든 날·출처·자리와 함께 찾을 수 있고, 사용자가 훑어 확인한 날이 따로 남는다 | 입력 N건이 목차 N행으로 나오고, 확인 칸은 사용자가 쓰기 전에는 비어 있다 |

## 8. 기존 것과의 관계

- `목록.md`(할 일)·`지식목록.md`(지식)는 이 설계의 **목차 생성기가 겹치는 첫 사례**다. 7단계에서 책 표지로 합칠지,
  그대로 두고 표지가 가리키게 할지 정한다.
- 데이터 루트 `README.md`의 낡은 표는 이 설계가 구현되기 전이라도 사용자 확인 뒤 고칠 수 있다(문서 한 장).
- 판단 기준과 번호 규칙(ADR-0006), 데이터 위치(ADR-0007·0010)는 바뀌지 않는다.

## 10. 확정한 것 (사용자 결정 2026-10-14 "1~4번 제안대로 확정")

| # | 질문 | 확정 |
|---|---|---|
| 1 | 책 단위가 폴더인가, 목적(할 일+지식을 묶음)인가 | **폴더** — 원천과 1:1이라 단순하다 |
| 2 | `목록.md`·`지식목록.md`를 표지로 합치는가 | **합친다** — 같은 일을 두 번 만들지 않는다. 7단계에서 합칠 때 옛 파일은 표지로 대체 |
| 3 | 표지에 사용자가 직접 쓰는 "메모" 구역을 두는가 | **둔다.** 생성 구역 마커 밖은 덮어쓰지 않는다 |
| 4 | 부록(실행 기록)을 책으로 세는가 | **세지 않는다** — 한 파일이고 읽기용이 아니다 |

남은 열린 것은 없다. 요구 L1~L6의 EARS 확정은 7단계 시작 시점에 한다.
