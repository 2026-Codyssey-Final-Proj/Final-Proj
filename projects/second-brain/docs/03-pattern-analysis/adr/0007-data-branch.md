# ADR-0007: 데이터는 `data` 브랜치에 바로 커밋 — 병합은 코드와 규칙만

- Status: **Accepted** (2026-10-08, 사용자가 운영 세부 네 가지에 "예")
- Deciders: 사용자 (2026-10-08 "1: 가")
- Date: 2026-10-08 (초안)
- 이어지는 결정: [ADR-0004](0004-vault-location-and-layout.md)(창고 위치), [ADR-0006](0006-serial-numbers.md)(번호). 이 ADR은 **데이터가 main에 들어가는 길**만 바꾼다.

## Context and Problem Statement

할 일 하나를 처리할 때마다 문서와 기록이 PR이 되고 사용자가 병합해야 한다. 세션이 열려 있으면 이슈를 올리는 단계도 필요 없다. 사용자가 "너무 귀찮아진다"고 했다. 한편 `git-workflow.md`는 "`main`으로의 병합은 사용자가 한다"를 **다른 어떤 지침보다 우선**하는 규칙으로 둔다.

## Considered Options

1. **(가) 데이터 전용 브랜치 (채택)** — 데이터만 `data` 브랜치에 Claude가 바로 커밋·푸시. 코드·규칙은 지금처럼 PR.
2. 하루 한 번 묶어서 PR
3. 별도 데이터 저장소
4. 지금 그대로

## Decision Outcome

- `data` 브랜치는 **고아 브랜치**(main과 이력이 이어지지 않음)로, 루트에 `vault/`, `run-log.md`, `목록.md`만 둔다. main에는 이 데이터가 없다.
- Claude는 `data` 브랜치에만 바로 커밋·푸시한다. **main으로 병합하지 않으므로** 규칙의 "병합은 사용자가 한다"는 지켜진다. 규칙 문구에는 "데이터 브랜치에는 PR 없이 커밋한다"는 예외를 한 줄 더한다(사용자 확인 후).
- 쓰기 전에는 항상 사용자의 "예"를 받는다(캘린더 일정과 같은 확인 한 번으로 묶는다). 비밀값 검사를 데이터 커밋에도 건다.
- 폰에서는 GitHub 앱에서 `data` 브랜치를 골라 읽는다.

## 위험과 막는 법 (비밀값 검사가 닿아야 한다)

| 위험 | 사실 | 막는 법 |
|---|---|---|
| Claude의 비밀값 훅이 데이터 커밋을 안 본다 | `check-secrets.sh`의 훅 모드는 **세션 작업 폴더의 저장소**를 검사한다. 데이터 폴더에서 커밋하면 그 변경을 보지 않는다 | 데이터를 커밋하기 전에 데이터 폴더 안에서 `check-secrets.sh --staged`를 직접 돌리고, 통과해야 커밋한다 |
| 사용자의 git pre-commit이 데이터 폴더에서는 검사를 건너뛴다 | 지금 pre-commit은 `<저장소 최상위>/.claude/hooks/check-secrets.sh`가 없으면 건너뛴다. 고아 브랜치에는 `.claude`가 없다 | pre-commit이 못 찾으면 **주 작업 폴더의 스크립트**를 쓰게 고친다(사용자 설정이라 확인 후) |
| main에서 데이터를 빼면 이력이 갈라진다 | 기존 문서 세 장과 실행 기록이 main에 있다 | 새 브랜치로 옮기고 main에서는 지우는 PR 한 번(마지막 병합). 이력은 main에 남는다 |

## 운영 세부 (사용자 "예" 2026-10-08, 모두 적용함)

1. **작업 폴더:** `projects/second-brain/data/`에 `data` 브랜치의 작업 폴더(git worktree)를 두고, main의 `.gitignore`에 넣는다.
2. **pre-commit 수정:** 위 두 번째 줄의 고침을 사용자의 `.git/hooks/pre-commit`에 적용한다.
3. **기존 데이터 옮기기:** 문서 3장과 `run-log.md`를 `data` 브랜치로 옮기고 main에서 지운다(한 번의 PR).
4. **규칙 문구:** `git-workflow.md`에 "데이터 브랜치에는 PR 없이 커밋한다" 한 줄(사용자 확인 후, `consistency.md` 지도를 따른다).

## Consequences

- 할 일마다 병합할 일이 사라진다. 코드와 규칙은 변함없이 PR이다.
- 데이터를 보려면 브랜치를 골라야 한다(GitHub 앱의 브랜치 선택).
- 데이터가 main에서 빠져 main의 이력이 가벼워진다. 데이터 이력은 `data`에만 남는다.
- 사용자가 되돌리고 싶으면 새 ADR로 대체한다.
