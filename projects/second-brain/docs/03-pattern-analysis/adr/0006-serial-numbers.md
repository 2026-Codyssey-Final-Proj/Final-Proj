# ADR-0006: 할 일 일련번호 — 목적마다 범위, 다시 쓰지 않음, 알림 제목에는 넣지 않음

- Status: **Accepted**
- Deciders: 사용자 (2026-10-08, "알림 제목에는 넣지말자 / 번호를 다시 쓰지 않고 일련번호로 저장할것 / 위 범위 배정하자")
- Date: 2026-10-08
- 대체하는 것: [ADR-0005](0005-issue-format-and-vault-folders.md)의 **창고 폴더 모양**(`<목적>/<이름>.md`). 이슈 제목 틀과 알림 제목은 그대로다.

## Context and Problem Statement

문서에 적던 `일정: <번호>`는 구글이 붙이는 긴 무작위 문자열이라 사람이 읽을 수 없다. 사용자가 도서 분류처럼 **분류별 범위의 일련번호**를 제안했다(재료 표 2026-10-08).

## Considered Options

1. **번호 없음** — 지금 그대로. 이름으로만 부른다.
2. **분류별 범위 일련번호, 다시 쓰지 않음 (채택)**
3. **번호를 다시 쓴다** — 완료된 일을 지우고 처음부터 다시 쓴다. Claude가 반대 의견을 한 번 말했고(Q8 "지우지 않는다", 옛 기록의 번호가 새 일을 가리킴) 사용자가 2를 골랐다.

## Decision Outcome

| 칸 | 규칙 |
|---|---|
| 범위 | 생활 0~999 · 학교 1000~1999 · 작업 2000~2999 · 대회 3000~3999 · 기타 4000~4999 (5000 이후는 비움) |
| 부여 | 새 일을 처리할 때 코드(`next_number`)가 그 목적의 가장 큰 번호 + 1을 붙인다. 보관한 문서의 번호도 센다 |
| 문서 | `vault/<목적>/<번호> <이름>.md`, 문서 안에 `- 번호: N`. 완료한 일은 지우지 않고 `<목적>/보관/`으로 옮긴다(번호는 그대로) |
| 이슈 | 완료·수정은 이름과 번호 둘 다 받는다: `완료 / 학교 / 이름` 또는 `완료 / 1000`, `수정 / 학교 / 이름 / 11-05` 또는 `수정 / 1000 / 11-05` |
| 알림 제목 | 번호를 넣지 않는다(D2·D7) |
| 구글 일정 번호 | 문서의 `- 일정:` 줄에 계속 적는다. 코드는 `save_event_id`로 쓰고, 완료·수정 때 읽어 일정을 가리킨다 |
| 완료 때 일정 | 제목에 `[완료]`를 붙이고 알림을 모두 끈다, 지우지 않는다(D9) — 코드가 이 값을 돌려준다 |

## Consequences

- 번호만으로 분류를 알 수 있고, 이름이 같은 일도 번호로 구분된다. 파일이 번호순으로 정렬된다.
- **번호를 다시 쓰지 않는 것은 문서를 지우지 않는다는 전제에서 지켜진다.** 마지막 번호의 문서를 지우면 그 번호를 다시 쓸 수 있다 — 지우지 않는다는 Q8이 이 전제다.
- 한 목적이 1000개를 채우면 새 일을 거부하고 범위를 넓히라고 알린다. 사용자가 말한 "한 달 10개" 속도로는 약 8년이 걸린다.
- 처음 두 문서는 `1000 자료구조 과제 제출`, `1001 클라우드 컴퓨팅`으로 옮겼다(번호 순서는 만든 순서).
