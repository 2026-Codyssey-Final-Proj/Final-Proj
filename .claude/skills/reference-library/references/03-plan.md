# 3·4단계 — 기술 설계 (Plan)

원문: `~/proj/coding_marathon_result/코딩마라톤 가이드/3. 기술 설계/<폴더>/README.md` (폴더 9개). 태그의 `required`는 원 라이브러리에서 필수 항목,
`optional`은 선택 항목이라는 뜻이다.

## 쓰는 법

- 3단계에서 **"왜 이 스택·구조인가"에 답할 후보 비교**가 필요할 때 연다. 후보를 2~3개 고르면
  ADR의 "고려한 선택지" 칸 재료가 된다([01-docs/03-pattern-analysis/](../../../../01-docs/03-pattern-analysis/README.md)).
- 서버·포트·도메인 값은 원 라이브러리 작성자의 인프라 기준이다 — 옮기기 전에 지금 환경을 확인한다.

## 웹 스택 프리셋 (8)

| 조합 | 난이도 | 언제 고르나 | 확인할 것 |
|---|---|---|---|
| Vue.js + Node.js + MySQL | 초급 | JS 하나로 프론트·백엔드를 다 하고, 익숙한 관계형 DB가 필요할 때 | 프론트와 API 서버를 따로 배포·운영할 여력이 있나 |
| React + Next.js + Prisma | 중급 | 화면과 API를 한 프로젝트로, 타입 안전한 DB 접근을 원할 때 | 서버 렌더링이 정말 필요한가, 호스팅(Vercel 등) 제약 |
| Python FastAPI + PostgreSQL | 중급 | 백엔드가 데이터·AI 처리 중심이고 Python에 익숙할 때 | 화면은 무엇으로 만들 건가(이 조합엔 프론트가 없다) |
| Nuxt 3 + Supabase | 초급 | 서버를 직접 운영하지 않고 인증·DB를 빌려 쓸 때 | 데이터가 외부 서비스에 저장된다 — 보안 기준 3절 |
| SvelteKit + PocketBase | 중급 | 작은 개인 도구, 파일 하나짜리 백엔드로 충분할 때 | 사용자·데이터가 늘었을 때 옮길 길 |
| Django + HTMX | 중급 | JS를 최소로, 서버가 HTML을 그리는 관리형 화면 | 실시간·복잡한 상호작용이 많으면 맞지 않음 |
| Remix + Cloudflare | 고급 | 전 세계 사용자, 엣지에서 빠른 응답이 필요할 때 | 엣지 런타임에서 못 쓰는 라이브러리 |
| Astro + Content Collections | 초급 | 블로그·문서처럼 콘텐츠가 중심인 정적 사이트 | 로그인·DB 쓰기가 필요해지면 다른 조합 |

## Docker 설정 (5)

| 항목 | 설명 (원문) | 확인할 것 |
|---|---|---|
| 네트워크 타입 `required` | Docker 네트워크 타입 (bridge 강제) | 컨테이너끼리 서비스 이름으로 통신하는지, 밖으로 열 포트만 publish했는지 |
| 포트 바인딩 `required` | 포트 바인딩 형식 및 충돌 검사 | `호스트:컨테이너` 형식, 같은 호스트 포트를 쓰는 서비스가 없는지 |
| 재시작 정책 `required` | restart: unless-stopped 강제 | 서버 재부팅 뒤 자동으로 다시 뜨는지 실제로 확인 |
| 볼륨 타입 | 볼륨 타입 선택 (Named/Bind) | DB 데이터는 Named 볼륨, 설정 파일은 Bind — 백업 대상이 어디인지 |
| 리소스 제한 | CPU/Memory 리소스 제한 | 한 컨테이너가 서버 전체를 먹지 않게 상한을 두었나 |

## MariaDB 설정 (7)

| 항목 | 설명 (원문) | 확인할 것 |
|---|---|---|
| 기본 서버 `required` | Host Server MariaDB 기본 연결 정보 | 접속 정보는 `.env`로 — 코드·문서에 쓰지 않는다 |
| 문자셋 `required` | utf8mb4_unicode_ci 문자셋 강제 | 한글·이모지가 깨지지 않는지 DB·테이블·연결 세 곳 모두 |
| 사용자 생성 `required` | 사용자 생성 (localhost + 네트워크) | 앱용 계정을 따로 두고 root를 앱에서 쓰지 않는지 |
| 포트 선택 `required` | 포트 선택 (3309 이상, 3306-3308 예약) | 원 환경의 규칙이다 — 지금 서버에서 이미 쓰는 포트 확인 |
| 대체 서버 | 대체 서버 옵션 (LLM Host, NAS) | 원 환경의 서버 이름이다 — 지금 환경에 해당하는 서버가 있나 |
| 권한 수준 | 권한 수준 선택 | 앱 계정은 자기 DB에만, 필요한 권한만 |
| 접근 범위 | 접근 범위 선택 | `'user'@'%'`처럼 아무 데서나 접속 가능하게 열지 않았나 |

## Nginx/SSL 설정 (7)

| 항목 | 방법론 요약 (원문) | 확인할 것 |
|---|---|---|
| 도메인 구조 `required` | `[service-name].<도메인>` 서브도메인, CloudFlare CNAME | 실제 도메인은 문서에 쓰지 않는다(원문도 가림) |
| SSL 인증서 `required` | Let's Encrypt, `--expand`로 통합, certbot 자동 갱신 | 인증서는 90일 — 자동 갱신이 실제로 도는지 `certbot renew --dry-run` |
| 라우팅 대상 `required` | 외부 443 → 내부 서비스 포트로 프록시 | 내부 포트가 바깥에 직접 열려 있지 않은지(방화벽과 같이 봄) |
| 기본 프록시 설정 `required` | 모든 서브도메인에 같은 헤더·버퍼·타임아웃 | 실제 클라이언트 IP 헤더(`X-Forwarded-For`)가 앱까지 오는지 |
| 서브도메인 계층 | 서비스 유형·환경별 네이밍 규칙 | dev/staging/prod 구분 규칙을 정했나 |
| WebSocket 지원 | HTTP/1.1 Upgrade 헤더 | 실시간 기능이 있을 때만 |
| 보안 헤더 | HSTS, X-Frame-Options 등 OWASP 권장 헤더 | 보안 기준 6-4(OWASP) — 6단계 점검 항목 |

## Ollama AI 통합 (7)

| 항목 | 설명 (원문) | 확인할 것 |
|---|---|---|
| 직접 연결 방식 `required` | Ollama API 직접 연결 (프록시 금지 정책) | 원 환경의 정책이다 — 지금 구조에서도 맞는지 |
| CORS 설정 `required` | OLLAMA_ORIGINS, OLLAMA_HOST | 허용 출처를 `*`로 열지 않았나 |
| 서버 선택 `required` | VM/HOST/LLM Host | 원 환경의 서버 이름 — 지금 환경으로 바꿔 읽는다 |
| 모델 선택 `required` | 서버별 사용 가능한 모델 목록 | 모델 크기가 서버 메모리에 맞는지 |
| API 엔드포인트 | 스트리밍/단순 응답 | 화면에 글자가 흘러나와야 하면 스트리밍 |
| 에러 처리 | 재시도, 폴백, 타임아웃 | 보안 기준 6-1 — 재시도 상한, 실패를 알리기 |
| 성능 최적화 | 연결 풀링, 캐싱, 부하 분산 | 측정 먼저(6단계), 최적화는 그다음 |

## 포트관리 (4) · 포트포워딩 (3)

| 항목 | 설명 (원문) | 확인할 것 |
|---|---|---|
| 프로젝트 포트 할당 `required` | Frontend/Backend 포트 제안 | 프로젝트마다 쓰는 포트를 한 표(포트 지도)에 적었나 |
| 포트 충돌 검사 `required` | devops-port-map.md 기반 | 원 환경의 파일 — 우리 쪽에도 포트 지도가 있나 |
| 포트 범위 정책 `required` | 시스템 예약 포트(1-1023) 사용 금지 | 일반 서비스는 1024 이상 |
| 서비스 그룹 선택 | 그룹별 포트 범위 자동 할당 | 그룹(웹/DB/AI)마다 범위를 정하면 충돌이 줄어든다 |
| 기존 포트포워딩 `required` | 기존 필수 규칙 (IPTIME) | 공유기 관리 화면은 외부에서 열리지 않게 |
| 프로토콜 지정 `required` | TCP/UDP/Both | 필요한 것만 — Both는 이유가 있을 때 |
| 추가 포트포워딩 | 프로젝트별 추가 | 열 때마다 방화벽 규칙과 같이 기록 — [04-tasks.md](04-tasks.md) |
