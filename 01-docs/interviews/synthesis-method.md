# 여러 사람의 말을 묶어 보는 법 — 가설 밖의 말 · 사용 테스트의 끝 질문

| | |
|---|---|
| 쓰는 때 | 응답자 요약(`respondent-X.md`)이 둘 이상 모였을 때, 사용 테스트(11/4 ~ 7)의 끝 질문 · 관찰을 모을 때 |
| 이 문서가 정하지 않는 것 | 가설 판정은 [결과 → 결정](results-to-decisions.md) 1절, 사용 테스트 판정은 [검증 계획](../06-service/02-verification-plan.md) 4절, 요약의 틀은 [README](README.md) "요약 틀"이 정한다 — 여기서는 **그 표에 들어가지 않는 말**을 묶는 법만 |
| 출처 | [anthropics/knowledge-work-plugins](https://github.com/anthropics/knowledge-work-plugins) `product-management/skills/synthesize-research` · `design/skills/research-synthesis`, 커밋 `33d3dea41a341b341d4f5da2e8801ae0c89be2b8`, [Apache 2.0](https://www.apache.org/licenses/LICENSE-2.0) — 고르고 우리 말로 바꿨다 |

이 문서는 스킬이 아니다. 플러그인은 설치하지 않았고, 우리 문서(질문지 · 요약 틀 · 판정 기준)와 다르면 **우리 문서가 이긴다.**

## 1. 한 사람의 요약에 붙일 표시

요약 틀은 그대로 두고, "들은 것" · "그 밖에 나온 것"의 줄 끝에 짧은 표시만 붙인다.

| 표시 | 뜻 | 왜 |
|---|---|---|
| `[한 일]` / `[말]` | 실제로 한 일인가, "하고 싶다 · 있으면 좋겠다"는 말인가 | 한 일이 더 강한 근거다. 가설 판정은 이미 한 일만 센다([질문지](questionnaire.md) 4절) — 그 밖의 말에도 같은 눈으로 표시한다 |
| `[돌아감]` | 문제를 피해 가는 자기만의 방법(다른 도구, 메모장, 사람에게 묻기, 처음부터 다시) | 채워지지 않은 필요가 숨어 있는 자리다 |
| `[세기: …]` | 감정 말(답답 · 포기) · 얼마나 자주 · 돌아가는 데 든 수고 · 안 됐을 때의 결과 중 들린 것 | 같은 말이라도 얼마나 중요한지가 다르다 |

## 2. 여러 사람을 묶기 — 비슷한 것끼리

1. **관찰 하나 = 쪽지 하나.** `A-3`처럼 응답자 기호와 번호를 붙인다. 한 쪽지에 생각 둘을 넣지 않는다.
2. **묶음 이름을 미리 정하지 않는다.** 비슷한 쪽지를 모은 뒤에 이름을 붙인다 — 가설 이름(H1 ~ H5)을 묶음 이름으로 쓰지 않는다. 가설은 이미 따로 판정한다.
3. 너무 커진 묶음은 둘로 나눈다. **어디에도 맞지 않는 쪽지는 억지로 넣지 않고 '따로'에 둔다** — 놀라운 발견이 거기서 나온다.
4. 묶음마다 적는다: 이름, 무슨 뜻인지 한두 문장, **말한 사람 수**(예: 5명 중 3명), 대표 말 하나(응답자 기호로), `[한 일]` · `[말]`이 몇 개씩인지, 들린 세기.
5. 묶음은 다섯에서 여덟 개 — 약한 묶음 스물보다 강한 묶음 다섯이 낫다.

모은 묶음은 `summary.md`(README 표) 끝에 "가설 밖에서 나온 묶음" 절로 두는 것을 제안한다 — 정하는 사람은 담당(고한결).

## 3. 엇갈림 · 놀라움

- 두 사람이 반대로 말하면 **배경(S1 · S2)이 다른지** 본다. 다르면 대상이 갈린다는 신호다(H5와 닿는다). 같으면 둘 다 적고 다음 사람에게서 확인한다.
- 질문지에 없던 이야기는 다른 사람에게 묻지 않았으므로 그 사람들은 **'모름'이다 — 0명으로 세지 않는다.**

## 4. 세 재료를 맞대기

| 재료 | 알려 주는 것 | 우리 쪽 자리 |
|---|---|---|
| 인터뷰 | 왜 그런지, 무엇이 문제라고 느끼는지(말) | `respondent-X.md` · `summary.md` |
| 사용 테스트 | 실제로 어디서 멈추고 무엇을 했나(한 일) | 검증 계획 7절의 사람별 기록 · 녹화 |
| 앱 기록 | 몇 단계까지 · 얼마나 자주(숫자) | 판정 · 관문 기록, 토큰 장부 |

- 셋이 같은 쪽을 가리키면 강한 발견이다.
- 엇갈리면 **하나를 고르지 않고 엇갈림을 그대로 적는다.** 그다음 볼 것: 잰 사람이 다른가(인터뷰 응답자와 테스트 참여자), 말과 한 일이 다른가, 질문이 우리가 생각한 것을 물었나.

## 5. 사용 테스트에서 나온 문제의 순서 — 고칠 목록에 넣기 전

[고칠 목록](../07-maintenance/fix-map.md)에 올릴 문제가 여럿이면 아래 네 칸을 채워 순서를 제안한다. 정하는 사람은 담당이다.

| 칸 | 값 |
|---|---|
| 겪은 사람 | 5명 중 몇 명 |
| 얼마나 막혔나 | 1 지나감 · 2 도움을 받고 지나감 · 3 멈춤 |
| 얼마나 자주 | 한 번 · 단계마다 |
| 근거 | 본 것(녹화 · 화면) / 들은 것(끝 질문의 말) |

겪은 사람 × 막힘이 큰 것부터, 같으면 자주 나온 것부터. **근거가 들은 것뿐이면 한 칸 뒤로** 둔다.

## 6. 하지 않는 것

- 결론을 먼저 정하고 말을 맞추지 않는다. 판정 기준은 시험 전에 정한 것을 따른다(결과 → 결정 1절, 검증 계획 1-2).
- 두 사람의 말은 결론이 아니라 가설이다 — 묶음에는 사람 수를 늘 같이 적는다.
- 이름 · 연락처 · 알아볼 수 있는 사연은 적지 않는다(README "레포에 올리지 않는 것").
- 원본에서 가져오지 않은 것: 커넥터로 Slack · Notion 등에서 자료 끌어오기(우리는 쓰지 않는 서비스), 페르소나 만들기 · 시장 크기 추정(5명 인터뷰에는 맞지 않는다), 설문 통계.

## 다시 가져오는 법

원본 두 파일을 위 커밋과 비교해(`gh api repos/anthropics/knowledge-work-plugins/compare/<커밋>...main`) 바뀐 것만 본다.
1 ~ 5절에 닿는 변경만 반영하고, 우리 질문지 · 요약 틀 · 판정 기준과 겹치는 것은 들이지 않는다. 이 문서 머리의 커밋을 고친다.
