## 3. 할 일 — 차례

| 묶음 | 고칠 것 | 끝 조건 |
|---|---|---|
| ⓐ 막힘을 말하기 | F-69 | `provider.js` `startTask`가 결과의 `permission_denials` **도구 이름 · 개수**와 `is_error`를 넘긴다(도구 입력은 넘기지 않음). 서버의 일 상태에 '막힘'(거절 1번 이상) — 화면은 '끝남' 대신 "허락을 못 받아 N번 막혔어요(파일 쓰기 · 명령)" + 다시 맡기기. 맡기기 전에 그 폴더에 허락 훅이 있는지 보고, 없으면 맡기지 않고 까닭 한 줄("이 폴더는 허락 카드가 안 떠요 — 다시 연결"). 다시 켤 때 훅 경로를 새로 적는다. 허락 카드는 섬이 접혀 있어도(알약 포함) 보이게. 시험: 가짜 claude(`NAV_CLAUDE_BIN`)가 거절 목록을 내면 화면이 막힘을 말한다 · 훅 없는 폴더면 맡기지 않는다 |
| ⓑ 뼈대 맡기기 | F-70 | 5단계 퀘스트에 '뼈대 맡기기' — 단계 문서(기획서 · 요구 · 설계)로 맡길 글을 짓고, 끝 조건은 "README에 실행 명령 한 줄" · "예시 입력으로 처음부터 끝까지 돈다" · "기획서에 적힌 결과물이 생긴다(경로를 보고)". 같은 길로 — `server.js` `startTask` + 끝 조건 + 섬 허락 + 보고. 문서에 없는 숫자 · 이름은 지어내지 않고 빈칸으로 묻는다 |
| ⓒ 하나씩 만들기 | F-70 | 6단계에서 3단계 요구 줄마다 '이 줄 맡기기' — 끝 조건은 그 줄의 확인 방법(Given-When-Then). 끝나면 보고와 바뀐 파일(작업실 파일 칸 다시 읽기) |
| ⓓ 돌려서 결과물 보기 | F-70 | 6 · 7단계에 '돌려 보기' — Claude Code가 실행 명령을 돌리고 결과 파일 경로 · 첫 줄을 보고한다(명령 실행은 섬 허락). 결과 파일은 작업실 파일 칸에서 연다(C-43 규칙 그대로). 6단계 관문은 코드 파일 0개면 닫힘(C-56 R-3 '먼저'와 같은 규칙 — 먼저 만드는 쪽이 만들고 다른 쪽은 쓴다) |

## 5. 꼭 지킬 것

- **사람 대신 허용하지 않는다** — `--dangerously-skip-permissions` · `--permission-mode` 건너뛰기 · 저절로 allow를 내는 훅을 쓰지 않는다(요구서 FR-17, [security-records.md](../../../.claude/rules/security-records.md) 6-3). 막혔다고 말하는 데까지만.
- 결과 JSON에서 읽는 것은 도구 이름 · 개수 · 토큰 · 보고만 — 도구 입력 · 답 글은 저장하거나 보이지 않는다. 훅은 이름 · 첫 줄 · 줄 수만(`steps.js`).
- `claude` 실행 · AI 호출은 `provider.js` 한 곳.
- 시험은 새 임시 폴더에서. 진짜 Claude Code로 볼 때는 기본 설정처럼(`--setting-sources project,local`) · 작은 모델로 — 만드는 사람 컴퓨터의 권한 설정에 기대지 않는다.
- 연습 모드(서버 없이)는 예시로 돈다(FR-10).
- 커밋마다 `python3 04-tests/run_all_tests.py` 전체가 통과해야 한다 — 코드를 바꾸면 그 코드를 글로 맞대는 시험도 같은 커밋에서.
- Claude는 `main`에 올리지 않는다. 변경 기록 조각은 `changes/output-path.md`, 쓴 곳에 `claude-drafted`.
