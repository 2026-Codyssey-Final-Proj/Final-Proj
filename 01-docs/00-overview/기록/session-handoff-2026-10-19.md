<!-- claude-drafted: 2026-10-19 — 이재엽 요청 "병합하다가 고치지 못하는 곳들은 어떻게 할지 생각해봐". 오늘 실제로 만난 충돌 4종에서 뽑았다. 규칙 파일(git-workflow.md · session-operations.md)은 고치지 않았다 — 받으면 그때 옮긴다. -->

오늘(10/19) 만난 충돌은 모양이 넷이었다. 모양마다 하는 일이 다르다.

| 유형 | 오늘의 예 | 하는 일 | 누가 정하나 |
|---|---|---|---|
| **가. 줄 번호 · 기록 줄** | CHANGELOG 맨 위 한 줄, fix-map F-번호 — PR 넷이 동시에 v4.0을 골랐다 | 두 줄 다 남기고, **나중에 병합하는 쪽이** 다음 번호로 고친다(이미 규칙). 기계적이라 Claude가 바로 푼다 | 규칙대로 |
| **나. 같은 문제를 두 PR이 다르게 풂** | #113 "옛 서버를 알아보고 끄기" vs #115 "늘 빈 포트에 자기 서버" | 하나를 고르고 다른 쪽은 **뺀 이유를 병합 커밋 · PR · CHANGELOG에 적는다**. 고르기 어렵거나 사람이 쓴 코드면 멈추고 묻는다 | 기능 담당(모르면 이재엽) |
| **다. 브랜치가 너무 오래돼 파일 여러 개가 엇갈림** | A — 지우기 작업 뒤 PR 8개가 같은 파일을 고쳐 7곳 충돌 | **병합하지 않는다.** 최신 `main`에서 새 브랜치를 따 원래 커밋을 목록으로 **다시 적용**한다. 원래 브랜치는 `ref/…`로 남긴다 | Claude가 하고 PR로 알림 |
| **라. 뜻을 모르는 남의 변경과 부딪침** | (오늘은 없었다) | 고치지 않는다. 고칠 목록에 한 줄(F-번호, "병합 충돌 — 담당 확인")을 남기고 PR 본문에서 담당을 부른다. 그 PR은 열어 둔다 | 담당 |

**하지 않는 것:** `--force`, 남의 변경을 말없이 지우기, 충돌을 피하려고 시험 · 훅을 끄기, `main`에 직접 올리기(Claude).

**예방 — 제안, 결정 전:**

1. **가 유형이 PR마다 생긴다.** 원인은 "CHANGELOG 맨 위에 한 줄" 규칙 자체다 — 동시에 열린 PR은 반드시 같은 줄을 고친다. 대안: PR마다 `changes/<브랜치>.md` 조각 파일을 두고, 병합되면 Action이 맨 위 버전 다음 번호를 붙여 CHANGELOG에 합친다(조각 파일끼리는 부딪치지 않는다). 버전을 "올린 사람이 고른다"(git-workflow.md)에서 "병합될 때 정해진다"로 바꾸는 일이라 이재엽이 정한다. Jira 릴리스 Action(`jira-release.js`)이 CHANGELOG 맨 위 줄을 읽으므로 같이 고쳐야 한다.
2. **다 유형은 브랜치가 하루를 넘기면 생긴다.** 10/19에는 반나절 사이에 PR 8개(#113~#120)가 병합됐다. 큰 지우기 · 옮기기는 브랜치를 따자마자 끝내고 바로 PR, 미뤄지면 이 문서처럼 `ref/`로 남기고 다시 적용.

## 5. 함정 — 오늘 실제로 걸린 것

- **앱이 옛 화면을 보이면** 먼저 `lsof -nP -iTCP:4317 -sTCP:LISTEN`. 앱 4.0부터는 자기 서버를 켜지만, 브라우저로 `http://127.0.0.1:4317`을 열면 그 포트의 아무 서버나 본다.
- **시연 길잡이 띠는 없다**(v2.1). 장면은 주소 끝(`#ex=1&done&gate` 등)으로 연다 — [3분 시연 스토리](../../04-pattern-implementation/demo-story-3min.md).
- **프롬프트 · 판정 규칙을 고치면 녹화를 다시 해야 시연 재생이 된다**(`record-demo.js --again`). 녹화본은 요청이 글자까지 같을 때만 재생된다.
- 커밋 작성자 이메일: 이 컴퓨터의 git 설정은 실제 메일이다. Claude는 커밋마다 `-c user.email=<GitHub noreply>`로 올렸다.
- Jira 키가 PR 제목에 없으면 GitHub for Jira · 릴리스 Action이 이슈에 잇지 못한다(jira.md 2절). 오늘 PR들은 키가 없었다.
