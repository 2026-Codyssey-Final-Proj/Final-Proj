## 4. 만들 것 — 스토리보드 웹페이지 한 장

1. **첫 화면** — 이 페이지가 보여 주는 것(Floe가 0~8단계를 어떻게 잇나, 예시 test-1), 읽는 법(범례: 사람 · 플로로(섬) · Claude Code · Floe 작업실), test-1 링크와 디자인 캔버스 링크.
2. **단계 길** — 0~8 칩을 위에 붙여 따라오게 하고, 누르면 그 장면으로 간다.
3. **장면마다(0~8)**:
   - ① 화면 그림: 작업실 캔버스 + 가장자리 섬. 그 단계의 카드 · 섬 대화 · '지금 하는 일' 줄을 보인다.
   - ② 다섯 칸 표: 누가 · 무엇을 · 화면에서 · 남는 파일.
   - ③ test-1에 남은 것: GitHub 파일 · 커밋 링크.
   - ④ "test-1에서 본 틈 → 이렇게 이어져야" 상자.
   - ⑤ 관문과 다음 장으로 넘기는 재료.
4. **장면 사이의 이어짐 띠** — 3절 '장 사이에 넘어가는 것'.
5. **맨 아래** — 2절 화면 기준 표, 열린 질문.
6. (선택) 장면 하나를 눌러 보는 작은 프로토: 섬 자리 바꾸기 · 섬 크기 · 캔버스 다시 배치(2절 7번)를 보여 주는 곳.

- **글:** 쉬운 말(C-33 초등학생 말). 지어낸 숫자 없이 test-1의 실제 문장만. 예시가 필요하면 `[예시]` 표시.
- **모양:** 작업실 파스텔 + 섬 네이비, 휴대폰 폭에서도 읽힘, 어두운 모드, 대비 4.5:1, 누르는 곳 44px.
- **어디에 [제안]:**
  - claude.ai 아티팩트로 올린다. 팀원이 보려면 이재엽이 Share로 링크를 열어 줘야 한다.
  - 레포 사본은 `01-docs/04-pattern-implementation/stage-storyboard/`(`index.html` · `README.md`)에 둔다. 웹사이트 초안(PR #168)과 같은 방식이고, 사본에는 doctype · charset 머리를 붙인다.

## 5. 꼭 지킬 것 · 함정

- 앱 코드를 고치지 않는다. test-1에 쓰지 않는다. 앱 버전은 그대로 둔다.
- 마우스 따라오기를 다시 넣지 않는다. 섬은 '끌어서 어디든'이 아니라 가장자리 넷이다.
- 미션 원문(코디세이 미션 글)은 앞 두세 문장만 옮기고 출처를 적는다 [해석].
- 다른 사람의 정보 · 비밀값이 없는지 본다(test-1은 공개 저장소이지만 내용은 이재엽의 것).
- 첫 5분 장면(S0~S8)과 숫자가 겹친다 — 0단계는 그 장면 번호를 가리키고 다시 지어내지 않는다.
- 정해야 할 것은 버튼(AskUserQuestion)으로 하나씩 묻는다:
  - ① 단계 숫자 표기(0 = 시작, 1~8)
  - ② 틈을 팀원이 보는 페이지에 그대로 보일지
  - ③ fix-map에 줄을 더할지
  - ④ 캔버스 다시 배치의 너비 경계
- 만들기 전에 페이지 구성(장면 목록 · 한 장면의 칸)을 먼저 보여 주고 확인받는다.
