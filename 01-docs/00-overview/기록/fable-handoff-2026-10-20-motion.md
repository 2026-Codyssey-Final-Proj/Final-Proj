# 넘김 — 움직임의 기준점과 랙 (F-45 · F-46)

> **기록 문서.** 2026-10-20 `main` 4ea3207 기준이다. 고칠 목록은 [fix-map.md](../../07-maintenance/fix-map.md) **F-45**(자리가 튐) · **F-46**(랙).
> 원인은 **코드를 읽어 찾았다(재현 전)**. `[제안]`은 Claude가 정한 기본값이라 바꿔도 된다.

## 0. 먼저

1. 이름 확인(CLAUDE.md "처음 세션이면") → 이 문서.
2. **이 문서와 F-45 · F-46 줄을 담은 PR이 병합된 뒤** 최신 `main`에서 브랜치를 딴다. 안 그러면 고칠 목록 줄이 부딪친다. 열린 PR #148이 F-41~44를 쓰고 있다.
3. **F-46은 재는 것부터.** 아래 2절의 의심 넷은 코드만 보고 고른 것이다. 앱에서 개발자 도구 Performance로 녹화해 빨간 프레임이 어디서 나는지 보고, 그 숫자로 고칠 순서를 정한다.
4. 앱 버전은 올리지 않는다. 팀이 "버전업"이라고 할 때만 올린다.

## 1. 정하신 것 — 원문

- 알림: "지금 전반적으로 에니메이션 위치가 이상하거든 기준을 잡아야하는 문제인거 같아 그리고 애니메이션에서 랙이 많이걸리면 어떻게 수정하면 좋을까?"
- 버튼(어떻게 진행할까): **"페이블 넘김 문서로"**. 기준 세 줄(아래 3절)은 Claude의 제안을 본 뒤 고른 것이다. 숫자는 페이블 세션에서 앱을 보며 조정해도 된다.

## 2. 찾은 것

### F-45 — 자리가 튄다: 기준점이 둘

| # | 무엇 | 어디 |
|---|---|---|
| 1 | **창은 가운데를 붙들고, 섬은 창의 왼쪽 위에 붙어 있다.** 그래서 창이 넓어지면 섬이 화면에서 늘어난 폭의 절반만큼 왼쪽으로 밀린다. 노치 Mac은 노치 가운데를 붙드니 같은 문제가 있다 | [lib.js](../../../02-frontend/electron/lib.js) `islandX` · [app.css](../../../02-frontend/navigator/app.css) `.in-app .nav{left:0;…}` |
| 2 | **섬의 움직임이 창보다 먼저 시작된다.** [morph.js](../../../02-frontend/navigator/morph.js) `plan`은 "커질 때는 창을 먼저 키운다(resize-then-animate)"라고 하지만, [app.js](../../../02-frontend/navigator/app.js) `morphFrom`은 그 자리에서 움직임을 시작하고 창 크기는 다음 프레임에 `queueSize` → `floe:resize`로 바뀐다. 움직이는 도중에 창이 옮겨져 한 번 튄다 | `morphFrom` · `measureSize` |
| 3 | **가운데 맞춤과 움직임이 같은 `transform`을 쓴다.** 키프레임마다 `translate(-50%…)`를 다시 적어야 하고, 빠지면 반 칸 튄다. `.pop-say`는 이미 `translate` 속성을 따로 써서 이 문제가 없다 — 이것을 본으로 삼는다 | `app.css` `.fx` · `@keyframes fly`, [library.css](../../../02-frontend/library/library.css) `say-pop` · `spin` |
| 4 | 시간 · 곡선이 제각각이다 — 길이 30가지 넘게, 곡선 15가지 안팎 | CSS 8개 파일 · `dive.js` · `library.js` |

### F-46 — 랙: 의심 넷 (영향이 클 것 같은 순서, 잰 것 아님)

이미 고친 것: 앱 안에서는 유리 흐림(`backdrop-filter`, F-24)과 굴절(`REFRACT`)을 끈다.

| # | 무엇 | 어디 |
|---|---|---|
| 1 | **작업 알림이 올 때마다 섬 전체를 `innerHTML`로 새로 그린다.** 숨쉬기 같은 무한 움직임이 처음부터 다시 시작되고, 크기 재기(강제 배치 계산)와 창 크기 IPC가 따라온다. AI가 일할 때 알림이 몰리면 쌓인다 | `app.js` `render` → `renderDesk` (`poll` → `onEvent`) |
| 2 | **배치를 바꾸는 속성을 움직인다** — 경험치 막대 `width`, 카운트다운 `@keyframes shrink`의 `width`, 인사의 `clip-path` | `app.css` `.lvc .xp i` · `.cd i` · `html.greeting .isl.greet` |
| 3 | **물범 그림 안 부품의 무한 움직임**(꼬리 · 몸 · 숨쉬기 · zz · 물방울). SVG 안의 요소는 따로 합성되지 않아 매 프레임 다시 그리고, 투명 창이라 창 전체를 다시 합친다 | [seal.css](../../../02-frontend/navigator/seal.css) 52~82줄 안팎 |
| 4 | 움직이는 도중의 창 크기 바꾸기 — F-45 2번과 같은 뿌리 | `morphFrom` · `measureSize` |

## 3. 기준 [제안 — 이재엽 버튼으로 진행]

| 기준 | 내용 |
|---|---|
| **기준점 하나 — 섬의 위 가운데** | 창도 섬도 이 점을 붙든다. 앱 안에서도 섬을 창 가운데에 두면(`left:50%` + `translate:-50% 0`) 창이 가운데를 붙든 채 커지고 줄어도 섬은 제자리에 있다. 예외는 설정 창이 옆에 열릴 때(anchor `"left"`) 하나뿐이다 |
| **자리와 움직임을 나눈다** | 자리는 `left` · `top` · `translate`, 움직임은 `transform` · `opacity`만 쓴다. `width` · `height` · `clip-path` · `top`을 움직이지 않는다 |
| **시간 · 곡선은 묶음에서 고른다** | 짧게 0.16초 / 보통 0.24~0.3초 / 큰 전환 0.4초. 곡선은 셋 — 들어옴(스프링), 나감, 기본. `morph.js`의 `MS` · `EASE`를 CSS 변수(`--t-*` · `--ease-*`)로 넓혀 CSS와 JS가 같은 값을 읽는다 |

## 4. 할 일

1. **F-46 재기** — 앱(Electron)에서 개발자 도구 → Performance 3초 녹화. 상황은 ① 가만히 있을 때 ② 펼침 ↔ 접힘 ③ 작업 알림이 몰릴 때(작업 장면 보기). Rendering 탭의 "Paint flashing"도 켠다. 프레임 16.7ms(60fps)를 넘는 곳과 그 까닭(Layout · Paint · Script)을 fix-map F-46 줄에 적는다.
2. **F-45** — 3절 기준점으로 맞춘다. 커질 때 창을 먼저 키우고 그다음 움직이게 `morph.js` `plan`의 순서를 실제로 지킨다.
3. **F-46** — 1의 숫자에서 큰 것부터 고친다. 2절 2번은 `transform: scaleX`(`transform-origin: left`)로 바꾼다. 3번은 섬이 접혀 있거나 창이 안 보일 때 `animation-play-state: paused`로 멈추는 것을 먼저 본다.
4. 시간 · 곡선 묶음은 새로 만들거나 고치는 움직임부터 쓴다. 한 번에 다 바꾸지 않는다 — 바꾼 움직임마다 앱에서 눈으로 본다.

## 5. 꼭 지킬 것 · 함정

- **움직이는 동안 창 크기를 바꾸지 않는다.** F-24(버벅임)와 F-38(빠르게 펼쳤다 접으면 창이 먼저 줄어듦)에서 고친 `morphHold` 흐름을 깨지 않는다.
- **노치 Mac은 노치 가운데가 기준점이다.** 3절의 위 가운데와 같은 점이니 새로 갈라지지 않게 한다.
- F-40의 "가로는 넓히지 않는다"(말풍선 때문에 창 가로를 바꾸면 한 줄이 밀린다)는 1번 문제의 증상이다. 기준점을 맞추면 이 제약이 풀리는지 보고, 풀려도 F-40 시험은 그대로 통과해야 한다.
- '움직임 줄이기'(`prefers-reduced-motion`)는 파일마다 따로 막고 있다. 새 움직임도 같은 규칙을 따른다.
- `seal.css`의 `transform-origin` 숫자(px)는 SVG 좌표다. 그림 크기와 무관하니 크기를 바꿔도 고치지 않는다.
