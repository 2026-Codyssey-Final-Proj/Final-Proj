## 3. 판단 규칙의 동작

| 점 | 코드에서 본 것 | 평가 |
|---|---|---|
| 근거 | 요청문이 "작업 내용에 적힌 것만 근거, 지어내지 않는다"를 요구 | 좋다. 다만 **프롬프트로만** 막는다 |
| **근거 구절 검증** | `parseJudgement`는 `evidence`를 문자열로 받기만 한다. **입력 글에 실제로 있는 구절인지 확인하지 않는다.** met=true인데 evidence가 비어도 통과한다 | **막힘(판정 규칙으로 쓰려면)** — 지어낸 근거로 "충족"이 표시될 수 있다 |
| 단계 선택 | AI가 0~7 중 단계를 고른다. 앞 단계 DoD가 안 채워져도 뒤 단계를 고를 수 있다 | **보완** — "가장 앞의 미충족 단계"를 코드로 계산하는 편이 게이트 규칙과 맞다 |
| 넘어가기 | `canAdvance`: 할 일이 모두 met이고 사용자가 "예"를 눌러야 함 | 좋다. 사람의 확정이 있다(FR-4). 다만 met을 AI가 정하므로 위 근거 검증이 먼저다 |
| 모양 확인 | 응답 JSON을 스키마와 `parse*`로 확인하고 모양이 틀리면 null("살펴보지 못함") | 좋다. 틀리면 지어내지 않고 정직하게 실패한다 |
| 할 일 문장 | AI가 준 것을 쓰지 않고 `STAGES`의 우리 문장으로 덮음 | 좋다. 기준 문장이 흔들리지 않는다 |
| 설계도 | AI는 초안과 방향만, 확정은 사람 버튼 | 좋다(FR-3) |
| 쉬운 말 | `JARGON` 목록을 화면 문구에서 테스트로 검사 | 좋다(FR-13). 목록에 없는 용어는 못 잡는다 |
| 반복 상한·Hold | 없음 | FR-5의 "아니요 N회 뒤 Hold"는 아직 규칙이 없다(11절의 미정과 같다) |

## 4. 판정 제안 (이재엽이 정한다)

| 항목 | 제안 |
|---|---|
| **그대로 #7 확정본으로** | **아니오.** 단계 표 29개 중 3·5단계와 보안 점검이 비어 있다 |
| **#7의 출발점으로** | **예.** 쉬운 말로 줄이는 틀, 응답 검증 구조, 사람이 확정하는 흐름은 가져갈 만하다 |
| 먼저 고칠 것 | ① `evidence`가 입력 글에 있는 구절인지 코드로 확인, met=true인데 근거가 비면 false ② 단계는 "가장 앞의 미충족 단계"를 코드로 계산 ③ 3·5단계 빠진 항목과 보안 점검 한 줄씩 추가 ④ 등급(Full/Xpress/Lite)에 따라 5단계 항목을 나눔 |

**시연 안전장치 점검표** (각 항목은 위반 시도 시험을 먼저 쓴다)

| # | 항목 | 확인 방법 |
|---|---|---|
| S1 | 시연용 가상 프로젝트(예: "동아리 행사 등록 앱")의 **새 세션만** 연결한다. 개인 작업 세션에는 훅을 달지 않는다 | 시연 전 `connect.js` 미리보기로 대상 폴더 확인 |

| S3 | 이벤트 주소에 **확인 값(토큰)** 이 있다 — 토큰 없는 `/api/events`·`/api/event`는 거절한다 | 토큰 없이 부르면 거절되는 시험 |
| S4 | 받은 알림 글도 화면에 보이기 전에 **민감 패턴 검사**를 거친다(보내기 전 검사와 같은 규칙) | 키·전화번호 모양 글이 카드에 그대로 안 나오는 시험 |
| S5 | 시연이 끝나면 **기록을 비운다**(서버 재시작 또는 지우기 버튼) | 비운 뒤 `/api/events`가 비어 있는지 |
| S6 | 시연 전 **한 줄 점검**: "실제 모드 / 시연 프로젝트만 연결 / 토큰 있음 / 개인 세션 닫음" | 시연 전 사람이 한 번 읽고 체크 |

| Xpress·Lite의 5단계 대신 확인(동등분할·경계값 + 차등 테스트, gates.md 5단계) | Full이 아닌 등급에만 있는 할 일을 넣으면 "Full = 할 일 전부"가 깨져, 등급 없이 `STAGES`를 쓰는 지금 화면과 개수가 어긋난다. 화면이 `criteriaFor`를 쓰게 된 뒤에 넣을 수 있다 |
| 등급별로 단계 건너뛰기(Lite 2~6 생략, Xpress 2 Skip) | 할 일이 아니라 단계 진행 규칙이다. 지금은 모든 등급이 0~7단계를 다 밟는다 |
| 즉시 처리 | 밟을 단계가 없어 등급 목록에 넣지 않았다. 서버에 보내면 "모르는 등급"으로 거절한다 |

**이재엽이 확인할 것** — ① 7단계 '왜?' 다섯 번을 Xpress에도 둘지(scope-tiers.md는 Full 칸에만 적었고, gates.md DoD는 밟는 단계에 그대로 적용한다 — Xpress에도 둔 쪽으로 읽었다) ② 3단계 기록(ADR)을 Xpress에도 둘지(scope-tiers.md의 Xpress 3단계는 "카탈로그 검색") ③ Lite의 1단계를 두 개(한 문장 한 가지 일, 보안 줄)로 둘지 ④ 위 "넣지 않은 것" ⑤ 4·5단계에 같은 비밀값 문장을 둔 것.
