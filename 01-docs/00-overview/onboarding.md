# Floe 처음 쓰기 — 받아서 첫 바퀴까지

**누구를 위한 글:** 앱을 처음 받은 사람(사용자 테스터 · 팀원). 설치 없이 보려는 심사위원은 맨 아래 "설치 없이 3분"으로.
**기준:** 앱 9.0.0 (PR #157, 2026-10-20). 화면이 이 글과 다르면 [팀 작업 가이드](team-guide.md)가 더 최신이다.

## 0. Floe가 뭔가요

AI로 프로그램을 만드는 사람 옆에 떠서 **지금 몇 단계인지, 다음에 무엇을 할지** 알려 주는 길잡이다.
화면 위쪽 가운데에 떠 있는 작은 창(섬)과 물범 **플로로**가 안내한다. 코딩 도구는 지금 쓰는 것(Claude Code) 그대로 쓴다.

## 첫 5분 — 무엇을 경험하게 할까 [제안 · 확정 전]

<!-- claude-drafted: 2026-10-20 — 두승현의 질문("게임 기획에서는 초기 5분이 핵심 … Floe에서 초기 5분안에 어떤 경험을 줘야")에 Claude가 답한 것을 두승현의 요청으로 옮겼다. 같은 날 두승현의 흐름 제안(플로로 자기소개 → 한 줄 적기 → 그다음 연결), 보완 ①② · 코드 검토 · 비슷한 서비스 조사를 더했다("지금까지 논의한 내용 모두"). 제품 흐름을 바꾸는 일이라 방향은 이재엽이 정한다. -->

게임 기획에서 첫 5분은 "무엇을 하고 싶은지 · 무엇이 가능한지 · 어떤 가치가 있는지"를 설득하는 시간이다.
게임 용어로 **FTUE**(First-Time User Experience, 처음 쓰는 사람의 경험) 안의 **아하 모먼트**(가치를 처음 깨닫는 순간)를 앞에 두는 것이다.
Floe의 첫 5분은 **설정이 아니라, 내 프로젝트에서 지금 어디쯤이고 다음에 뭘 하면 되는지 처음 알게 되는 순간**이어야 한다 — Floe가 풀려는 문제(H1 "어디까지 왔고 다음에 뭘 할지 몰라 멈춘다", [인터뷰 가설](../interviews/questionnaire.md))와 같은 자리다.

**지금(앱 9.0.0) — 이 글 1~3절의 순서**

| 분 | 하는 일 | 유저가 느끼는 것 |
|---|---|---|
| 0~2 | 받기 · 설치, 경고 넘기기 | 귀찮음 |
| 2~4 | 처음 설정 — Claude Code 연결 / API 키 | "뭘 고르라는 거지?" |
| 4~5 | 프로젝트 폴더 연결 | 아직 아무 가치도 못 봄 |

5분이 지나도록 준비만 하고 Floe가 무엇을 해 주는지는 아직 못 본다. 게임으로 치면 튜토리얼 전에 설정 메뉴만 5분 만지는 셈이다.

**제안 — 가치 먼저, 설정은 필요한 순간에** (두승현, 2026-10-20)

사용자가 먼저 **자기가 풀고 싶은 문제를 적게 하고**, Floe가 그 해결의 길을 잡아 준다는 인상과 가치를 준 다음에 번거로운 설정을 한다.
이미 내 아이디어를 써 넣은 사람은 "이어 가려면 연결이 필요해요"를 들어도, 빈손으로 설정 화면을 만날 때보다 덜 떠난다.

| 순서 | 플로로 / 화면 | 설득하는 것 |
|---|---|---|
| 1 | 플로로가 **자기소개** — "저는 길잡이 물범 플로로예요. 지금 어떤 앱을 만들고 있어요? 알려 주면 길을 잡아 주고 정리해 줄게요" | "나를 도와주러 왔구나" |
| 2 | **"처음 시작해요 / 이미 만드는 중이에요"** 두 단추 → 만드는 앱을 한 줄로 적는다 | 내 문제를 꺼내 놓는다 — 이미 시간을 들였다 |
| 3 | **작은 답 먼저**(보완 ①) — 적은 글을 그대로 인용해 되짚고, "처음 시작해요"면 **"지금 0단계예요. 첫 할 일은 '어떤 불편을 풀지 한 문장으로 쓰기'예요"**. 그리고 연결하면 받는 것을 미리 보인다 — "연결하면 지금 몇 단계인지, 다음 할 일 하나를 알려 줄게요" | 핵심 가치 — 멈춘 자리에서 다음 한 걸음이 보인다 |
| 4 | 그제서야 **"이 내용을 이어 가려면 Claude 연결이 필요해요"** → 처음 설정(Claude Code / API 키). 부담스러우면 "AI 없이 연습용 예시로 둘러보기" | 번거로운 일은 가치를 본 뒤에 |
| 5 | 연결이 끝나면 **적어 둔 글로 바로 이어서**(보완 ②) — "적어 둔 내용으로 어디쯤인지 볼까요?" 단추 하나. 다시 적게 하지 않는다 | 믿음 — 내 글이 사라지지 않았다 |
| 6 | 할 일 하나를 끝내면 "이해하셨나요?" → **EXP가 오르고** 플로로가 기뻐한다 | 게임 같은 보상 — 레벨 오버레이(LV · EXP)가 이미 있다 |
| 7 | "오늘 한 게 책 한 장으로 남았어요. 다음에 켜면 여기서 이어져요" | 다시 올 이유 — 배운 게 쌓인다(H4) |

**보완책이 실제로 되는가 — 코드 검토 (2026-10-20, `main` 앱 9.0.0, 코드를 읽어서 판단 — 실행해 보지는 않았다)**

| 보완 | 되는가 | 근거 |
|---|---|---|
| ① 적은 글을 **요약해** 되짚기 ("행사 신청 받는 앱이군요!") | **AI 없이는 어렵다** | 글을 이해해 줄이는 건 AI의 일 — 연결 전에는 부르지 못한다 |
| ① 적은 글을 **그대로 인용해** 되짚기 | 된다 | 받은 글을 다시 보이기만 한다 |
| ① "지금 0단계 · 첫 할 일" 보이기 | **된다 — 가장 효과가 크다** | 0단계와 그 할 일 넷은 코드에 고정된 데이터(`03-backend/navigator/navigator.js`의 `STAGES[0]`). 새로 시작하는 사람은 늘 0단계라 AI 없이도 맞는 말이다. 이미 만드는 중인 사람에게는 틀린 말이라 2번의 두 단추로 먼저 가른다 |
| ② 적은 글이 연결 뒤에도 남기 | **이미 된다** | 적은 글(`st.text`)은 이 컴퓨터에 남는 목록에 있다(`02-frontend/navigator/app.js`의 `KEEP`) |
| ② 연결 뒤 바로 이어 가기 | **하나만 더하면 된다** | 처음 설정이 끝나면 `floe:setup-done` 신호가 이미 온다(`app.js`). 그때 적은 글이 있으면 "어디쯤인지 볼까요?" 단추를 띄운다. 자동으로 AI를 부르지는 않는다 — 부를 때마다 토큰이 들어 한 번 눌러 동의받는다 |
| 순서 자체 (설정을 뒤로) | **가장 큰 변경** | 지금은 처음 켜면 처음 설정이 먼저 뜬다(`02-frontend/navigator/setup.js`의 `shouldOpen`). 설정이 뜨는 때를 바꾸는 것이 핵심이다 |
| 연결이 부담스러운 사람의 길 | 이미 있다 | 처음 설정의 "AI 없이 연습용 예시로 둘러보기" 단추 |

바꿀 곳은 셋 — 설정이 뜨는 때, 두 단추와 0단계 보이기, 연결 뒤 "어디쯤인지 볼까요?" 단추.

**참고한 서비스 — 비슷한 서비스는 어떻게 온보딩하나 (2026-10-20 웹 조사)**

출처 대부분은 제3자 UX 블로그다(공식 문서 아님) — 실제 순서는 지금과 다를 수 있다.

| 서비스 | 성격 | 첫 화면에서 하게 하는 것 | 가입 · 설정은 언제 | Floe와의 관련 |
|---|---|---|---|---|
| Duolingo | 게임형 학습 + 마스코트 | 첫 수업 — 켜고 네 번쯤 누르면 시작한다는 리뷰 | **첫 수업 뒤.** 진행을 저장할 이유가 생길 때 계정을 권한다. 계정이 꼭 필요한 건 순위표 같은 부가 기능 | 가장 가까운 본보기(게임 · 마스코트 · 배움) |
| Lovable | 바이브 코딩 | 한 리뷰: 홈 화면 입력창에 바로 적고 가입 전에 결과를 본다 | 역할 · 팀 규모 질문은 결과를 본 뒤 | 다른 리뷰(2026년 6월)는 빌드 전 4단계 질문 — 리뷰어가 "바로 만들려는 사람에게 마찰"이라 지적. **두 리뷰가 다르다** |
| Replit Agent | 바이브 코딩 | "만들고 싶은 걸 설명하세요" 입력창 하나 | — | 계획 모드(코드 안 고치고 구상)와 만들기 모드가 나뉜다 — Floe 단계 안내와 비슷한 생각 |
| Mimo · Codecademy Go | 코딩 학습 | 누구인지 → 경험 → 목표 | Codecademy Go는 답을 다 넣은 뒤 "맞는 과정을 보려면 가입" | **답을 넣은 뒤에 문을 연다** — 이 제안과 같은 방식 |
| Cursor | AI 코딩 편집기 | 로그인 · VS Code 설정 가져오기부터(리뷰마다 순서 다름) | 먼저 | 이미 쓰기로 정한 개발자용 — 비개발자 대상 Floe와는 맞지 않는다 |
| CouCou (Floe가 참고한 앱) | 노치에 사는 코딩 도우미 | 마스코트 Mochi가 튀어나와 손을 흔들고 눈으로 커서를 따라간다 | 온보딩 순서 자료는 찾지 못했다 | 마스코트의 첫인사만 확인 |

공통 패턴 셋 — ① **가치 먼저, 가입 · 설정은 나중에**(Duolingo, Lovable 한 리뷰) ② **목표 질문 하나로 시작**(Replit, Mimo, Codecademy Go) ③ **답을 넣은 뒤에 문을 연다**(Codecademy Go, Duolingo).
반대 사례는 설정을 먼저 묻는 Cursor, Lovable의 위저드, 초반에 알림 권한부터 묻는 Tolan — 리뷰어들이 마찰로 지적했다. 이 제안은 ①②③을 모두 따른다.
Floe만의 숙제: 앱이라 설치는 피할 수 없다 — **설치 전에 맛보기**는 아래 "설치 없이 3분"의 연습 예시가 맡을 수 있다.
"가치를 먼저 본 사람이 가입률이 2~3배"라는 숫자도 나왔지만 출처 없는 개인 게시물이라 근거로 쓰지 않았다.

## 1. 받기 · 설치 (5분)

[GitHub Releases](https://github.com/2026-Codyssey-Final-Proj/Final-Proj/releases)의 **`app-v9.0.0`** 에서 내 컴퓨터에 맞는 파일 하나를 받는다. 비공개 저장소라 팀원 권한이 있어야 받을 수 있다.

| 컴퓨터 | 받을 파일 | 처음 열 때 |
|---|---|---|
| Windows | `Floe-Setup-9.0.0.exe` | "PC 보호" 경고가 뜨면 **추가 정보 → 실행** |
| Mac (M칩) | `Floe-9.0.0-arm64.dmg` | Floe를 '응용 프로그램'으로 끌어 놓고 연다. 막히면 **시스템 설정 → 개인정보 보호 및 보안 → 그래도 열기** |
| 우분투 | `Floe-9.0.0-x86_64.AppImage` 또는 `-amd64.deb` | AppImage는 파일 속성에서 "실행 허용" 뒤 더블클릭 |

- 옛 버전이 켜져 있으면 **먼저 끈다.** 켜진 채로 새 것을 열면 옛 화면이 나온다.

## 2. 처음 켜기 — 플로로와 처음 설정

처음 켜면 플로로가 반기고, AI를 어떻게 부를지 **둘 중 하나**를 같이 준비한다.

| 고르기 | 이럴 때 | 알아 둘 것 |
|---|---|---|
| **Claude Code로 연결** | 이 컴퓨터에 Claude Code가 깔려 있고 로그인돼 있다 | 내 Claude 구독 사용량을 쓴다 |
| **API 키 넣기** | 받은 API 키가 있다(코디세이 가상 키 포함) | 키는 앱의 설정 폴더에만 저장된다. 채팅 · 스크린샷에 붙이지 않는다 |

나중에 바꾸려면 톱니(설정) → **처음 설정 다시 하기**.

## 3. 내 프로젝트 폴더 연결

- **Mac:** 위 메뉴 **Floe → 프로젝트 폴더 연결…**
- **Windows · 우분투:** 섬을 **우클릭**하거나 알림 영역(트레이)의 Floe 아이콘 → 같은 메뉴

연결한 뒤 **그 폴더에서 Claude Code를 새로 열면**, 작업이 끝날 때마다 플로로가 "어디쯤인지 볼까요?"라고 묻는다.
이 컴퓨터에 Node가 있어야 한다. 진짜 AI로 보면 최근 작업 대화가 Claude로 가므로, 비밀번호나 다른 사람 연락처가 든 프로젝트에는 붙이지 않는다.

## 4. 첫 바퀴

1. 켜면 **기본 화면** — 플로로와 지금 한 줄, 단추 넷: **바이브 코딩 · 서재 · 알림 · AI 진행**(숫자 1~4로도 누른다).
2. **바이브 코딩**을 누르면 이번 단계와 할 일이 보인다. 할 일을 하나씩 끝낸다.
3. 다 했으면 **넘어가기 전 확인** — 그림을 보고 "이해하셨나요?"에 답한다. "아니요"면 헷갈린 곳을 같이 짚고 다시 묻는다.
4. 위쪽 맨 왼쪽 **집** 단추로 기본 화면에 돌아온다.
5. **플로로에게 먹이 주기** — 글 파일(`.md` · `.txt`)을 섬에 끌어다 놓거나 글을 붙여 넣으면, 플로로가 구간으로 나눠 보여 준다. '맞아요'를 누른 것만 내 책에 들어간다. 비밀값 · 개인적인 일은 자동으로 빠진다.
6. **서재** — 끝낸 프로젝트가 책으로 꽂힌다. 책장은 내가 만든다('분류 안 함' 하나에서 시작).

## 5. 느낀 점 남기기 (사용자 테스트라면 꼭)

톱니 → **느낀 점** → 한 줄 적기. 어느 화면 · 몇 단계 · 언제인지는 저절로 붙는다. **Jira용 복사**로 팀 Jira에 붙인다.

## 6. 막히면

| 보이는 것 | 해결 |
|---|---|
| 앱이 안 열린다 | Windows는 "추가 정보 → 실행", Mac은 "그래도 열기" (1절) |
| 옛 화면이 나온다 | 켜진 Floe를 모두 끄고 다시 연다 |
| `claude 명령을 찾지 못함` | Claude Code를 설치 · 로그인하거나, 처음 설정에서 API 키를 넣는다 |
| `API 키가 맞지 않아요 (401)` | 키가 잘렸거나, 가상 키인데 주소를 안 넣었다 |
| `요청이 받아들여지지 않았어요 (400/404)` | 모델 이름이 그 서버에 없다 — 받은 안내의 모델 이름으로 |
| 그 밖 | 화면의 오류 문구를 팀 채널이나 Jira에 붙인다. **키는 지우고** |

더 많은 경우는 [팀 작업 가이드 5절](team-guide.md).
