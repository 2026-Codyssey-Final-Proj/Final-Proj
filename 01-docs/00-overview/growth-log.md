# 성장 로그

> **팀 레포의 빈 구조.** V1(이재엽 개인 워크스페이스)의 기록은 개인 기록이라 옮기지 않았다. 규칙·표 틀만 가져왔고 기록은 이 레포에서 새로 쌓는다. 개인별 지적을 한 파일에 섞지 않으려면 이 표에는 *유형과 횟수*만 적고 사람 이름은 적지 않는다.

리뷰에서 나온 지적과 잘한 점을 **유형별로** 쌓아, 무엇이 늘었고 무엇이 아직 기억에
기대고 있는지 보는 곳입니다. 규칙은 [`.claude/rules/review-mode.md`](../../.claude/rules/review-mode.md),
기록 절차는 [`dev-workflow` 명령 5](../../.claude/skills/dev-workflow/PROCEDURE.md)에
있습니다.

[worklog.md](worklog.md)가 "시스템이 왜 이 모양이 됐는가"라면, 이 문서는 "내가 어떻게
늘고 있는가"입니다. 성장은 양쪽에서 기록합니다 — 내 작업에서 나온 지적과, **리뷰어(Claude)가
질문·리뷰를 잘못한 것**(맨 아래 "리뷰어 개선 기록").

## 운영 규칙

- **유형**은 아래 "유형 요약" 표의 이름을 재사용한다. 맞는 게 없을 때만 새 유형을
  만든다(비슷한 유형이 여러 개로 쪼개지면 반복이 안 보인다).
- **승격**: 같은 유형의 "막힘/보완"이 **3회** 쌓이면
  [`catalog/checklist.md`](../catalog/checklist.md)에 체크리스트 항목으로 올리고,
  상태를 `체크리스트 승격`으로 바꾼다. 이미 체크리스트에 있는 항목을 계속 놓치면
  항목 문구가 확인 가능한 형태인지 다시 본다.
- **익힘**: 그 유형이 적용될 수 있었던 리뷰에서 **연속 3회** 지적이 없고 "잘한 점"이
  1회 이상 있으면 `익힘`으로 바꾼다. 다시 나오면 `관찰`로 되돌린다(지우지 않는다).
- **판정 차이**: 게이트 리뷰에서 자기 판정과 리뷰 판정이 다르면 기록한다.
- **대신 써 달라고 한 영역**: `claude-drafted` 주석이 붙은 부분은 따로 센다 — 자주
  맡기는 영역이 다음에 연습할 곳이다.
- 마지막으로 리뷰한 커밋을 아래 "리뷰 기준점"에 남긴다. 세션 시작 훅이 이 값 이후의
  커밋을 "리뷰받지 않은 커밋"으로 알려준다.

## 리뷰어 개선 기록 (Claude 쪽)

Claude가 [질문하는 법](../../.claude/rules/review-mode.md)을 어기거나 리뷰를 잘못한 것을
남긴다 — 사용자가 지적했거나 Claude가 스스로 알아챈 것. **Claude는 리뷰를 시작하기 전에
이 표를 먼저 읽는다.** 같은 실수가 2회 나오면 `review-mode.md`의 규칙 문구를 고친다(사람
쪽 3회보다 기준이 낮다 — 규칙 문구는 Claude가 매번 다시 읽는 것이라 고치는 비용이 작다).

| 날짜 | 무엇을 잘못했나 | 어긴 규칙 | 조치 | 출처 |
|---|---|---|---|---|
| 2026-10-18 | 사용자가 확정한 섹션 셋(2-9~2-11)의 상태 줄을 고치지 않고 다음으로 감 → 확인 단계(개수 검사)에서 걸림. 그사이 명령을 `;`로 이어 내용 없는 커밋이 메시지만 앞서 올라감 | 질문하는 법 12번(받은 답을 기록한 뒤 다음으로) | 다음 커밋에서 채우고 메시지에 바로잡음. 여러 단계 명령은 `set -e`로 멈추게 함 | Claude가 알아챔 |
