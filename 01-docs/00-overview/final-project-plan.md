## 기획 의도

### 배경
- AI 코딩 도구 덕분에 누구나 말로 서비스를 만들 수 있게 됐다(바이브 코딩).
- 하지만 **'코드를 생성하는 것'** 과 **'프로젝트를 완성하고 회고하며 개발 실력을 키우는 것'** 은 다른 문제다.

### 문제
- 사용자는 AI가 만든 결과가 맞는지, 지금 어느 단계이고 다음에 무엇을 해야 하는지 판단하지 못해 개발이 중도에 멈춘다.
- 끝까지 만들어도 내 코드를 설명하지 못하고, 배운 것이 다음 프로젝트로 이어지지 않아 실력 향상이 체감되기 어렵다.
- 이 문제가 학생 말고 다른 바이브 코더(기획자·직장인·창작자)에게도 같은 모양인지는 인터뷰로 확인한다 — 아래 "검증 계획".

### 목표
- 결과를 대신 만들어 주는 AI가 아니라, 사용자가 작업 과정을 이해하고 **스스로 결정**하도록 길을 안내하는 **'AI 내비게이터'**.
- "AI가 일하는 시대에도, 성장하는 건 사람이어야 한다."

## 누구를 위한 서비스인가

| 사용자 | 어떤 때 쓰나 | 비고 |
|---|---|---|
| AI로 코딩을 배우는 학습자 | 과제·프로젝트를 AI와 만들다 막힐 때 | **첫 검증 대상**(원안 그대로) |
| 코딩은 모르지만 AI로 서비스를 만들어 보는 기획자·디자이너 | 지금 단계와 내가 만든 것을 이해하고 싶을 때 | 원안 그대로 |
| 업무·개인 프로젝트로 바이브 코딩을 하는 직장인·창작자 | 여러 프로젝트와 일정 사이에서 개발을 이어 갈 때 | 인터뷰로 확인 전 가설 |

대상은 모두 **AI로 프로그램을 만드는 사람**이다. 보고서·과제 같은 비개발 작업은 범위 밖이다.

## 핵심 기능

### ① 길 안내 — "지금 어디까지 왔고, 다음에 뭘 해야 하나요?"
- 사용자가 UI에 작업 내용을 넣으면 Claude가 **우리 워크 프로세스**(7단계에 코딩마라톤 루틴을 합친 것)로 작동해, **지금 몇 단계인지**와 **이번 단계에서 어디까지 해야 하는지**(완료 기준)를 알려 준다.
- 설계도(명세·계획·설계서)는 **Claude가 초안을 만들고**, 사용자가 고치거나 쓰면 Claude가 **다시 리뷰하고 안내**한다. 사람이 승인한 것만 확정이다.
- 다음 할 일은 4단계 흐름으로 안내한다: **무엇을(What) → 왜(Why) → 결정(Decision) → 실행(Action)**
  - 무엇을: 다음에 할 일을 추천한다
  - 왜: 그 일이 지금 필요한 이유를 설명한다
  - 결정: 정하기 전에 정해야 할 것을 선택지별 장단점과 함께 보여 주고, **결정은 사용자가 내린다**
  - 실행: 결정한 내용을 정리해 사용자가 쓰는 AI 코딩 도구(Cursor, Claude Code 등)로 넘겨 준다
- 예: 행사 등록은 누가 하나요? A 모든 회원 / B 운영진만 / C 신청 후 승인

### ② 이해 확인 — "이 게이트에서 이렇게 작업했는데, 이해하셨나요?"
- 게이트가 끝나면 그 단계의 작업을 **다이어그램으로 보여 주고** "이해하셨나요?"를 묻고 **예 / 아니요**를 받는다.
- **아니요**라면: 어느 부분을 모르는지 확인 → 사용자의 질문을 받아 답함 → 그 게이트의 작업 내용을 **요약한 계획서**를 확인할 수 있다.
- **"예"가 나올 때까지** 이해를 돕고, 그 전에는 다음 단계로 가지 않는다.
- 게이트가 끝나면 **다음 할 일들을 정리해 우선순위를 정할 수 있게** 한다(순서는 사용자가 정한다).

### ③ 성장 기록 — "이번 프로젝트로 무엇을 배웠나요?"
- 프로젝트가 남으면 지식 창고에 기록이 쌓여 **역량이 무엇인지, 어떤 노력을 해 왔는지** 보인다.
- 배운 것은 4단계 레벨(처음 봄 → 이해함 → 직접 씀 → 응용함)로 기록하고, 쌓인 기록은 **'역량 지도'** 로 시각화된다. AI는 이를 기억해 다음 프로젝트에서 조언한다.
- 예: "지난번엔 권한 설계를 나중에 바꿔서 고생했어요. 이번엔 먼저 정해 볼까요?"

### ④ 한곳에서 보기 — "내 작업과 일정이 지금 어떤가요?"
- 진행 상황, 내가 할 일, 다른 프로젝트·일정과의 충돌, Claude 토큰 사용을 **한 화면**에서 본다.
- Claude에서 작업한 내용이 알림으로 기록되어, 끝난 일이 끝났다고 표시된다.
- 대회 시연에서는 **가상 숫자와 미리 만든 응답**으로 보여 주고, 서버·도메인을 열지 않는다.

## 기술 구성
- AI 에이전트 + 장기 기억(Long-term Memory) + 문서 검색(RAG)
- 개인 프로젝트에서 만들어 2건에 적용해 본 7단계 개발 방법론(5~6단계까지 적용, 7단계 완주 전)에 코딩마라톤 루틴을 합쳐 쉬운 말로 바꿔 적용 — **원안의 "8건으로 검증"은 근거를 찾지 못해 고쳤다. 사실 확인 필요**
- [제안] 장기 기억·성장 기록의 저장 방식은 이재엽의 세컨드 브레인(기록을 쌓고 마감·일정으로 되돌려 주는 개인 지식 창고)에서 가져온다 — 아래 "기존 작업과의 연결"

## 검증 계획
- 개발 전: 예비 사용자 3~5명 인터뷰로 문제가 실제로 있는지 확인. **[제안] 코딩 학습자만이 아니라 AI를 쓰는 다른 유형(학생·직장인·창작자)을 최소 1명씩 넣어, 대상 확장이 맞는지 본다.**
- 개발 후: 5명 이상 사용 테스트로 사용 전후 변화를 비교한다.
- 수치(완주율, 설명 성공률 등)는 인터뷰 뒤에 정한다 — 지금은 **미정**이다. 지어내지 않는다.

## 기대효과 및 활용방안

### 기대효과
- **끝까지 완성하는 경험:** 지금 어느 단계인지, 다음에 무엇을 해야 하는지 항상 보여서 막막함 때문에 중간에 멈추는 일이 줄어든다.
- **스스로 결정하는 힘:** 만들기 전에 선택지와 이유를 비교하며 직접 결정한다. AI가 제안하는 대로 따라가는 대신, 내가 방향을 정하고 AI를 도구로 쓰는 사람이 된다.
- **설명할 수 있는 결과물:** 결정할 때마다 이유가 기록되고 이해 확인을 거치므로, "왜 이렇게 만들었나요?"라는 질문에 1분 안에 답할 수 있도록 준비된다.
- **쌓이는 실력:** 작업을 할수록 역량 지도가 넓어지고, 지난 작업의 실수와 배움이 다음 작업의 조언으로 돌아온다.
- **내 것으로 남는 기록:** 결정 기록과 역량 지도는 특정 AI 도구에 묶이지 않고 사용자가 소유한다. 도구가 바뀌어도 성장 기록은 그대로 이어진다.

### 활용방안
- 교육 현장: 부트캠프·코딩 수업에서 수강생의 완주와 이해도를 확인하는 도구, 강사용 수강생별 역량 현황판.
- 취업 준비: 역량 지도와 노력 기록, 게이트 요약 계획서를 포트폴리오 자료로 활용.
- 협업 소통: 기획자가 개발 과정을 쉽게 이해해 개발자와 원활하게 소통.
- 학교·직장: 과제·업무 프로그램을 AI로 만든 과정을 설명할 수 있는 기록으로 활용.
- 장기 비전: 나에게 맞춰 돕는 '개인 지식 저장소'로 발전.

- 사람이 승인한 것만 확정한다. AI의 초안에는 표시를 남긴다(`claude-drafted`).
- "외부 AI는 한 모듈에서만 부른다" 같은 규칙은 기억이 아니라 린트·테스트로 강제한다.
- 검증 기록에는 **고친 결함**과 **하지 못한 것**도 적는다.

## 기존 작업과의 연결 — 이재엽의 세컨드 브레인 [제안]

팀장이 개인 프로젝트로 만들어 온 **세컨드 브레인**(지식 창고: 할 일 문서 정리, 마감 알림, 기록 순환)은 이 기획의 ③ 성장 기록·장기 기억과 같은 문제를 푼다.

- **그대로 가져가는 것:** 코드와 규칙, 설계 결정 기록(ADR), 그리고 "넣기 → 요약 → 창고에 쌓기" 흐름.
- **일반화하는 것:** "학교생활 동안 쓰는 개인 지식 창고" → "바이브 코딩하는 사람의 프로젝트·결정·배움 창고". 학교는 여러 *목적* 중 하나가 된다(생활·학교·작업·대회·기타 중 '학교').
- **가져가지 않는 것:** 개인 데이터(할 일 문서, 실행 기록, 캘린더 연결, 계정 정보). 이 레포는 협업자 전원이 읽기 때문이다(비공개).
- 어디까지 이 레포로 옮길지는 팀장이 따로 정한다 — 다음 단계.
