## Context and Problem Statement

대회 시연은 서버·도메인 없이 가상 데이터와 미리 만든 응답으로 한다(FR-10, 확정). 평가는 "기존 AI API를 그대로 쓴 수준을 넘어"(기획 20점)와 "결과물의 실행 가능성"(기술 10점)을 본다. 시연을 **미리 만든 응답만**으로 할지, **실제 Claude 호출 한 경로**를 넣을지가 정해지지 않았다. 멘토링(10/17)에서 물을 질문이기도 하다(schedule.md S5).

이미 있는 것: `implementations/navigator-demo/index.html` — 서버 없는 단일 HTML, 네트워크 호출을 시험으로 막음.

## Considered Options

1. **미리 만든 응답만** — 단일 HTML, 모든 응답은 고정 데이터. 코딩마라톤의 "키 없이 도는 fixture 모드"와 같다.
2. **미리 만든 응답 + 실제 Claude 호출 한 경로** — 기본은 1과 같고, 한 장면(예: 설계도 초안)만 실제로 호출한다. 키는 환경변수, 레포에 없다.
3. **서버를 두고 API 연동** — 화면이 서버를 거쳐 Claude를 부른다.

## Decision Outcome (제안)

**Claude 제안: 1을 기본으로 하고, 멘토링(10/17)의 답에 따라 2를 한 경로만 더한다.**

| 이유 | 근거 |
|---|---|
| 시연이 어떤 환경에서도 열려야 한다 | FR-10, 현재 시험 5개가 네트워크 호출을 막고 있음 |
| 2는 "API 그대로 쓴 수준"에 대한 직접 증거가 된다 | 평가 기획 20점, 다만 시연 중 호출 실패 위험이 따른다 |
| 3은 일정(11/1 동결)과 보안(키·개인 데이터) 부담이 크다 | schedule.md, 기록·보안 기준 |

## Consequences

- 1이면: 화면과 시험은 지금 그대로 쓸 수 있다. "AI 적용"은 판정 규칙(ADR-0003)과 문서로 보인다.
- 2이면: 호출 모듈이 하나여야 한다(ADR-0003), 실패 시 미리 만든 응답으로 되돌아가는 길이 필요하다, 시연 영상에는 실제 호출임을 표시한다.
- 어느 쪽이든 시연이 가상 데이터임은 화면에 표시한다.
