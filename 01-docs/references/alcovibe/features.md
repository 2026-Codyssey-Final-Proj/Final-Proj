> **출처: 이재엽의 개인 프로젝트 "Alcovibe" 파일.** 팀 기준이 아니라 소개 자료다. 개인 프로젝트 소개: [README.md](README.md)

## 한 문장

일의 시작에서 문제를 같은 틀로 저장하고, 단계마다 게이트로 확인하며, 끝의 회고를 다음 일의 재료로 쌓는 **개인 작업 환경**이다.
작업물은 사람이 쓰고 Claude는 되묻고 리뷰한다.

## 기능 목록

| # | 기능 | 하는 일 | 팀 저장소에서의 상태 |
|---|---|---|---|
| 1 | 7단계 워크플로우와 규모 등급 | 문제 저장 → 분석 → 패턴 → 구현 → 서비스 → 유지보수. 규모(Full/Xpress/Lite/즉시)로 밟는 단계를 정한다 | **이미 있음**(`01-docs/00-overview/scope-tiers.md`) |
| 2 | 게이트 리뷰 | 단계 사이에 DoR/DoD를 확인, 자기 판정을 먼저 받고 Claude 판정을 본다 | **이미 있음**(`gates.md`) |
| 3 | 리뷰 모드 | 사람이 쓰고 Claude는 막힘/보완/잘한 점으로 리뷰한다. 대신 쓸 때는 표시를 남긴다 | **이미 있음**(`review-mode.md`) |
| 4 | 성장 기록 | 리뷰 지적을 유형별로 쌓아 반복되면 체크리스트로 올린다 | **이미 있음**(빈 구조) |
| 5 | 후보 장부와 참고 자료 받기 | 참고 자료를 받아 → 문서화 → 비교 → 반영, 후보 상태는 한 곳에만 | **이미 있음**(`01-docs/catalog/`) |
| 6 | 요구 접수 | 새 요구를 원문 그대로 접수 → 분류 → 확인 → 원천 한 곳에 확정 → 파생 갱신 | **이미 있음**(세컨드 브레인 `requirement-intake.md`) |
| 7 | 보안 기록 기준 | 비밀값은 환경변수만, 밖으로 나가는 것을 표로, 단계마다 보안 점검 | **이미 있음**(`security-records.md`) |
| 8 | 훅 — 위험한 git, 병합된 브랜치 푸시, 테스트 실패 커밋, 비밀값, 링크·Mermaid·스킬 명세 | 잊어도 기계적으로 막거나 알린다 | **이미 있음**(7개) |
| 9 | **훅 — 캘린더 소유자 확인** | 소유자 표시가 없는 컴퓨터에서는 일정 쓰기를 막는다(기본이 막힘) | **이번에 가져옴** |
| 10 | **훅 — 캘린더 초대 확인** | 참석자를 넣으려 하면 확인을 요구한다 | **이번에 가져옴** |
| 11 | **훅 — 세션 시작 브리핑** | 마감·진행 중인 일·다음 할 일을 먼저 말한다 | **이번에 가져옴** |
| 12 | **스킬 9개** — 테스트 먼저(`tdd`), 보안 점검(`owasp-security`), 화면 점검(`impeccable-review`), 움직임·마감 리뷰(Emil 스킬 6개) | 반복 작업을 스킬로 묶음 | **이번에 가져옴**(출처·라이선스는 `VENDORED.md`) |
| 13 | **기능 계획서** | 유즈케이스별 계획, 접수된 요구를 기능 단위로 묶은 계획 | **이번에 가져옴** |
| 14 | **레프런스 창고** | 화면 테마·스타일 가이드·이미지 시안을 한곳에 | **이번에 만듦**([창고 안내](../README.md)) |
| 15 | 세션 운영 | 주제 하나·브랜치 하나·작업 폴더 하나, 상태는 원천 파일에만 | **이미 있음**(`session-operations.md`) |

## 이번에 가져오지 않은 기능 (개인 환경에만)

| 기능 | 이유 |
|---|---|
| 공유 준비 절차(내 데이터를 비우고 각자 로컬에서 쓰게) | 개인 저장소를 건네는 절차라 팀 저장소와 맞지 않다. 팀은 개인 데이터를 처음부터 두지 않는다 |
| 반출 규칙(올릴 때 개인 이야기 빼기) | 개인 환경의 반출 점검표 — 팀에는 같은 취지의 공유 점검(`team-sharing-security.md`)이 있다 |
| 개인 우선순위·접수 색인 | 개인 기록 |
| AI 운영체제(ai-os), qa-prep-system 폴더 | 팀 V2 결정("지금은 `second-brain` 하나") — 필요하면 팀이 따로 정한다 |

## 팀 기준과 다른 점 (맞춤 필요)

| 항목 | 개인 환경 | 팀 기준 |
|---|---|---|
| 병합 | 사람이 병합 | 사람은 `main`에 직접 푸시, Claude는 `main`에 올리지 않음 — **팀 기준을 따른다** |
| 결정하는 사람 | 한 사람 | `TEAM.md` 역할 + 팀 합의 |
| ADR 번호 | 개인 프로젝트 번호 체계 | 팀 번호 체계(0002~)가 유효 |
| 이름 | Alcovibe(개인 환경) | Project Navigator(팀 제품) |
