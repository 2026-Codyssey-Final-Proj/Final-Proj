# 서고 전환 프레임 — 고치기 전 · 뒤 (F-35, 2026-10-20)

**무엇을 쟀나.** 화면을 파일로 열어(서버 · AI 없음) 섬의 도서관 탭에서 '내 서고 들어가기' → 서고 → '← 작업 화면으로' → 섬까지 한 바퀴를 3번. 페이지마다 머리에서 `requestAnimationFrame` 간격과
`PerformanceObserver({ type: "long-animation-frame" })`를 재고, 떠날 때 `sessionStorage`에 남겼다. 잰 도구: 헤드리스 Chrome(puppeteer) 1440×900, CPU 6배 느리게(`emulateCPUThrottling(6)`) — 느리게 하지 않으면 고치기 전에도 50ms 넘는 프레임이 0이라 차이가 보이지 않는다.

| 구간 | 고치기 전 (3번 중 최악) | 고친 뒤 (3번 중 최악) |
|---|---|---|
| 나가기(섬 — 물이 커지고 플로로가 내려감) | 50ms 넘는 프레임 0 · 가장 긴 33ms · LoAF 1(52ms) | 50ms 넘는 프레임 0 · 가장 긴 33ms · LoAF 1(53ms) |
| 들어오기(서고 — 첫 그림부터 물이 빠지고 층이 떠오름) | 50ms 넘는 프레임 1 · 가장 긴 100ms · LoAF 1(100ms) | 50ms 넘는 프레임 1 · 가장 긴 117ms · LoAF 1(112ms) |
| 나오기(서고 — 물이 차오름) | 0 · 17ms · LoAF 0 | 0 · 17ms · LoAF 0 |
| 떠오름(섬 — 물이 빠지고 섬이 내려앉음) | 50ms 넘는 프레임 1 · 가장 긴 117ms · LoAF 1(134ms) | 50ms 넘는 프레임 1 · 가장 긴 117ms · LoAF 1(135ms) |

**읽는 법.** 움직이는 동안의 프레임은 고치기 전에도 뒤에도 헤드리스 Chrome에서는 끊기지 않는다. 남은 긴 프레임 하나는 **새 페이지의 첫 그림**(스크립트를 읽고 처음 그리는 때)이고, 이것은 넘김 문서 5절의 ②③(페이지 넘김 · 창 크기)에 속한다 — 이번 "가볍게, 그리기만"의 범위 밖이다.
즉 이번에 고친 넷(물의 `clip-path` → 둥근 판의 `transform`, 서고 층의 `filter: blur` 제거, 물방울 22 → 12, 시간 대신 움직임이 끝나면 넘기기, 새 페이지 첫 그림부터 물방울)은 **헤드리스 Chrome에서는 수치로 드러나지 않는다.** 무거운 그리기를 뺀 것은 투명 창(앱)에서 더 크게 나타나는 종류라, **앱에서 사람이 다시 재야 한다**(아래).

**확인한 것 — 그리기 종류(수치 밖).**
- 고친 뒤 나가기의 물은 섬 자리의 둥근 판(`.dive.out .pane`) 하나가 `transform`으로 화면 밖까지 늘어나고, 물방울 · 빛줄기는 다른 층(`.fx`)에서 물이 덮은 뒤 나타난다 — 매 프레임 다시 그리는 `clip-path`가 없다(`dive.test.js`).
- 새 페이지(서고 `#lib-dive` · 작업 화면 `&back`)는 `dive.js`가 `#dive-cover` 바로 뒤에서 읽히며 머리의 표시를 보고 물방울을 바로 채운다 — 물방울이 생긴 순간 페이지의 script는 2개(머리의 한 줄 + dive.js)였다(전체 9 · 22개 중). 즉 첫 그림부터 물방울이 있다.
- 넘기기는 `setTimeout`이 아니라 물 · 플로로 움직임의 `finished` 뒤(상한 `OUT_CAP` 1450 · `LEAVE_CAP` 950ms는 멈춤 막이). 서고 → 작업 화면은 전에 끝나기 30ms 전에 넘겼는데(`LEAVE_GO` 620 < 650) 헤드리스 Chrome에서는 차이가 없어 끝나면 넘기는 것으로 통일했다.

**앱에서 사람이 잴 것(넘김 문서 8절).** 묶은 앱에서 들어가기 · 나오기를 3번씩 하며 같은 방법(개발자 도구 콘솔에 `PerformanceObserver({ type: "long-animation-frame" })`)으로 50ms 넘는 프레임 수와 가장 긴 프레임을 센다. 목표 [제안]: 50ms 넘는 프레임 0~1개, 가장 긴 프레임 33ms 이하. 고친 뒤에도 끊기면 그 끊김은 창 크기 · 페이지 넘김(①·③)에서 오는 것이고, 그때는 창 둘로 나누기 / 한 창 순서 바꾸기 중에서 다시 정한다(fix-map F-35).

**잰 날 · 환경.** 2026-10-20, macOS, Google Chrome(헤드리스), `main` f74e8f8 위의 브랜치 `v2/island-modes`. 잰 스크립트는 저장소에 넣지 않았다(세션 임시 폴더) — 같은 방법을 다시 쓰려면 위 "무엇을 쟀나"대로 만든다.
