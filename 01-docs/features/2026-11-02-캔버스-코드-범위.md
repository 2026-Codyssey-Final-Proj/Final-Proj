# 작업실 캔버스 탭 — 코드 범위 (2026-11-02 잰 것)

작업실 창의 첫 탭 "캔버스"(퀘스트 한 바퀴 — ① 생각 → ② 행동 → ③ 기록 → ④ 저장 → ⑤ 버전 → 관문)를 그리고 움직이는 코드가 어디에 얼마나 있는지 센 것이다.
기준은 `main` 최신(2026-11-02, 앱 11.0.0 · v60.x). 줄 수는 `wc -l`과 파일 안 줄 번호로 쟀다.

주의: 저장소 안의 "캔버스"라는 말은 두 가지다. **이 문서는 제품의 캔버스 탭**만 센다. 두승현이 디자인할 때 쓰는 "목업 캔버스 · 디자인 캔버스(DockPrototype)"는 설계 자료일 뿐 코드가 아니다(커밋 메시지 57건 중 상당수가 그쪽 뜻).

작업실 전체(파일 칸 · 퀘스트 탭 · 책 탭 · 오른쪽 칸)는 이보다 훨씬 크다. 캔버스 탭만 떼어 보면 **프런트 파일 셋에 거의 다 모여 있다** — 백엔드에 캔버스 전용 코드는 없다.

## 1. 판 그리기 — `app/45-knowledge.js`

`app.js`는 `app/` 조각을 합친 파일이라 고칠 때는 조각을 고친다(`node 02-frontend/navigator/app-parts.js join`).

| 줄 | 무엇 |
|---|---|
| 191 ~ 193 | `openQwin` · `closeQwin` · `QTABS`(캔버스 · 퀘스트 · 책) — 작업실 여닫기, 탭 목록 |
| 194 ~ 206 | 캔버스 상수 — `FLO_AT`(작은 플로로가 서는 판 좌표 6곳) · `FLO_MINI`(플로로 svg) · `ARROW`/`ARROWS`(화살표 svg 5개) · `CV_HINT` · `CV_TOOLS`(− 맞춤 + 단추) |
| 207 ~ 244 | `canvasPane(n)` — 단계 n의 여섯 칸을 지금 상태에서 만든다 |

`canvasPane`이 칸마다 읽는 상태와 그 출처:

| 칸 | 읽는 것 | 어디서 오나 |
|---|---|---|
| ① 생각 | 퀘스트의 지금 칸 글 · 플로로 초안 · 준비된 퀘스트 | `st.quest` · `st.prep` → `03-backend/navigator/quest.js`(`curIdx` · `proposalOf` · `progress`) |
| ② 행동 | 맡긴 일 이름 · 진행 n/m | `st.plan` → `plan.js`(`running` · `progress`) |
| ③ 기록 | 적은 칸 Ⅰ ~ Ⅴ · 살펴본 결과 · 한 장 | `st.results` · `quest.js`(`filled` · `nameOf` · `shortOf`) |
| ④ 저장 | 올라갈 파일 이름 셋 | `docs.js`(`SLUGS` · `MAIN_DOC` · `LOG_DOC`) |
| ⑤ 버전 | V.n | `docs.js` `versionsOf` |
| 관문 | 남은 기준 수 · 안 된 기준 이름 | `st.j.criteria` |

이 백엔드 함수들은 캔버스 전용이 아니다. 퀘스트 탭 · 문서 묶기 · 관문이 같이 쓰는 것을 캔버스가 읽기만 한다. 캔버스를 바꿔도 백엔드는 건드릴 일이 없다.

## 2. 움직임 — `canvas-pan.js` (103줄)

처음은 "맞춤"(CSS가 줌 · 다시 배치). 끌거나 키우면 `.free`가 되어 옮기는 층 `.cvp`를 translate · scale로 옮긴다.

- 순수 계산 10줄 안팎: `clampZ` · `zoomAt` · `fit` · `keepIn` · `pan` · `label` — Node에서도 돌아 시험한다
- 입력: 끌기(pointer 4px 넘게) · ⌘/Ctrl+휠 · 옮기기 중 두 손가락 휠 · 키보드 + − 0 화살표 · 단추 − 맞춤 +(`data-cv`)
- 상수: 판 1100×640, 배율 0.35 ~ 2.5, 한 단 1.25배, 가장자리 80px은 늘 보임
- `window.FloeCanvas.apply(root)` — 섬이 다시 그려 보내도 보던 자리로 되돌린다. 섬 상태(`st`)로는 보내지 않는다(단추가 `data-act`가 아니라 `data-cv`인 까닭)

`index.html` 89줄 · `win.html` 50줄에서 불러오고, `server.js` 162줄 STATIC 목록에 이름이 있어야 서버가 내준다.

## 9. 캔버스를 뺀다면 — 작업량 (UI/UX 포함, 2026-11-02 센 것)

> **했다(2026-11-02, 두승현 "숨기지말고 캔버스 부분 지우기") — 브랜치 `v2/canvas-remove`, 고칠 목록 F-133, 요구 C-69.** 9-3의 결정 둘은 이렇게 두었다: ⑤ 버전은 새 자리를 만들지 않고 README의 버전 기록에만(책 탭의 README에서 V.1 · V.2 … 알약으로 보인다 — 2026-11-02 앱에서 확인), 퀘스트 탭의 오른쪽 칸 기본값(접힘)은 그대로. 단위 시험 23/23 통과, e2e는 이 컴퓨터에 puppeteer가 없어 글로만 고쳤다.

"뺀다"를 **탭 · 코드 · 시험 · 문서를 모두 지우는 것**으로 놓고 셌다. 실제 시간은 재지 않았다 — 아래 시간은 고칠 자리 수에서 어림한 것이다.

### 9-1. 먼저 알아야 할 것 — 이미 내린 결정과 부딪친다

- [2026-10-31 기능 줄이기 제안](2026-10-31-기능-줄이기-제안.md) 1번(다-03)에서 두승현이 정한 것: **첫 탭을 퀘스트로 바꾸고 캔버스는 둘째 탭으로 둔다. 탭을 빼는 것(3 → 2)은 C-23 · C-42를 바꾸는 일이라 대회 뒤.** 그 결정 중 "첫 탭을 퀘스트로"도 아직 코드에 반영되지 않았다(`00-base.js` 151줄은 여전히 `qtab: "canvas"`).
- 빼면 요구 셋이 바뀐다: **C-23**(퀘스트 한 바퀴 — ⑤ 버전 칸이 캔버스에만 있다) · **C-41**(작업실 캔버스 + 가장자리 섬) · **C-42 R-11**(줌 · 다시 배치). 요구 문서는 고치지 않고 새 줄(C-번호)로 "뺐다"를 적는 쪽이 맞다.
- 시연 장면 다섯에는 캔버스가 없다. 다만 **켤 때 처음 보이는 화면**이 캔버스라 켜는 장면은 다시 찍어야 한다.

| ⑤ 버전(V.n · 날짜) | **없다** — README의 '버전 기록' 글뿐 | **C-23 ⑤가 화면에서 사라진다.** 지도 카드나 오른쪽 칸에 새 자리를 만들거나(+10줄 안팎), README에서만 보기로 정해야 한다 |

| 화살표로 이어진 '한 바퀴' 그림 | **없다** — 퀘스트 탭은 목록 모양 | 다섯 칸이 순서대로 돈다는 느낌(C-23의 뜻)은 그림이 없어진다. 퀘스트 탭 '흐름' 보기가 비슷한 역할 |
| 끌어 옮기기 · 크게 작게 | 캔버스에만 있던 상호작용 | 통째로 사라진다. 다른 탭은 스크롤만 |

켤 때 바뀌는 것: 첫 화면이 **퀘스트 탭(지도 띠 + 퀘스트 카드)**이 된다. 퀘스트 탭은 오른쪽 칸('이 문서' · '이 프로젝트의 기준' · '퀘스트')을 기본으로 접으므로(`wsideQuest`), 켜자마자 **기준 카드가 안 보인다**. 보이게 할지(`wsideQuest` 기본값 바꿈)는 UX 결정이 하나 더 필요하다.

탭은 둘(퀘스트 · 책)이 되고 파일 탭이 그 뒤에 붙는다. 머리 줄 모양은 그대로다.
