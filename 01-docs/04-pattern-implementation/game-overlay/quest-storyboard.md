# 스토리보드 — 플로로와 대화하며 퀘스트를 받는 Floe (게임처럼, 7단계는 그대로)

> 목업: [quest-overlay.html](quest-overlay.html)(첫 초안) · **[quest-canvas.html](quest-canvas.html)(둘째 레프런스, 9절)** — 브라우저로 바로 연다(서버 · AI 없음). 지금 제품은 [level-overlay](README.md) 3번(LV · EXP · 명령 네 칸)이고, 이 문서는 **그다음 모양**의 초안이다.
> 바탕: 요구서 FR-1 · 2 · 4 · 5 · 12 · 13 · 15 · 16 · 17은 그대로 — 바뀌는 것은 **보이는 방식과 말**이다. 7단계(0 정하기 → 7 돌아보기)의 할 일과 판정 규칙(`navigator.js`)은 바꾸지 않는다.

## 1. 한 줄로

**단계는 챕터, 할 일은 퀘스트, 넘어가기 전 확인은 관문.** 플로로가 퀘스트를 주고, 사용자는 플로로와 대화하며 수행하고, 완료하면 조각(보상)을 모아 책 한 권을 완성한다. 처음 보는 사람도 "지금 퀘스트 하나"만 보면 된다.

## 2. 이재엽이 정한 것(2026-10-21) → 어디에 넣었나

| 받은 것 | 정한 것 | 목업에서 |
|---|---|---|
| 도전과제 나무(마인크래프트) | 7단계를 **도전과제로 이어서** 수행 | 오른쪽 판의 **도전과제** 탭 — 단계마다 한 줄(챕터), 할 일이 가지로 뻗고, 끝낸 것 · 지금 · 아직으로 색이 다르다 |
| 퀘스트 창(메이플) | **퀘스트를 받고 수행하는 공간**, 오버레이 **오른쪽**에서 정보를 더 준다 | 오른쪽 판의 **퀘스트** 탭 — 제목 띠(퀘스트 이름 · 누가 주나 · 플로로), 요약(할 일 0/1), 설명, 단추 넷(완료 보고 · 힌트 · 나중에 · 넘기기) |

## 3. 화면 하나 — 통일된 오버레이

```
┌─ 🏠 Floe ───── 2장 · 꼭 필요한 기능 정리하기 · 퀘스트 1/5 ●○○○○ ──────── ⚙ 📌 ⌃ ─┐
│                                                                                │
│  [플로로와 대화]                          │  [퀘스트]  도전과제  서고           │
│   🦭 안녕하세요! 2장에 왔어요.            │  ┌──────────────────────────────┐  │
│      첫 퀘스트는 '기능을 한 문장으로'예요  │  │ 기능을 한 문장으로 쓰기   🦭 │  │
│                                           │  │ 2장 · 플로로가 줌           │  │
│   나: 회원 신청 화면이 있어야 해요         │  ├──────────────────────────────┤  │
│                                           │  │ 요약                          │  │
│   🦭 좋아요! "~하면, 앱은 ~한다"로         │  │ ▫ 기능 문장 3개         1/3  │  │
│      바꿔 볼까요?                          │  │ ▫ 애매한 말 숫자로       0/1 │  │
│     ┌───────────────┐ ┌──────────────┐    │  │ 설명 …                        │  │
│     │ 네, 바꿔 볼게요 │ │ 예시 보여 줘 │    │  │ [완료 보고] [힌트] [나중에]   │  │
│     └───────────────┘ └──────────────┘    │  └──────────────────────────────┘  │
│   ┌─ 플로로에게 말하기 · 파일 놓기 ────┐  │  보상: 조각 🧩 ×1 · 책갈피 ▮ +1    │
│   └────────────────────────────────────┘  │                                   │
└────────────────────────────────────────────────────────────────────────────────┘
```

- **왼쪽 = 대화.** 플로로가 말하고, 사용자가 고르거나 쓴다. 지금의 '맡기기 · 살피기 · 꺼내기 · 쉬어 가기' 명령 네 칸은 **대화 속 단추**로 녹는다(예: "어디쯤인지 볼까요?" → [네] [아직]). Claude Code 알림(FR-7)은 대화에 **시스템 말**로 들어온다("Claude Code가 작업을 마쳤어요 — 퀘스트를 확인할까요?").
- **오른쪽 = 정보.** 퀘스트(지금 하나) · 도전과제(전체 나무) · 서고(내 책 · 받은 먹이 · 확인할 먹이). 세 개는 판 안의 작은 고르기로 바꾼다 — 위 줄은 바뀌지 않는다.
- **위 줄 = 늘 같다.** 집(홈으로) · Floe · 진행 줄 · 설정 · 핀 · 접기. 홈과 바이브 코딩의 차이는 **대화 내용**(홈: 인사와 오늘의 퀘스트 셋, 바이브 코딩: 지금 퀘스트)뿐이다.
- 접힌 한 줄 · 띠는 지금 그대로(플로로 얼굴 + 한 줄). 한 줄에는 "퀘스트 1/5 · 기능을 한 문장으로"가 보인다 [제안].

## 4. 7단계 → 챕터와 퀘스트 (도전과제 나무)

단계 이름 · 할 일은 `navigator.js` `STAGES`와 같다. **주 퀘스트**(끝내야 관문이 열림)와 **곁 퀘스트**(골라서 — 등급 Lite · Xpress에서는 안 나오는 할 일)가 가지로 뻗는다. 이름 뒤 ⛩ = 관문(넘어가기 전 확인, FR-4 · 5).

| 장 | 챕터 이름 [제안] | 주 퀘스트(차례로) | 곁 퀘스트(가지) | 관문 뒤 보상 |
|---|---|---|---|---|
| 0 | 출발 — 무엇을 만들지 | 불편 한 문장 → 달라지는 것 → 누가 쓰나 → 얼마나 크게 | — | 조각 '목표 한 문장' · 도장 0 |
| 1 | 적어 두기 | 빈칸 채우기 → 왜 · 어디까지 · 언제 → 한 문장 한 가지 | 자세한 기획서로 키우기(Full) · 보안 점검 한 줄 | 조각 '아이디어 정리표'(책에 꽂힘) |
| 2 | 기능 정리 | 기능을 '~하면, 앱은 ~한다'로 → 애매한 말 숫자로 → 꼭 · 있으면 좋음 표시 | 출처 표 잇기(5개 이상일 때) · 막아야 할 일 쓰기 | 조각 '꼭 필요한 기능 목록' |
| 3 | 방법 고르기 | 선택지 셋 → 장단점 → 하나 고르기(왜) | 그림 하나로 그리기 · 다른 길이면 무엇이 달라지나 | 조각 '방법을 고른 기록' |
| 4 | 뼈대 | 작은 할 일로 쪼개기 → 차례 정하기 | 위험한 일 먼저 표시 | 조각 '작은 할 일 목록' |
| 5 | 만들기 | 할 일 하나씩 → Claude Code에 넘기기(FR-17) → 허락 · 거절 | 시험 먼저 쓰기 · 느낀 점 남기기 | 조각 '만든 것' ×N(파일 이름) |
| 6 | 써 보기 | 직접 써 보기 → 잰 값 적기 → 못 한 것 적기 | 다른 사람에게 보여 주기 | 조각 '잰 값' |
| 7 | 돌아보기 | 잘된 것 · 안 된 것 → 다음엔 뺄 것 | 서고에 책장 고르기(C-21) | **책 한 권 완성** → 서고에 꽂힘, 플로로 꾸미기 하나 |

- **고르는 데 도움:** 퀘스트마다 플로로가 선택지 2~4개를 대화 단추로 준다(지금의 `next.options` 그대로). 고르면 대화에 "→ ○○로 정했어요"가 남고 퀘스트 요약의 칸이 찬다. 곁 퀘스트는 "이것도 해 볼까요?"로 **권하기만** 한다 — 안 해도 관문은 열린다.
- **관문(⛩):** 챕터의 주 퀘스트가 다 차면 플로로가 "이번 장에서 한 일, 이해되셨나요?"를 대화로 묻는다(FR-4). 아니요 → 헷갈린 곳 고르기 → 질문 → 한 장 요약(지금 흐름 그대로, 대화 안에서). 세 번째 아니요부터 '잠시 멈추기'.
- **도전과제 나무 보기:** 8줄(0~7장)이 위에서 아래로, 줄마다 주 퀘스트가 왼쪽에서 오른쪽으로, 곁 퀘스트가 아래 가지로. 끝낸 것은 금빛 테두리, 지금은 파란 빛, 아직은 흐리게. 누르면 그 퀘스트 설명이 오른쪽 판에 뜬다(먼저 보기만 — 순서를 건너뛰지는 못한다).

## 7. 지금 제품에서 무엇이 바뀌나 (만들 때 볼 것)

| 지금 | 바뀜 | 코드 자리 |
|---|---|---|
| 위 줄 탭 넷(이번 단계 · 단계 지도 · 도서관) + 홈의 '집 + Floe' | 위 줄 하나로 통일, 탭은 오른쪽 판 안으로 | `app.js` `topbar` · `TABS` · `BASE_BTNS` |
| '이번 단계' 카드(상자 + 명령 네 칸 + LV/EXP) | 왼쪽 대화 + 오른쪽 퀘스트 카드, LV/EXP 없음 | `levelCard` · `momentBox` · `pathsFor` · `.cmds` · `.stats` |
| 진행 줄(단계 · 몇 번째 할 일)이 카드 안에 | 위 줄 가운데로 | `momentToday` meta → `topbar` |
| 기본 화면 단추 넷(바이브 코딩 · 서재 · 알림 · AI 진행) | 대화 단추 셋 + 알림 · AI 진행은 대화 속 시스템 말 + 오른쪽 '서고' 탭 | `baseBody` · `basePane` |
| 단계 지도 탭 | 도전과제 나무(같은 데이터) | `deskMap` → 나무 |
| 판정 · 할 일 · 관문 규칙 | **그대로** | `navigator.js` · `scenario.js` |

- 쉬운 말(FR-13): '퀘스트' · '도전과제' · '챕터'는 게임 말이라 처음 쓰는 사람에게 통하는지 사용 테스트에서 묻는다 — 풀이 한 줄("퀘스트 = 지금 할 일 하나")을 용어 풀이(glossary)에 둔다 [제안].
- 등급(Lite · Xpress · Full)은 곁 퀘스트가 보이고 안 보이는 것으로 드러난다.
- 먹이 주기(FR-15) · 일 넘기기(FR-17) · 승인 카드 · 책 보기 설정 · 책장은 그대로 — 자리만 대화와 오른쪽 판으로 옮긴다.

## 8. 정할 것 (이재엽)

1. 위 줄에서 탭 넷을 **정말 없애도** 되나 — 단계 지도는 도전과제 나무로, 도서관은 오른쪽 '서고'로.
2. 보상 이름 — 조각 · 도장 · 책갈피 · 꾸미기 중 무엇을 쓰고, 꾸미기 그림은 누가 그리나(고한결).
3. 곁 퀘스트를 권하는 빈도 — 매번 / 챕터 끝에 한 번.
4. 이 모양을 요구서에 넣을지(후보 C-22 — 2-2에 한 줄 적어 둠) · 언제 만들지(11/1 기능 동결 전인지, 베타인지).

| 발전 과제(세로 탭 · 큰 그림) | 도전과제는 **그림만**: 왼쪽 세로 탭이 장(0~7, 끝낸 장은 금빛 점), 판에는 그 장의 퀘스트가 **큰 그림**으로 위에서 아래로, 곁 퀘스트는 옆 가지, 끝은 관문 원. 글자 없음 — **마우스를 올리거나 키보드로 고르면** 이름 · 상태 · 보상이 설명으로 뜬다 | "무조건 그림만 그리고 크게 … 마우스를 두면 어떤 내용인지" |

- 흐름: 말하기 → **받기 화면**(이벤트 창) → 퀘스트 받기 → **공책**(목차 · 줄) → 대화로 수행 → 완료 보고 → 다음 퀘스트는 다시 받기 화면. 받기 화면 · 공책 어디서든 고칠 수 있다.

### 11-3. 바뀐 규칙은 없다

판정(`navigator.js` · 서버) · 넘어가기(FR-4 · 확인 질문) · 설계도 · 먹이 주기 · 허락 카드 · 서고 · 모아 보기 창은 그대로다. 바뀐 것은 **보이는 방식**뿐 — 그래서 `quest.js`는 `STAGES`를 읽기만 하고, 완료 보고는 전의 '어디쯤인지 보기'다.
