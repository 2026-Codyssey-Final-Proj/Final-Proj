> **2026-10-17 바뀜(이재엽 요청):** 달은 각자의 폴더 = **은하**, 은하 안의 태그 = **태양계**, 태양계 안의 책 = 별. 별자리는 12궁 모양 대신 가지가 갈라지는 모양이고 별 수에 상한이 없다.
> "어디"는 이제 **"10월 은하 · 보안 태양계 ★2"**로 말한다. 아래 2절의 12궁 표는 은하의 별명으로만 남는다(별 수 · 부분 이름은 쓰지 않는다). 새 구조는 5절.

## 0. 한 문장

**지식 한 개 = GitHub 저장소의 마크다운 파일 한 개 = 하늘의 별 한 개.** 파일의 날짜가 몇 월 별자리에 뜰지를 정하고, 그 달 안에서 날짜 순서가 별 번호(★1, ★2 …)가 된다.
화면은 언제나 "**10월 천칭자리 ★2 · 저울대 가운데**"처럼 어디에 있는지를 한 줄로 말한다.

## 1. 지식 파일 모양 — 정리의 약속

```markdown
---
title: 세션과 토큰의 차이
date: 2026-10-03
line: 서버가 기억하느냐, 들고 다니느냐
tags: [로그인, 보안]
level: 2            # 0 처음 봄 · 1 이해함 · 2 직접 씀 · 3 응용함 (FR-8)
---

(본문 — 하늘에는 가져오지 않는다. 펼칠 때 GitHub에서 연다)
```

- 경로: `knowledge/<연-월>/<짧은-이름>.md` — 사람이 폴더만 봐도 몇 월 별자리인지 안다.
- **하늘이 읽는 것은 머리말뿐이다.** 본문은 하늘 데이터에 들어가지 않는다(서재 설계 "표지만, 본문은 열 때"). 시험이 확인한다.
- 제목·날짜가 없거나 다른 해의 파일은 하늘에 올리지 않고 "못 올린 파일"로 따로 보인다(조용히 버리지 않는다 — 보안 기준 6-1).

## 2. 1월~12월 별자리 — 무슨 이야기인가

달마다 그 달 대부분을 차지하는 황도 12궁을 쓴다. 이야기 이름은 그 달의 지식을 읽는 틀이다(제안 — 바꿀 수 있다).

| 달 | 별자리 | 이야기 | 별 수 |
|---|---|---|---|
| 1 | 염소자리 | 첫 걸음을 뗀 이야기 | 8 |
| 2 | 물병자리 | 요구를 쏟아 적은 이야기 | 8 |
| 3 | 물고기자리 | 둘을 잇는 이야기 | 8 |
| 4 | 양자리 | 뼈대를 세운 이야기 | 4 |
| 5 | 황소자리 | 끝까지 만든 이야기 | 6 |
| 6 | 쌍둥이자리 | 함께 나눈 이야기 | 6 |
| 7 | 게자리 | 지킨 이야기 | 5 |
| 8 | 사자자리 | 용기 낸 이야기 | 8 |
| 9 | 처녀자리 | 거둔 것을 정리한 이야기 | 7 |
| 10 | 천칭자리 | 무엇부터 할지 고른 이야기 | 6 |
| 11 | 전갈자리 | 위험을 피한 이야기 | 9 |
| 12 | 궁수자리 | 다음 해를 겨누는 이야기 | 8 |

별마다 별자리의 부분 이름(예: 천칭자리 ★2 = 저울대 가운데)이 있어 "어디"를 그림으로도 말할 수 있다. 별 수보다 지식이 많으면 넘친 것은 **다음 별 대기**로 보인다.
별자리 모양은 실제 별자리를 단순하게 다시 그린 것이다(별자리 자체는 누구의 저작물도 아니다).

## 3. GitHub과 주고받는 길 — 결정이 필요한 곳

| 방향 | 무엇 | 후보 | 제안 |
|---|---|---|---|
| **쓰기** (정리 → GitHub) | 세션이 끝나면 지식 파일 초안을 만들고, 사용자가 확인한 것만 커밋 | 가) 사용자가 직접 커밋 / 나) 브랜치에 올리고 PR / 다) 데이터 브랜치에 바로 커밋(개인 데이터, V1 ADR-0007 방식) | 다) — 개인 지식은 병합 검토가 필요 없고 이력만 남으면 된다. 팀 공유본은 별도 규칙(FR-9) |
| **읽기** (GitHub → 하늘) | 머리말만 읽어 하늘을 만든다 | 가) **내 컴퓨터의 클론 폴더를 읽기**(키 없음, `git pull` 뒤) / 나) GitHub API + 개인 토큰(환경변수) / 다) GitHub 앱 | 가) — 시연은 서버 없이(FR-10), 베타도 각자 로컬(ADR-0005 제안과 같음). 나)는 폰에서 볼 때 다시 정한다 |
| **새 지식 알림** | 저장소에 새 파일이 올라오면 "새 지식 N개 가져오기" | 화면을 열 때 비교 / 주기적 확인 | 화면을 열 때 비교(서버 없이) |

**지켜야 할 것**
- 저장소는 **비공개가 기본**이다. 공개 저장소를 연결하려 하면 한 번 묻는다.
- 토큰을 쓰는 경우(나) **환경변수에만** 두고 코드·저장소·로그에 쓰지 않는다. 권한은 그 저장소 읽기 하나만.
- 다른 사람의 이름이 든 지식은 이름 · 맡은 일 · 한 줄만(팀원 정보 규칙). 머리말에 키 모양이 보이면 저장 전에 경고한다(보안 기준 6-3).
- "GitHub에서 열기"는 사용자 자신의 권한으로 연다. 화면이 대신 열람 권한을 갖지 않는다.

|---|---|
| 위 가운데 머리띠 | 지식 N개 · 별이 뜬 별자리 수 |
| 오른쪽 위 GitHub 칸 | 저장소 · 가지 · 파일 수 · 마지막 가져온 때, **새 지식 2개 가져오기**(누르면 10월 천칭자리 ★5·★6이 반짝이며 뜬다) |
| 가운데 큰 별자리 | "10월 · 천칭자리 — 무게를 재는 저울 / 무엇부터 할지 고른 이야기", 별마다 ★번호 · 제목 · 부분 이름 · 이해 수준, 빈 자리는 흐리게 |
| 오른쪽 목록 | 이 별자리의 지식을 ★순서로. 고르면 **📍 10월 천칭자리 ★2 · 저울대 가운데**, GitHub 경로 · 커밋, 같은 배움을 가진 다른 달의 별 |
| 아래 달 막대 | 한 해 · 1월~12월(별 개수 점), ←→ 키로 달 넘기기 |
| 한 해 하늘 | 12개 별자리를 한 화면에 — 누르면 그 달로 |
| 검색창 | 결과가 **검색창 바로 밑에** 펼쳐지고 오른쪽에 "2월 물병자리 ★1 · 손"처럼 어디인지. ↑↓ · Enter로 그 별로 간다 |

## 5. 은하 · 태양계 구조 (2026-10-17)

| 하늘 | 저장소 | 정하는 규칙 |
|---|---|---|
| 은하 | 폴더 `knowledge/<연-월>/` | **폴더가 정한다.** 날짜가 2월이어도 3월 폴더에 두면 3월 은하. 폴더에 달이 없으면 머리말 날짜로 |
| 태양계 | 머리말 `tags`의 **첫 태그** | 태그가 없으면 "태그 없음" 태양계. 둘째 태그부터는 그 태양계에 **손님 책**으로 보이고, 은하 안에 두 태양계를 잇는 다리가 생긴다 |
| 별 | 지식 파일 하나 | 태양계 안에서 날짜 순서로 ★번호. 자리는 파일 내용으로 정해져 늘 같다 |

- **태그로 책 보기:** 태그를 누르면 모든 은하에서 그 태그의 책을 은하(달) 순서로 보인다. 첫 태그가 아니어도 그 태그를 가진 책은 다 나온다.
- **정해야 할 것(이재엽):** 태그 이름을 자유롭게 둘지, 정해 둔 목록(예: 요구 · 설계 · 보안 …)에서 고르게 할지. 자유로 두면 "로그인"과 "login"이 다른 태양계가 된다. 시안은 자유.
- 시험: `knowledge-sky.test.js` 12개(은하 = 폴더, 태양계 = 첫 태그, 손님 책 · 다리, 태그로 보기, 모양이 이어지고 같은 입력이면 같은 모양, 본문 제외).

## 6. 이 문서가 하지 않는 것

- GitHub에 연결하는 코드는 쓰지 않았다. 시안의 "가져오기"는 화면 안의 더미 파일을 더할 뿐이다.
- 3절의 선택은 제안이다. 정하는 사람은 이재엽이다.
