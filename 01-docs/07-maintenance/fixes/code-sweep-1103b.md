## 새 맥락 리뷰 — 고친 것과 남긴 것

대화 기록 없이 요구(위 표의 줄)와 바뀐 코드만 받은 리뷰어가 본 결과([code.md](../../../.claude/rules/code.md) 7번). 고친 것은 그 번호의 '새 맥락 리뷰' 커밋에 있다.

- **막힘 → 고침:** F-144-8 — 창에 마지막으로 보낸 단추 상태(`lastOff`)를 다른 일로 다시 보낼 때 비우지 않아, '남기기' · '다시 세우기' 뒤 다음 글자에 단추가 다시 켜지지 않았다 → 보낼 때 비운다(`clearLive`).
- **보완 → 고침:**
  - F-144-8: `plan-direct` · `note-add`의 커서도 `focusAct`로. 창을 닫으면 커서 신호를 비운다.
  - F-144-2: `rd`의 `/s`는 어느 자리든, `-fu` · `-df` 같은 옵션 묶음, `"+main"`도. push 뒤는 그 명령 안에서만 본다(`&& ls -d`를 원격 지우기로 보지 않게).
  - F-144-6: 훅 둘(`hook.js` · `approve-hook.js`)의 표준 입력도 `setEncoding("utf8")`.
  - F-144-7: 커밋이 없는 새 저장소를 다시 고르면 막히던 것 — HEAD가 없으면 `git ls-remote --heads origin`으로 원격도 비었는지 본다.
  - F-144-12: 서버로 연 화면이면 지금 모드와 상관없이 지운다. 못 지웠으면 말하고 멈춘다(security-records 6-1). 문구는 "지금 폴더의 대화".
  - F-144-13: 조합 중에는 입력이 부른 그리기만이 아니라 모든 그리기(1초 타이머 · 안내 말)를 미룬다.
  - F-144-14: 2단계 이상을 쓰다 만 폴더도 되살린 줄로 채우고, 그 위에 초안을 덮지 않는다.
  - F-144-17: 처음 설정에서 모드를 바꾸는 길(`floe:setup-done`)도 README를 잊는다.
  - F-144-24: 해낸 것 보고 · 문서 초안 · GitHub에 커밋되는 단계 줄 · 다시 맡기는 글의 자르기도.
- **보완 · 제안(남김):**
  - F-144-17: 바꾸기 직전에 보낸 README · 찾기 요청의 답이 늦게 오면 비운 뒤 다시 옛 값으로 채워질 수 있다(요청 번호로 늦은 답을 버리기).
  - F-144-10: 주제와 글이 똑같은 먹이가 연달아 있으면 둘을 구분하지 못한다(드묾).
  - F-144-7: macOS · Linux에서 `killTree`는 `child.kill()`만 해서 gh 아래의 git이 남는다(팀은 Windows).
  - F-144-24: 같은 `head` 한 줄이 여러 파일에 있다 — 화면 · 서버가 함께 읽는 공용 모듈이 생기면 모은다.
